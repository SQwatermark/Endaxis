# 战斗切面数据模块

本目录定义完整帧边界上可以保存、复制和恢复的战斗数据。运行时类、动作程序、回调、校验和推进逻辑
放在 `runtime` 等业务目录；这里不执行游戏规则。

六个文件按依赖方向排列，上层可以直接引用所需的下层：

1. `foundationState.ts`：共享黑板、稳定引用、事件订阅目录、属性与修正项、施法来源及全局 Buff 数据节点；
2. `environmentState.ts`：时钟、资源、生命、时间膨胀、连携窗口、随机流、输入游标和全局编号；
3. `actionState.ts`：递归动作序列、时间轴进度和动作宿主持有的句柄账本；
4. `abilityState.ts`：技能选择、单次技能执行、冷却、事件来源和干员初始化；
5. `instanceState.ts`：Buff 容器和实例（寿命、触发、叠层、属性、子引用、护盾）、能力实体、投射物及宿主；
6. `combatState.ts`：把以上数据与干员、敌人和事件目录组成 `CombatStateGraph`。

运行模块应直接导入实际需要的文件。这里不提供汇总导出文件，以免隐藏依赖方向或引入运行时循环。
新增切面字段时，先按所有权放进以上层次；只有一组数据确实形成新的独立子系统时才新增文件。

模块依赖方向与对象图形状是两回事。共享引用、父子关系和递归动作数据可以形成环，保存和恢复必须
保留原有身份，不能为了得到一棵树而复制节点或改写关系。相互递归的动作数据集中在 `actionState.ts`；
新增循环应先确认它表达实际数据关系，不能用类型导入掩盖数据层对运行时类、端口或执行器的反向依赖。

状态层直接使用公共契约和游戏数据类型。运行时事件从纯施法数据扩展回调端口，切面不再从含回调的
事件结构裁剪字段。瞬时执行上下文（例如 `SequenceExecutionState`）不是完整帧边界上的持久状态，
留在执行协议中；文件名含 State 并不是迁移依据。
