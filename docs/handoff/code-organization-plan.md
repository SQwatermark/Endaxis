## 删除、合并与验收规则

1. 删除证明覆盖静态导入、公共导出使用、动态 glob、注册表、路由、Worker、脚本命令、
   生成模板和文件路径读取。孤立模块只被自己的测试引用，可以连同无效测试删除；
   正式行为的测试改接正式入口，不能靠删测试获得通过。
2. 合并要求同一职责、同一生命周期、通常一起修改，且不会破坏依赖方向或加载边界。
   完整帧边界的切面数据统一归入 `combat/state`，执行与校验留在功能模块；瞬时执行上下文不机械搬迁。
   数据图允许必要的循环和共享引用，不能把模块依赖整理变成改变对象关系的理由。
3. 机械搬迁保持符号和行为；内部调用方一次改完，不长期堆兼容转导出。
   契约稳定入口和有真实外部调用的入口则明确保留。
4. 所有修改由 `apply_patch` 记录；生成文件通过生成器更新。同步修改 glob、import.meta.url
   相对路径、inspector-schema 扫描路径、测试配置及文档引用。
5. 每批跑受影响测试；大检查串行、单 worker。完整收尾集中执行，不为每次改路径重复全量。
   首次跨功能迁移和最终收尾使用同一组已存真实轴核对结果，无需枚举所有干员重新研究规则。
6. 保持既定时间语义：截面先于新输入、未来不改过去、技能与人工标记都经过输入边界；
   回执历史共享和运行状态分离；结束/reset/ClearSource 顺序不变。
