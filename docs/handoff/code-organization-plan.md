# 代码组织与冗余清理

目标：维护一个功能时，能在相邻的少数文件中看清入口、数据、执行和测试。
不按文件数或行数切代码，也不把不同职责合成大文件。验证统一见[当前交接](current-context.md)。

## 剩余推进顺序

1. **职责复核**：审阅运行时装配根/标准环境、页面放置交互与模拟装配。
   只合并同一职责、同一生命周期的重复实现，不为降低大类行数制造转发碎片。
2. **数据与文档**：按实际读者检查 JSON、脚本、旧报告和教程。
   原生证据归 combat-spec，Endaxis 保留应用取舍、生成映射、开发操作和待办。
   完成的过程记录删除，编译/审计中间产物不入库。
3. **行为对照**：使用同基线的已存真实轴核对整理前后结果、回执与恢复行为。
   没有执行的检查保持待办，不用以往切面验收替代，也不重新枚举所有干员。
4. **收尾与提交**：检查空目录、无用转导出、动态加载路径和文档引用，按功能形成可审阅提交。
   大范围代码变化后集中串行验证，已通过的同一检查不因文档改动重复执行。

## 删除与合并依据

- 引用检查包括导入、公共导出、动态 glob、注册表、路由、Worker、脚本、生成模板和路径读取。
  只有自身测试使用的孤立模块可连同自测删除；正式行为的测试必须改接正式入口。
- combat/state 保存完整帧边界的数据；执行器、校验和临时执行上下文留在功能模块。
  模块依赖保持单向，实际对象图可以有必要的递归和共享节点。
- 移动文件同步更新 import.meta.url、glob、schema 扫描和测试配置，不留内部兼容转导出。
- 固定程序保持共享；资源归属、时间语义、回执历史与回收顺序不能因整理而改变。
- 生成文件通过生成器更新；纯搬迁、行为变化和生成内容变化分开审阅。

P6 广域测试、类型检查和构建已经执行，结果与环境限制见当前交接；
剩余职责审阅和最终同基线真实轴对照完成前，不将整个整理任务标记为完成。
