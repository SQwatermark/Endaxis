## 全程边界

1. 状态是纯数据，固定程序与状态分开。只有步进过程中执行游戏规则；保存和恢复不施放、
   不触发事件、不扣费、不重新安装效果、不消费随机样本。
2. 保留现有模拟语义，包括 float32 运算顺序、同帧事件顺序、实例编号、来源归属和回执顺序。
   若发现原有 bug，单独说明证据、修复和预期差异，不能混在重构差异里放行。
3. 多个技能共用的冷却、黑板回退关系、Buff 引用等，在保存和恢复后仍必须共享同一份数据。
   兄弟分支之间的可变对象不得共享。固定程序目录可以共享，恢复时不能重新编号。
4. 未来编辑器计划、未提交技能块及其种子配置留在外部。已经提交的输入产生的延迟行为必须
   保存。外部连续组排程也要能随试探回退，但不能因此塞进战斗内部。
5. 不通过重放此前整场输入冒充恢复，不悄悄从头重算来掩盖缺失状态；恢复不支持的情况必须
   明确暴露。正式可恢复入口开放前，必须完成覆盖审查。
6. 发布前允许修改内部接口，不为旧实验接口增加兼容层。不扩展项目存档格式来迁就这次重构。
7. 手写文件使用 Codex 的补丁接口修改。检查以单线程为主，重型测试、构建和类型检查顺序执行；
   不加载整个游戏转储，不长期保留所有试探历史，不引入未经测量的缓存。

## T3：统一会话与分支回退

**做什么：** 把完整装配接入统一步进、保存、恢复和分支 API，替换实验性的分散保存入口。
完成未来输入隔离、连续组排程回退、随机配置绑定、分支回执与历史结果管理。

**中期审视后的接口边界：** 固定定义和构筑只准备一次；外部排程器保存尚未执行的计划。
战斗以“当前状态 + 本帧人工输入”推进，技能、切人和手动事件分别在原有阶段消费，不能让
isOperatorControlled 通过整条未来时间线绕开输入状态。当前主控身份属于可恢复状态。
连续组尚未提交的后缀留在排程器；已观察到的进度随排程器回退，不固定未来组数。
同一程序允许多个独立动作实例，不能用复制程序或全树 castId 登记代替实例隔离。
只改未来输入不重编译过去；不以放宽程序对象身份检查接通候选。

**参考代码：** [步进器](../../src/core/combat/runtime/stateStepper.ts)、
[模拟驱动](../../src/core/combat/runtime/combatSimulation.ts)、
[输入运行时](../../src/core/combat/runtime/combatInputRuntime.ts)、
[回执](../../src/core/combat/receipt/combatReceipt.ts)、
[应用服务](../../src/application/scenarioSimulationService.ts)。

**边界：** 只在完整步进边界保存；帧中保存/恢复明确拒绝。树形历史不支持合并，不因记录父子
关系而永久持有所有节点。旧句柄不能操作恢复分支。只共享固定程序和明确不可变的历史数据。

**质量与验收：** 同一切面依次尝试 A、B、再 A，两个 A 的结果完全相同，B 不污染它们。
覆盖第 0 帧、空输入、同帧多个输入、连续组、时间膨胀、随机模式和执行失败后回退。
只改变未来技能块的 ID、参数或种子时，共同前缀的战斗数据相同。调用方释放试探分支后，
会话不继续持有其可变数据；反复试探的内存不能随已丢弃的历史无限增长。

样本必须来自当前可定位的文件或分享记录，不临时拼一个只有空操作的轴作为整体证明。

**验收矩阵：** 多段/强化技能；Buff 叠层与周期伤害；装备/被动监听；终结技膨胀与局部变速；

## T5：旧轴转换复用前缀与性能验收

**做什么：** 在已确定的输入前缀处保存，候选时间试探从该切面恢复，只推进受影响的后缀。
候选通过才提交下一段；失败候选不污染已接受结果。不得改变用户已确认的时间修复算法。

**参考代码：** [时间修复](../../tools/legacy-timeline/heuristicRetiming.ts)及其测试、
[转换](../../tools/legacy-timeline/projectConversion.ts)、
[模拟审计](../../tools/legacy-timeline/simulationAudit.ts)。

**必须保持：** 全局按旧轴顺序处理；首技能按原时间。之后取旧轴真实时间、同轴前一块新版
实际显示结束、全局前一技能新版开始加旧轴间隔三者的最大值；落入终结技时间膨胀期间则后移
到其结束。显示时长来自真实模拟，不填估算值，不改存档结构。合法输入模拟失败按程序 bug 排查。

### 确定内容与当前候选

原始旧轴顺序、原帧和操作意图只读保留。排程器另维护已确认输入和当前候选片段。
已确认的是技能形态、放置帧及标记安排；尚未执行的已确认输入仍在外部排程器中，不提前改变
战斗状态。试跑观察到的未来结果不因某个输入被确认，就全部变成已经确定的过去。

当前候选包含一个待修复技能，以及随其时间变化的切人和人工标记。失败时整段丢弃，不能先把
候选切人写入主会话，再只回退技能。时间已经独立确定的标记可以单独确认。
定义和构筑只准备一次；若输入带局部参数或自定义技能，只准备该输入的必要绑定并与其他分支
隔离，不重新准备整场战斗，不覆盖其他分支相同 castId 的程序。

### 保存位置

找出候选片段最早可能影响的帧 `f`，在第 `f - 1` 帧结束后保存。`f` 要包括前置切人和人工标记，
不能只看技能帧。若还有未确定输入可能落在同一帧，继续保留该帧之前的截面。
初始合法输入帧也必须有明确的输入前截面，不能通过多推进一帧改变准备期或回能。

截面保存此前输入造成的全部状态：当前主控、活动技能、Buff、飞行投射物和已经产生的延迟请求。
随后由排程器逐帧提交后续人工输入。公共试探接口不接受一份能够任意改写历史的完整候选场景。
若修改位置早于截面，就使用更早截面，不能在下一帧补执行过去的输入。

### 一个技能块的推进

1. 按旧轴全局顺序取下一技能。首技能先试原时间；其余初始帧取旧轴原时间、同轨前技能新版实际
   显示结束、全局前技能新版开始加旧轴原间隔三者最大值。保留现有膨胀避让及主控输入冲突处理。
2. 按已有标记时间规则生成候选片段，在最早影响帧前取得截面，随后才添加候选输入。
3. 从截面推进，排程器到对应帧提交技能、切人或人工标记。尚未确定的后续旧轴技能不提交；
   已确认输入和过去输入造成的行为照常执行。读取正式回执判断实际输入、技能形态和显示结束。
4. 显示结束尚未出现时，直接延长当前试跑的观察窗口，沿用现有上限，不重新开局。
5. 原生路由指出不同技能形态时，按现有形态解析规则修正当前候选，回到输入前截面再试。
   不能在已经运行的状态中替换技能；费用、Buff 和回调仍由正式技能逻辑执行。
6. 不能打断当前技能时，按现有上限逐帧后移候选，每次从合法截面重试整个片段。
   许可可能短暂开放再关闭，保留逐帧查找，不改成二分搜索。
7. 找到候选后一次确认技能及关联标记，记录原有调整与诊断。若窗口搜索穷尽，保持现有算法的
   初始候选和明确的穷尽诊断，不伪造合法输入。若模拟抛异常，暴露错误，不吞错后全量重算。

### 切人和其他人工标记

所有人工标记遵守相同的截面边界，但保持各自原有帧内阶段；统一输入归属不等于改变执行顺序。
仅按当前转换规则调整标记，不自行发明标记跟随技能的语义。
时间依赖左右技能位置的标记，在相应位置未确定前不能提前提交，应与依赖的候选一起求解。
前置切人可能早于技能帧，截面必须覆盖它。旧格式尚不支持的标记继续明确报告，不借优化静默补全。

### 确认后推进下一段

主会话只带已确认输入推进，候选会话用来向前观察。试跑为寻找显示结束，可能已经越过下一个
待插入输入的位置，不能直接把试跑末帧当作新的已确认截面。
确定下一候选最早影响帧后，让主会话推进到它之前，保存下一截面。这可以重走上一个截面以来的
局部段，但不再对每个技能或候选重复模拟整个历史前缀。
下一输入与当前输入同帧时，仍用同一输入前截面，按原顺序提交已确认的同帧输入和新候选。

```text
准备固定定义、构筑、只读旧轴意图
建立初始输入前截面
逐项处理待修复技能：
    计算时间约束和关联人工标记
    在整个候选最早影响帧之前保存截面
    重复试探：
        回到截面
        推进时逐帧提交已确认输入及本次候选
        观察实际结果；需要更多时间就在此分支继续
        可确定则确认整个片段，否则丢弃并调整候选
    按下一待定输入的边界推进主会话、保存下一截面
用最终新轴正式运行一次，生成完整结果和诊断
```

最终重跑是产物一致性核验，不能掩盖试探失败。第一版只保留主会话、当前所需截面和一个试跑
分支；无用分支及时释放。是否增加截面缓存或只读回执前缀共享，依据后续测量再决定。

**质量与验收：** 优化前后转换结果、输入顺序及诊断一致；已有偏差必须逐项解释。
记录完整模拟次数、总推进帧数、候选数、复制/恢复耗时、总耗时、峰值内存和保留切面数。
同机同输入同种子测短、中、长轴，预热后至少重复 5 次并报告中位数及范围。
证明共同前缀不再为每个候选重复推进；不能仅以调用次数减少或微基准证明加速。
长轴须得到可重复的总耗时收益，短轴若回退需修复或说明有依据的策略；内存若持续增长不得通过。
不宣称恢复是常数复杂度：完整复制成本取决于状态规模，必须把它计入测量。
