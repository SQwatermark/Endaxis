# 战斗切面后续任务与验收计划

更新日期：2026-09-14。本文是后续工作的唯一任务清单，按任务更新状态，不追加逐轮日志。

## 目标与当前结论

完成整场战斗的保存、恢复、分支试探和回退，再用于旧轴转换，减少重复模拟。
切面只知道此前发生的事情，不读取之后尚未提交的技能块。过去释放的投射物、正在执行的
技能、Buff 的后续触发等必须保留。切面之间只有分支和回退，不做合并。

**当前不能恢复一场完整战斗，旧轴转换尚未获得切面加速。** 已有的数据拆分、局部恢复和
投射物联合测试是基础，不是功能完成证明。不要按文件数量或局部测试数量估算完成率。

已接入实际运行的数据包括共享账本、技能与能力系统、冷却、随机取样、事件目录、Buff
容器基础数据及动态实例目录。Buff 的启用/触发序列、普通事件响应、局部定时动作、技能槽替换，
以及 SkillAffix 的事件、预施放请求和 Buff 回收引用已有恢复验证。主要缺口是跨容器对象解析在
标准环境中的实际接线、其他来源宿主重建、整场入口、外部输入隔离收尾、分支结果管理，
以及转换器接入和性能验收。

## 全程边界

1. 状态是纯数据，固定程序与状态分开。只有步进过程中执行游戏规则；保存和恢复不施放、
   不触发事件、不扣费、不重新安装效果、不消费随机样本。
2. 保留现有模拟语义，包括 float32 运算顺序、同帧事件顺序、实例编号、来源归属和回执顺序。
   若发现原有 bug，单独说明证据、修复和预期差异，不能混在重构差异里放行。
3. 多个技能共用的冷却、黑板回退关系、Buff 引用等，在保存和恢复后仍必须共享同一份数据。
   兄弟分支之间的可变对象不得共享。固定程序目录可以共享，恢复时不能重新编号。
4. 未来编辑器计划、未提交技能块及其种子配置留在外部。已经提交的输入产生的延迟行为必须
   保存。外部连续组排程也要能随试探回退，但不能因此塞进战斗内部。
5. 不通过重放此前整场输入冒充恢复，不悄悄从头重算来掩盖缺失状态；恢复不支持的情况必须
   明确暴露。正式可恢复入口开放前，必须完成覆盖审查。
6. 发布前允许修改内部接口，不为旧实验接口增加兼容层。不扩展项目存档格式来迁就这次重构。
7. 手写文件使用 Codex 的补丁接口修改。检查以单线程为主，重型测试、构建和类型检查顺序执行；
   不加载整个游戏转储，不长期保留所有试探历史，不引入未经测量的缓存。

## T0：核对缺口并固定基线

**状态：已完成。** 详细分类、命令和结果见
[状态覆盖清单](../research/combat/runtime-checkpoint-coverage.md)。T0 不代表完整战斗恢复已经可用。

**做什么：** 核对当前分支、HEAD、工作区修改及实际可运行环境，保留已有工作。沿
`CombatStateGraph`、装配对象和环境对象逐项追踪所有影响后续结果的可变字段。
在本文件的“验收记录”中链接覆盖清单和基线结果，避免重新建立一套平行待办。

**参考代码：** [数据根](../../src/core/combat/runtime/combatStateGraph.ts)、
[装配](../../src/core/combat/runtime/combatRuntimeAssembly.ts)、
[标准环境](../../src/core/combat/runtime/standardPlayerDamageEnvironment.ts)、
[通用步进器](../../src/core/combat/runtime/stateStepper.ts)。

**质量要求：** 每个可变字段说明“固定程序／战斗数据／外部输入／仅步进中临时值／可重建缓存”
中的归属、所有者、恢复方式和证明它不遗漏的测试。可重建缓存不得反过来影响业务顺序。
特别检查 WeakMap、闭包局部变量、订阅句柄、延迟请求、编号分配器和输出数组。

**验收：** 无未分类的可变字段；所有尚未接线项都有对应后续任务。记录基线代码身份、样本文件
校验值、种子、运行参数、最终伤害、逐帧回执及状态摘要。基线是同一输入的当前新版从头运行，
不是旧版伤害，也不是会持续变化的临时默认轴。临时大文件放忽略目录，保留可复现方法。

## T1：完成 Buff 恢复

**做什么：** 恢复实例生命周期、层数组、发布顺序、触发进度、黑板、属性与伤害/治疗/失衡修正、
护盾、标签、子实例、动作宿主和事件订阅。先重建数据引用，再绑定对象和端口，不重新调用 add/start。

**参考代码：** [Buff 对象与容器](../../src/core/combat/buffs/combatBuffs.ts)、
[容器数据](../../src/core/combat/buffs/buffContainerState.ts)、
[实例数据](../../src/core/combat/buffs/buffInstanceState.ts)、
[Buff 动作宿主](../../src/core/combat/runtime/buffLifecycleSequenceRuntime.ts)、
[事件分发](../../src/core/combat/events/abilityEventDispatcher.ts)。
参考已有护盾、属性归属、监听重新绑定测试，但不要把这些局部测试当成容器恢复证明。

**边界：** 不重算创建时已确定的护盾参数，不重加修正项，不改变原生叠层、替换与失效规则。
跨实体来源、全局 Buff、被动/装备产生的 Buff 都必须有明确的恢复所有者。

**质量与验收：** 在添加后、叠层变化后、触发前后、部分吸收后及结束前保存。恢复后逐帧比较
状态和回执，覆盖正常到期、替换、驱散、触发、子 Buff 清理与同步重入。旧分支的结束/注销操作
不能影响新分支；重复结束不能重复扣层或移除修正。所有注册数量和属性结果与从头运行一致。

## T2：接通完整装配

**做什么：** 为标准环境和整场装配提供完整恢复路径，接入 T1、技能、能力系统、共享冷却、
随机、时间系统、逻辑实体、子技能、全局 Buff、投射物及回调。重建各来源的操作执行器与监听。
先准备新的数据和绑定，全部成功后再交给会话使用。

**参考代码：** T0 的装配与环境；
[技能恢复](../../src/core/combat/runtime/skillRuntime.ts)、
[能力系统](../../src/core/combat/runtime/abilitySystemRuntime.ts)、
[投射物联合测试](../../src/core/combat/runtime/projectileRestoration.test.ts)、
[回调恢复](../../src/core/combat/runtime/projectileCallbackRuntime.ts)、
[固定回调目录](../../src/core/combat/runtime/projectileCallbackPrograms.ts)。

**边界：** 不直接构造普通新战斗再覆盖字段；普通初始化可能已经注册效果和执行行为。
不保留旧执行器、旧宿主或其闭包。Owner、Source、施法来源和伤害归因分别恢复，不相互替代。
尚缺的逻辑实体、子技能、被动和装备宿主绑定必须在此完成，不能只接已通过测试的投射物。

**质量与验收：** 恢复前后编号计数、随机位置、回执和事件数量不变；恢复过程中无业务回调。
故意缺少程序、实体或监听绑定时，恢复失败且原分支仍可继续运行。测试创建/销毁后恢复、
待回收实例、跨实体引用和共享冷却。第一个整场样本必须包含伤害、Buff、时间膨胀和投射物，
中途恢复后至结束的状态和回执逐帧一致，而非仅最终总伤相同。

## T3：统一会话与分支回退

**做什么：** 把完整装配接入统一步进、保存、恢复和分支 API，替换实验性的分散保存入口。
完成未来输入隔离、连续组排程回退、随机配置绑定、分支回执与历史结果管理。

**参考代码：** [步进器](../../src/core/combat/runtime/stateStepper.ts)、
[模拟驱动](../../src/core/combat/runtime/combatSimulation.ts)、
[输入运行时](../../src/core/combat/runtime/combatInputRuntime.ts)、
[回执](../../src/core/combat/receipt/combatReceipt.ts)、
[应用服务](../../src/application/scenarioSimulationService.ts)。

**边界：** 只在完整步进边界保存；帧中保存/恢复明确拒绝。树形历史不支持合并，不因记录父子
关系而永久持有所有节点。旧句柄不能操作恢复分支。只共享固定程序和明确不可变的历史数据。

**质量与验收：** 同一切面依次尝试 A、B、再 A，两个 A 的结果完全相同，B 不污染它们。
覆盖第 0 帧、空输入、同帧多个输入、连续组、时间膨胀、随机模式和执行失败后回退。
只改变未来技能块的 ID、参数或种子时，共同前缀的战斗数据相同。调用方释放试探分支后，
会话不继续持有其可变数据；反复试探的内存不能随已丢弃的历史无限增长。

## T4：真实轴正确性验收

**做什么：** 固定一组真实输入，批量运行“从头模拟”和“保存后恢复续算”，输出首次差异的位置。
样本必须来自当前可定位的文件或分享记录，不临时拼一个只有空操作的轴作为整体证明。

**参考：** [公开轴回归](../../src/application/publicShareRegression.test.ts)、
[运行入口测试](../../src/application/runScenarioSimulation.test.ts)、旧轴转换工具的样本与证据记录。
优先纳入“简单自用电队钱本 (副本)”“弭洛卡骏”及覆盖其他机制的配队；先核实实际文件和分享 ID，
缺少任何一个时在记录中说明，不能用同名样本冒充。

**验收矩阵：** 多段/强化技能；Buff 叠层与周期伤害；装备/被动监听；终结技膨胀与局部变速；
切人和连续组；投射物及实体子技能；资源、护盾和提前结束。每种机制覆盖边界前、边界后及
同帧事件多的保存点，期望/随机模式都测试，随机模式使用多组固定种子。

**判定：** 对同一新版输入，恢复续算的状态、伤害分项、诊断及有序回执应一致。用可读差异定位
对象、字段、帧和事件，不仅比较哈希。不能普遍删除 ID、排序事件或放宽浮点误差来消除差异。
若字段确属无业务意义，先证明并明确列出排除项。旧版比较另行记录，不作为恢复正确性的基准。

## T5：旧轴转换复用前缀与性能验收

**做什么：** 在已确定的输入前缀处保存，候选时间试探从该切面恢复，只推进受影响的后缀。
候选通过才提交下一段；失败候选不污染已接受结果。不得改变用户已确认的时间修复算法。

**参考代码：** [时间修复](../../tools/legacy-timeline/heuristicRetiming.ts)及其测试、
[转换](../../tools/legacy-timeline/projectConversion.ts)、
[模拟审计](../../tools/legacy-timeline/simulationAudit.ts)。

**必须保持：** 全局按旧轴顺序处理；首技能按原时间。之后取旧轴真实时间、同轴前一块新版
实际显示结束、全局前一技能新版开始加旧轴间隔三者的最大值；落入终结技时间膨胀期间则后移
到其结束。显示时长来自真实模拟，不填估算值，不改存档结构。合法输入模拟失败按程序 bug 排查。

**质量与验收：** 优化前后转换结果、输入顺序及诊断一致；已有偏差必须逐项解释。
记录完整模拟次数、总推进帧数、候选数、复制/恢复耗时、总耗时、峰值内存和保留切面数。
同机同输入同种子测短、中、长轴，预热后至少重复 5 次并报告中位数及范围。
证明共同前缀不再为每个候选重复推进；不能仅以调用次数减少或微基准证明加速。
长轴须得到可重复的总耗时收益，短轴若回退需修复或说明有依据的策略；内存若持续增长不得通过。
不宣称恢复是常数复杂度：完整复制成本取决于状态规模，必须把它计入测量。

## T6：收尾与最终交付

删除被正式入口替代的临时 API、重复绑定、过渡缓存和无用测试夹具。保留能独立检验业务语义
的测试，不为维持旧接口再包一层。整理文档：架构只写最终设计，本文保留任务验收，交接只写
当前结果和下一项任务，本机路径留在本地环境说明。清掉过时的“尚未接入”和重复阶段日志。

最终交付包括：正式 API 与调用示例、覆盖清单、整场对比结果、转换性能结果、已知限制及复现命令。
所有 T0—T6 验收项都有代码/输出证据，且不存在被忽略的恢复路径，才可标记目标完成。
代码提交按当前用户授权处理，不因本计划自动推送或部署。

## 检查命令与执行纪律

在仓库根目录运行。局部开发先跑对应测试，重型检查顺序执行，避免占用过多内存。

```powershell
# 例：当前投射物联合恢复测试；其他模块替换成相应文件
npx vitest run src/core/combat/runtime/projectileRestoration.test.ts --maxWorkers=1 --silent

npx vitest run src/core/combat src/application/publicShareRegression.test.ts src/application/scenarioSimulationService.test.ts src/application/runScenarioSimulation.test.ts --maxWorkers=1 --silent

# 转换器接入后增加此项
npx vitest run tools/legacy-timeline --maxWorkers=1 --silent

npm run type-check
# 只对实际修改文件运行 prettier --check，不通过脚本改写文件
```

最终整合另跑 `npm test -- --maxWorkers=1 --silent` 和 `npm run build`；修改契约或生成器时
按开发指南增加对应类型检查与测试。纯文档修改只检查格式、链接和内容，不无故跑整套模拟。
测试通过后，只有新改动或未解决风险才扩大/重复检查。
