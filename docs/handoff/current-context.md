伤害从保存的 `skillCastInfo.originSkillType` 恢复来源技能分类，投射物自身没有新增分类或资源字段。
活动能力实体子技能也已进入该样例：恢复时从实体保存的来源施法身份取回原固定技能程序，并把
子技能继续绑定到原动作宿主状态；回能、伤害和后代对象因而保留来源技能归因，不改写成子技能名。

原生连携条件也已接入同一恢复样例。标准环境是在 AbilityEvent 分发阶段调用公共条件运行时，
这里不存在需要重新分配或重绑的独立订阅 ID；切面现在按编译条件 key 保存每条条件的 direct
黑板与公共动作宿主账本，恢复时重新安装固定条件程序并绑定这些数据。投射物回调伤害触发条件后，
原始分支、命中前恢复分支和活动回调宿主恢复分支的累计黑板与连携窗口一致。该验证同时发现并
修复了回调恢复遗漏来源技能组的问题，恢复后的伤害事件继续带原技能的
`executingSkillGroupKey`，没有把技能组写成投射物私有状态。

装备和潜能来源现已进入这条综合链。回调的 `beforeOutputDamage` 先让已启用装备能力在其共享黑板
累计命中次数，随后 `outputDamage` 由按 `battleSkill` 技能组筛选的潜能监听施加持续 Buff；保存的
装备原生订阅与潜能语义订阅都由恢复分支按原身份接回。三条分支的装备黑板、潜能 Buff、订阅目录、
回执及完整状态图保持一致，不再只依赖来源子系统的隔离接口测试。

`restoreCombatRuntime` 已把预检、基础环境、能力实体外壳、敌方定时标记、对象图和正式帧阶段合成
一个公开候选。恢复后的能力实体 Buff 会按实体时间推进、回收，并在实体结束时释放；整场帧驱动
保持时间膨胀、资源、全局 Buff、能力实体、投射物、敌方 Buff/生命/状态、干员状态与能力系统的
既有先后顺序。对象工厂可在建立宿主时取得恢复分支的敌方定时标记，不必捕获旧分支对象。

活动 `SkillAffix` 的纵向恢复现已覆盖投射物对象引用：保存的 reset 登记按原编号接回恢复分支，
来源技能、输出 Buff 和普通能力实体都结束后，宿主 Buff 仍等待该投射物实际回收；恢复分支的
reset 只释放恢复分支引用，原分支投射物和 Buff 保持活动。完整装配还可预建当前分支投射物目录，
并在来源宿主创建前登记全部恢复后的干员核心，为生产操作链接线消除旧分支闭包入口。

T2 的正式装配恢复已完成。缺失投射物回调程序的候选会在提交前失败，原分支状态保持不变，随后
仍可从同一保存点建立正常分支。在统一会话完成前仍不能用于加速旧轴转换。

T3 已建立第一层 `CombatRuntimeSession`：会话只公开完整帧推进、数据读取、保存和恢复，检查点由
所属会话的弱引用目录管理。恢复先从检查点副本构造完整候选，成功后才替换当前装配；失败候选不
改变当前分支或换代编号。同一检查点按 A、B、A 推进已验证两个 A 完全一致，B 不污染回退结果。
技能输入现已把固定输入位置、递归接续位置/前项/停止状态，以及每个持久连续组的位置、前项和停止
状态移入纯数据；外部事件也保存消费位置。恢复会校验组锚点、前项身份、游标范围和保存帧，不按

运行时，并保持“连携窗口、技能输入、AbilitySystem、投射物能力阶段、外部事实”的原帧顺序。
整场 A/B/A 样例同时放置第 0 帧和第 4 帧技能输入与外部事实：保存前输入没有在恢复时重放，未来
输入在原分支和恢复分支均恰好执行一次，完整状态图一致。会话恢复还可显式选择候选装配工厂，
