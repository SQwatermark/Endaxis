# 项目与工具

这份说明只介绍用途。实际仓库、分支、构建、地址和端口见 [本地环境](local-environment.md)。
各工具的启动参数以它自己的README为准，不在这里再维护一套命令。

| 工具                    | 做什么                                     | 不负责什么                          |
| ----------------------- | ------------------------------------------ | ----------------------------------- |
| Endaxis                 | 把用户输入和游戏定义编译、模拟并显示       | 运行时不直接解密游戏资源            |
| AKEDatabase / AKEDB CDN | 前端字段解释、结构化游戏数据和图片来源     | 不能代表完整客户端行为              |
| vfs-index-browser       | 按逻辑路径查找本机游戏资源，按需解码和导出 | 不决定Endaxis要下载哪些资源         |
| AnimeStudio             | 读取Unity对象、模型、材质、动画和Shader    | 不处理Endaxis网页业务               |
| IL2CPP-Dumper           | 获取类型、代码、方法探针和进程内存         | 一次转储不能证明所有版本和状态      |
| combat-spec             | 根据证据实现可执行的C#行为规格和测试       | 不是Endaxis的默认资源目录或UI模拟器 |

## 数据从哪里取得

Endaxis的需求清单和来源选择由 [转换器](../../tools/game-data-compiler/README.md)管理。
CDN入口、清单格式和版本规则也以该处实现为准，不照抄旧手册里的逐集合URL。
AKEDatabase前端代码可用于理解字段和富文本，但下载不应依赖本地前端仓库中的旧数据。

VFS先通过索引和manifest定位Bundle，再按文件类型解析内容，不必全量解包。
同名资源可能有多个候选；调用方应根据来源选择，不能直接取第一个。
来源缺根SkillData时，只有BuffData并不能证明整个技能的时序。

## 使用和修改工具

- 每个独立仓库单独检查Git状态、验证和提交。不要清理与当前任务无关的研究修改。
- 修改AnimeStudio后保留真实资源回归，核对GameObject/Transform、模型和动画等已有导出。
  VFS使用的构建应与源码一致，不保留已经失效的回退路径。
- IL2CPP采集先查已有文件，再决定是否启动游戏或注入。不要反复启动第二个客户端。
  崩溃或报错后检查输出完整性，不能把残缺文件当作成功；已有读取方式见 [本地环境](local-environment.md)。
- combat-spec在其工作区运行C#测试，具体解决方案和CLI参数以该仓库README为准。
  测试应验证实际顺序和输出，明确已确认、推断和未知部分。
- 音频、模型等专题工作树是研究分工，不应长期形成多份正式实现。
  临时目录可能包含未保存的证据，不能因名称像缓存就删除。

## 外部参考

此前参考过endfield_research_kit、EFMI-Package，以及RuriRipper、Shader和动画相关工具。
这些项目用于理解格式和算法，不是默认运行依赖。采用代码前核对版本、许可证和维护成本。
完整历史工具名可从Git中的旧工具总览追溯；不把旧克隆位置当作本机现状。
