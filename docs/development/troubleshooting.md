# 常见问题

先确认实际工作区、正在运行的构建和日志，再修改代码。不要用占位数据或无效回退隐藏错误。

| 现象                 | 先检查什么                                                         |
| -------------------- | ------------------------------------------------------------------ |
| 页面一直加载         | 应用层任务是否结束、目录请求是否失败、控制台错误、生成定义是否存在 |
| 资源曲线与警告不一致 | 是否读取同一份战斗结果；警告不能另建资源账本                       |
| 撤销只能恢复一次     | 历史中是否混入派生对象，恢复时是否重新分配随机身份                 |
| 新干员生成缺内容     | 来源版本、根SkillData、Buff和实体引用是否完整；不能拿旧TS补缺      |
| Prefab导出失败       | AnimeStudio构建、对象快照功能、Bundle及CAB映射是否匹配             |
| 服务连不上或返回502  | 主机是否可达、服务是否运行、实际监听地址、日志和当前启动参数       |
| 运行时采集失败       | 进程和模块、已有客户端、工具版本、权限以及输出是否完整             |

## 连接另一台机器

连接信息只写本机环境文件。先检查网络，再检查认证与服务：

```powershell
Test-NetConnection <主机> -Port <SSH端口>
ssh <用户>@<主机>
```

常见原因包括地址变化、网络不同、VPN未连接、OpenSSH未启动或防火墙限制。
一次连接成功不代表下次仍可用；主机重启后也不能假定服务已经恢复。

## 验证失败

先区分代码错误与测试环境错误，保留实际错误信息。
例如Windows创建symlink时报EPERM，应说明失败发生在哪里，不写成全部测试通过，
也不直接删除断言。类型检查内存不足时先停止并行大任务，不连续扩大堆或启动更多检查。

修复后重跑相关检查；新失败或行为变化才扩大范围。结束时说明改动、验证结果和剩余问题。
