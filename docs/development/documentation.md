# 文档维护

Endaxis 只保留有实际用途、凝练的当前说明和近期交接。

- 架构：说明职责、数据流、关键约束和代码入口，不复制接口或枚举。
- 开发：说明操作方法，命令只在所属工具 README 维护。
- 交接：改写当前状态、剩余项和最近验证边界，不在顶部叠加日期日志。
- 原生游戏逻辑：结论、版本、原始配置、哈希及取证范围归 combat-spec。
  Endaxis 只说明采用的规则与单敌人模型的简化，不能将简化反写成原生事实。
- 性能与验收：保留近期仍用于决策的方法、基线和限制，过期报告删除。
- 中间产物：审计 JSON/Markdown、缓存、转储和本机信息不进入文档目录。
  固定测试输入按实际消费者保留在测试目录。

优先更新已有主题。完成的计划、重复教程、日期流水账直接删除，不另建 archive。
删除前转移独有原生证据，保留当前未完成事项；历史过程可以从 Git 找回。
移动或删除后同步检查文档链接、代码注释、路径读取和工具默认输出，避免下次运行重新生成旧文件。
跨仓库链接按并列工作树解析；发布文档时须同时提供对应 combat-spec 版本。
