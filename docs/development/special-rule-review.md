## 仍需核对的行为

### 洛茜的原生连携环

本机证据为 `tmp/projectile-live-20260911/IL2CPP_Dump_Normal/Gameplay.Beyond.dll.cs`
中的 `ShowComboRingQte`，以及 `tmp/il2cpp-current/IL2CPP_GameAssembly.runtime.bin`。
下述结论来自后者按虚拟 RVA 定位的静态、非热更分支，不保证正在运行的版本没有热更覆盖。
它与最新 AKEDB 快照的版本对应关系也尚未证明。

- `ExecuteInternal`（RVA `0x0602AF98`）读取提前时长和有效时长，保存总时长及开始时的连携剩余时间，
  发送 `ON_COMBO_SKILL_RING_QTE`，携带队伍位置、总时长和有效阶段开始时间。
- `_OnComboSkillCast`（RVA `0x0602B594`）先核对队伍位置，再用开始时与当前的连携剩余时间之差判断窗口。
  该静态分支要求差值不小于提前时长、不大于总时长，随后执行成功回调。
- `_GetRemainTime`（RVA `0x0602B470`）查询连携剩余时间；不能据此认定它等于某个 Buff 的剩余寿命。
- UI 的 `ComboSpecialNodeRingQte` 接收同一事件，先进入 `EarlyState`，到有效阶段切换为 `PerfectState`，
  超时进入 `MissState`，输入后进入 `PressedState`。`PerfectState` 会通过 `ringStateController` 切换显示状态，
  与游戏中看到的发光阶段一致。

当前源数据给出的提前阶段和有效阶段均为 0.5 秒，QTE 总计 1 秒；外层监听 Buff 的 6 秒寿命不是窗口时长。
因此，成功 Buff、原生连携环事件和输入判定是不同证据。暂停行为以及 IFix 是否覆盖静态方法仍未核实。

此前 `buffRuntimeProjection.ts` 会按共享黑板键关联计时 Buff，在原始分支之外安装计时动作，
再用 Buff 存在性代替 QTE 回调。这一错误推断已删除。
现在生成定义直接保留 `ShowComboRingQte` 的提前时长、有效时长和完整 `triggeredAction`；
运行时按连携剩余时间差判断，窗口内输入才执行成功动作。没有增加干员配置项。
UI 暂时只沿用旧版成功高亮，不展示四种原生细分状态。高亮直接读取成功 QTE 回执携带的
`sourceActionId`，不再用后续成功 Buff 的来源反推；因此一次命中只会点亮实际按下的第二段。

### Buff 伤害归属与可见性

回执记录实际执行 Buff 的身份，与 UI 是否有可见持续条，是两件事。
洛茜爪印斫痕已有场景回归，但不能据此证明所有 Buff 都应从技能轴隐藏。
现在只把能按目标、Buff ID、实例 ID 和执行帧对应到实际可见 Buff 段的伤害放在 Buff 条上。
其余伤害只要仍继承原技能的 `castId` 和 `hitId`，就留在技能命中点：包括隐藏 Buff 和能力实体持有、
但打向敌人的 Buff。定义投影会沿 `applyBuff` 引用收集候选伤害；运行后仍以实际伤害回执决定是否显示。

庄方仪单独释放战技的原生动作链给出了这个边界：`buff_chr_0030_zhuangfy_normal_skill_trigger_sword`
找到召唤出的剑，再把 `buff_chr_0030_zhuangfy_sword_triggerd` 施加给当前能力实体。后者在本地第 6 帧执行
最后一剑伤害。实际回执的 Buff 所有者是 `ability-entity:2`，受击目标是敌人，因此没有敌方 Buff 段可承载；
该命中应回到本次战技。只有一把剑时，原生 `swordCnt` 先减一，普通段的 `swordIndex < swordCnt` 不成立，
只有 `swordIndex == swordCnt` 的最后一剑成立，实际命中帧是 29。这里没有加入庄方仪 ID 特例。

洛茜爪印斫痕仍由敌人持有，并能对应到同实例的可见敌方 Buff 段，所以持续伤害继续显示在
`buff_chr_0028_wulfa_normal_bleed` 上，不回到洛茜技能块。
