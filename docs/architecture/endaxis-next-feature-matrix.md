# Endaxis Next 功能迁移矩阵

## 1. 状态定义

每项功能分别经过四个门槛：

- **M（Model）**：项目文档或目录模型能够无歧义表达；
- **C（Core）**：无 Vue 的命令、编译、模拟或投影逻辑已实现；
- **E（Evidence）**：有旧版 fixture、游戏快照或反编译证据可重复验证；
- **U（UI）**：并行新版入口已经接入且通过用户流程测试。

状态使用：`完成`、`进行中`、`未开始`、`暂缓`。只有 M/C/E/U 全部完成，功能才可以计入入口切换条件。

## 7. 当前执行顺序

1. 将机制语义校验接入 resolved scenario 构建边界，并实现目录 adapter；
2. 补齐武器、装备、套装、敌人和系统规则目录接口；
3. 收集真实旧存档、面板快照和性能基准 fixture；
4. 实现 build resolver 和 panel calculator；
5. 以 `combat-spec` 为依据定义首个真实 combat program 和 receipt；
6. 贯通佩丽卡主动攻击闭环并测量增量重算；
7. 再进入 editor command 与并行 UI。

每次交付更新本矩阵，不以“文件已创建”代替 M/C/E/U 任一门槛。
