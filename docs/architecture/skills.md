# 技能定义、编辑与执行

技能模板、时间轴上的一次释放和运行中的技能实例是三种对象。它们共享技能身份，但各自保存不同内容。

## 模板和一次释放

游戏数据中的 `SkillDefinition` 描述技能动作、黑板、条件、费用和时序，不保存翻译名称或编辑器布局。
完整字段见 [公共技能类型](../../packages/game-data-contract/src/skills.ts)，本文不复制一套容易过时的接口。

用户项目用 `SkillCastDocument` 保存一次释放，结构见 [项目格式](../../src/core/project/schema.ts)：

- `source` 指向技能组、技能和玩家操作。
- `placement.startFrame` 保存用户安排的战斗帧。
- `presentation` 保存颜色、锁定、禁用和辅助展示条等编辑属性，不承载技能动作定义。
- `simulationInputs` 保存本次释放需要的额外输入，例如镜头角度和强制暴击的步骤身份。
- `customDefinition` 保存完整技能覆盖；存在时替代模板，不是与模板逐字段合并的补丁。

没有覆盖时使用版本化游戏数据中的模板。恢复模板就是移除覆盖。养成和配装仍由各自数据参与编译，
不能为了编辑一次技能，把整套构筑效果复制进技能覆盖。

`kind: 'custom'` 的自由展示块目前没有可执行技能定义，不能进入战斗编译。
可执行的自定义技能使用 `operatorSkill` 来源和完整 `customDefinition`。

## 编辑和校验

编辑器允许用户表达输入；编译和模拟应明确报告无法处理的数据，不应偷偷删动作、换技能或补默认规则。
不要把“技能释放条件不满足”与“定义无法编译”混为一谈：`availability` 用于合法性诊断，
条件不成立也不跳过用户已排入时间轴的技能。

玩家操作、技能库分组和实际执行技能也不是同一个身份。输入映射选择操作指向哪个技能，
接续窗口决定能否提前中断；条件输入信息不足时应报告未知。技能组整组放置策略属于编辑器元数据，
不能拿它代替单个技能的运行规则。

## 几种时间各管什么

| 字段                    | 用途                               |
| ----------------------- | ---------------------------------- |
| `timelineBlockFrames`   | 时间轴技能块的显示宽度             |
| `naturalDurationFrames` | 技能局部时钟上的自然结束周期       |
| `exclusiveFrame`        | 判断当前技能能否被中断的原生边界   |
| `costFrame`             | 从施放开始计数的扣费与冷却确认时刻 |
| `cooldownFrames`        | 冷却配置，编译时解析等级值         |

这些值不能互相代替，也不能用最后一次可见伤害推断技能寿命。
原生自然结束周期由生成数据保留；到期时，运行时先执行本帧动作，再结束技能。
只有缺少 `naturalDurationFrames` 的旧自定义定义，才兼容使用“时间轴动作全部完成”作为结束边界。
显式结束请求和中断也可以结束当前释放。具体顺序见 [SkillRuntime](../../src/core/combat/runtime/skillRuntime.ts)。

## 编译、执行和结束

编译器解析模板或完整覆盖、等级和配装，生成运行时需要的程序。
[编译程序类型](../../src/core/compiler/combatProgram.ts) 区分时间轴放置身份和技能执行程序，
运行时无需读取编辑器文档。

结束当前技能会处理它的时间轴、附着清理、冷却结算和结束通知，不能据此清空所有外部对象。
已经发射的投射物、Buff和其他执行对象各有生命周期；是否随技能结束取决于明确的绑定关系。
投射物结束回调有独立技能实例，回调结束与投射物回收也不是同一件事。

只有表现回调、或没有启用回调的投射物，也可能被其他技能持有，因此仍要保留发射和回收通知。
已支持的直线投射物在固定零距离模型中按移动Tick到达：一段需要一个Tick，多段每Tick推进一段。
多段同时保留原始持续时间上限；未获准执行Tick时，不能自行推进段数。
结束后再按所有启用回调技能的最大原生时长等待回收，随后分别标记回收、执行reset。
空目标组不发射，多个能力实体目标逐个发射。适用条件与来源见
[投射物生命周期编译](../research/combat/projectile-lifetime-compilation.md)。

界面根据实际结果记录展示命中和状态。强化状态条按确认的 Buff 回执生成，不能把任意自身 Buff
猜成强化状态，也不能把显示条的长度写回技能寿命。

运行对象、事件清理和各自时钟见 [战斗执行与状态](runtime.md)。
旧设计细节保存在 [生命周期旧稿](../archive/next/history-skill-lifecycle.md) 和
[定义蓝图旧稿](../archive/next/history-skill-definition-blueprint.md)，使用其中结论前仍需核对代码与证据。
