# 事件、Buff 与宿主生命周期

事件系统同步传递已经发生的事实；Buff 和被动宿主拥有响应程序、修正和清理关系。事件中心不决定 Buff 应何时结束，Buff 容器也不拥有所有技能输入或伤害规则。

## 入口与依赖

- `AbilityEventDispatcher`：事件/载荷、订阅阶段和优先级 → 同步处理函数调用；保存订阅数据，绑定当前分支函数。
- `CombatSemanticEventRuntime`：定义中的触发器 → 原生实体订阅或明确的手工标记；组合订阅必须保留每项数据引用。
- `AbilityEventHostLifecycle`：被动、装备、养成等宿主 → 注册句柄、子 Buff 与禁用清理；不是另一个事件总线。
- `CombatBuffContainer` / `CombatBuff`：已解析定义、来源、黑板和目标 → 有身份的实例、堆叠、启停及修正。
- `GlobalBuffRuntime`：全场父实例 → 共享资源修正和队员上的普通子 Buff 镜像。
- `GameplayTagRegistry` / `GameplayTagPredefine`：路径查询与配置 → 读取目标当前标签；不另存一套控制状态。

编译层提供固定动作和定义，装配层提供账本、实体目标、事件端口与回执。事件触发期间的条件和动作继续进入同一个领域执行链，不能靠显示用的来源标签反查一个近似宿主。

## 同步事件顺序

一次分发依次执行 callback、action、skill、combo。action 按优先级降序、同优先级按登记编号排序。每个阶段开始时单独获取处理函数快照：同阶段新增者等下一次分发，后续阶段可以看见新增订阅；同阶段已经选中的函数即使中途注销仍会调用，宿主许可决定是否继续动作。

事件上下文边界只临时写入 event、eventSkillCastInfo、目标上下文和 InputTarget。内层退出或抛错后通过 finally 恢复外层事件/Trigger，不改变宿主保存的施法、Buff 来源或执行身份。新事件没有来源时清除临时来源，不沿用外层来源。

游戏事件响应抛错会中断同步分发并由外层会话处理失败；这里不吞掉错误继续算战斗。应用层性能订阅者的隔离策略不适用于这条游戏规则链。

## 订阅和宿主所有权

订阅状态保存事件、阶段、编号与优先级，处理函数由本分支 dispatcher 持有。恢复按原引用绑定，拒绝另一目录、错误事件、缺项和重复绑定，不重新 register 分配编号。

宿主登记所有订阅和子 Buff；结束/禁用时释放。恢复先绑定订阅，再在全部 Buff 实例存在后接回子关系，不重新应用子 Buff。宿主适配器清理会尽量完成注册释放、禁用动作和子 Buff 结束，并汇总异常；这是接线层失败处理，不是通用的原生异常恢复规则。事件安装半途失败只清理已安装部分，完整候选仍须丢弃。

## Buff 的状态并非一个布尔值

Buff 身份由 ownerId 和实例编号定位，定义 ID 只表示规则。实例持有黑板、时长/触发余量、堆叠/启用状态、来源、子关系及修正对象。容器持有成员顺序、实例目录、堆叠组、添加冷却和实体标签计数。

创建、增强、Enable/Disable、MarkFinish、Release、Recycle 各有边界：

1. 增层先更新层数并发变化事件，再刷新属性，所以同步监听者可以读到新层数和旧属性。
2. 结束先执行结束动作和持续动作收尾，再标记 finished、处理子关系与修正清理，最后通知结束。不可结束的实例走延展标签逻辑，不冒充结束成功。
3. Tick 遍历当前成员并推进各自时间；周期回调每次检查宿主，前一次触发可能已经使后续触发失效。
4. 独立回收阶段逆序检查当前结束状态、调用回收回调，然后移出目录。回收回调期间旧引用仍可解释；完成后不能作为活实例使用。
5. 宿主释放调用 releaseAll，不等待已经停止的宿主再 Tick；重复或重入释放有专门门禁。

这些遍历有的使用快照、有的保留实时成员影响，不能统统替换为一个 forEach 模板。技能附着 Buff 的结束清理也必须逐项重新检查引用，早先回调可能已经回收后面的对象。

## 全局父实例和标签

GlobalBuff 父实例有精确身份，按全局时间推进；队员镜像是普通 Buff。任一镜像消费父实例时清理同一父的全部镜像和共享修正，不能按名字清理其他同名实例。创建子关系失败会结束已创建的父实例；恢复先建立普通实例，再绑定全局父目录，最后统一接回跨实例关系。

标签是带层级的路径，非 exact 查询允许子路径满足父路径。实体标签以计数保存，移除一个来源不应抹掉其他来源。预定义标签和免疫查询只是配置，实际门禁、Buff/状态消费者读取同一容器；新增标签不能只改 UI 或维护另一份布尔标记。

## 恢复与扩展检查

Buff 恢复预检身份、来源属性绑定、修正别名、父子关系和订阅；实例与关系分阶段绑定，失败阶段不能继续使用。保存来源名称不代表一定需要复活来源对象，但消费者确实读取来源属性时必须有有效端口。

新增事件要说明发布时点、载荷和当前事件作用域；新增 Buff 效果要说明启停、叠层、结束/回收、句柄所有者、时间域及恢复。验收至少覆盖嵌套事件、同帧增删订阅、同名实例、子 Buff 自结束/父释放、回收中读取和分支恢复。原生测试位于 events/buffs/tags、Ability 宿主及 restoration 对应文件；游戏版本中的全部事件语义仍需独立来源证据。
