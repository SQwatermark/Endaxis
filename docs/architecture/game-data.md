# 游戏数据与编译

游戏数据编译器把原始表、技能和资产转换成 Endaxis 使用的定义。应用读取这些定义，再按用户构筑准备一场战斗。原始格式、公共定义和可变战斗实例是三个不同层次。

## 公共类型

[packages/game-data-contract](../../packages/game-data-contract) 是生成器与应用共同使用的数据模块，不是已发布的 npm 包。它不依赖应用、转换器、浏览器或文件系统。

| 文件              | 定义内容                     |
| ----------------- | ---------------------------- |
| `primitives.ts`   | 身份、元素、等级值及基础枚举 |
| `gameplayTags.ts` | 标签查询及预定义配置         |
| `conditions.ts`   | 条件与数值引用               |
| `actions.ts`      | 动作、序列、调度和公共事件   |
| `skills.ts`       | 技能、技能组和能力实体       |
| `operators.ts`    | 干员、成长、天赋与潜能       |
| `buffs.ts`        | Buff 属性和生命周期程序      |
| `modifiers.ts`    | 属性槽及伤害、治疗、失衡修正 |
| `equipment.ts`    | 武器、装备、套装及词条       |

同一个概念只声明一次。消费者需要部分字段时从公共类型选取，不复制一份同形接口。原生类型留在转换器来源层；请求、缓存和诊断留在工具实现中；战斗状态与回调不进入生成定义。

字段的含义、单位、缺省行为、等级轴和引用作用域写在类型注释中，文档不再复制全部字段清单。

## 查询协议与校验边界

运行时所需的不是整份资源目录，而是已经装载好的同步查询端口。`GameDataRepository` 按稳定身份返回定义或 `null`；`GameDataBrowser` 另外提供目录枚举，供选择器使用。缺少定义由当前编译或校验入口处理，查询本身不下载文件、不选择替代定义，也不接触活动战斗状态。异步装载必须在进入核心前完成。

同一个仓库还持有 `actionPrograms`：它是图编译目录，不是战斗程序的执行器。因此“只读查询仓库”不等于可以直接序列化的纯数据对象。Worker 传输定义集合后重建仓库和缓存，不传递这个类实例。

输入检查分层进行，不能互相代替：

| 入口               | 输入与失败方式                                                              | 不保证什么                                   |
| ------------------ | --------------------------------------------------------------------------- | -------------------------------------------- |
| 项目解析与结构校验 | 接收未知 JSON，返回带字段路径的结构问题、非法 JSON 或版本结果               | 不证明全部原生行为都被支持                   |
| 定义校验器         | `validateOperatorDefinition`、装备/技能校验接收相应已成形定义，返回问题列表 | 不能把任意未知对象强转类型后绕过前一层       |
| 共享读取守卫       | 标签、事件名、SkillSetting 资源参数等按各自入口断言或抛出错误               | 不是通用 JSON 修复器，不填默认值掩盖未知字段 |
| 仓库登记           | 拒绝重复身份、冲突/缺失别名目标、非法资源图所有权等装配错误                 | 冻结登记数组不等于深冻结所有定义字段         |

代码入口：[查询协议](../../src/core/game-data/gameDataRepository.ts)、[定义守卫](../../src/core/game-data/definitionGuards.ts)、[干员定义校验](../../src/core/game-data/validateOperatorDefinition.ts)、[仓库登记](../../src/data/createGameDataRepository.ts)。

### 图定义什么时候成为只读

仓库构造会复制并冻结目录数组，查询返回的定义仍保留其原对象身份。图第一次交给 [ActionGraphDefinitionRepository](../../src/core/compiler/actionGraphDefinitionRepository.ts) 时，图、实体定义及相关公共来源会递归冻结，再准备或编译。编辑草稿必须先复制，提交新对象形成新修订；不能把编译调用当成对原对象完全无影响的草稿检查。

缓存按图对象、实体定义目录、导入目录和等级区分；公共定义缓存按来源集合对象区分。仓库的 `revision` 是来源版本标识，不是这些内容的哈希，也不是替代对象身份的缓存失效按钮。换图但复用旧版本字符串仍可得到新编译；原地编辑旧图则违背发布约定。

这些缓存归仓库所有，以 WeakMap 关联来源对象；不保存技能施放、资源或 Buff 进度。部分编译节点按需建立，所以共享的是固定定义与编译结果，不意味着编译器内部每张 Map 都已经冻结。修改查询协议或新增图依赖时，应检查仓库所有权和缓存键是否仍包含该依赖，而不是把新字段一路转发到模拟层。

## 共享实现的归属

契约包只保存数据类型和枚举，不放转换、校验、求值或编辑算法。生成器可以直接引用主包的纯逻辑模块，不必为了复用把实现搬进契约包。

| 位置                                                 | 职责                                                           |
| ---------------------------------------------------- | -------------------------------------------------------------- |
| `src/core/action-graph`                              | 数据节点提取、表达式引用绑定、图和宏的结构校验；不读取战斗状态 |
| `src/core/game-data/definitionGuards.ts`             | 标签、被动事件名、技能资源参数的输入校验                       |
| `src/core/mechanics/combatNumbers.ts`                | 生成器静态计算和运行时共用的数值比较规则                       |
| `tools/game-data-compiler/src/compiler/optimization` | 来源转换后的分支去重、宏提取、裁剪和代码输出                   |
| `src/core/compiler`                                  | 把定义编译成模拟器执行程序                                     |
| `src/application/editor`、`src/ui/action-graph`      | 编辑命令、撤销重做、节点布局和交互                             |

共享模块只依赖契约或同层纯逻辑。生成器不能因此间接加载应用状态、界面或正式数据仓库；应用生产代码也不反向引用生成器。图结构校验与战斗运行时的执行分别维护，绑定表达式不等于提前执行表达式。

## 编译与资源

离线来源准入、读取缓存和生产责任链见[离线游戏数据生产](game-data-production.md)。

流程依次为读取来源、校验引用、解释公共动作、组装领域定义、优化、生成候选、检查、发布。未知原生动作或缺失引用应明确失败，不能读取旧生成文件填补。

普通技能、天赋和潜能由来源结构推断编译方式。人工配置用于需要确认的身份关联、产品范围和显示信息，不逐技能选择编译器。

干员生成到 `src/data/operators/<slug>.generated.ts`。其他正式定义也由登记的生成入口维护；下载文件、原始 JSON、审计和临时模板留在忽略目录。元素反应的公共算法由运行时维护，倍率和时长等版本数据仍从生成定义读取。

图片资源由游戏数据编译器统一输出 WebP。这条规则只针对游戏资源，不限制时间轴图片导出；时间轴 PNG 导出属于产品功能。

版本更新的来源核对、配置表和完整命令集中在[编译器操作说明](../../tools/game-data-compiler/README.md)。

## 类型与数值约定

GameplayTag 使用可读完整路径。原生整数和路径的解析只在来源边界进行，应用不重新哈希或反查。伤害标签是另一种语义，不与 GameplayTag 混并。

`LevelValues` 可以是单值或等级数组，等级轴由所属定义确定；动作黑板引用则在运行时对应作用域求值，不能当作静态等级数值冻结。

Buff 定义与每次施加的参数分开。多个词条引用同一蓝图不要求复制定义；来源施法、Buff 宿主和专门的词条施法身份也不能互相替代。

## 编译优化

优化位于领域组装和步骤身份分配之后。默认只删除能够证明不影响消费者的内容：可确定的无效分支、无人读取的技能写入与黑板初值，以及没有运行入口的装备贡献黑板。

没有运行入口按启用、初始化和事件程序判断，不按“第几个武器词条”判断。Buff 自身黑板和定义身份不能据此删除。

跨 Buff、实体、子技能和回调的读取需要一起分析。未知访问、循环或缺失接收方时保守保留；子黑板已有默认值也不证明父值无用。条件可能写黑板或消费随机数，相同分支不代表可以删去求值。

联合生成收集同批全部消费者的用途，不能用上次产物推断没人读取。独立确定性检查重新读取来源、编译和渲染，不能复用首轮结果证明一致。

优化验收比较同一冻结来源的前后定义，在相同输入和随机策略下检查伤害、资源、状态、来源、诊断及有序记录。减少文件大小不能代替行为一致性。

## 内置装载与项目定义视图

同名的两个 `createProjectGameDataRepository` 处在不同边界，不能混用：

| 入口                                                       | 输入 → 输出                                         | 所有权与失败                                                                |
| ---------------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------- |
| `src/data/projectGameDataRepository.ts`                    | 待打开项目引用 → 异步准备内置模块，返回稳定查询外壳 | 初次只装载引用的角色/装备及公共数据；缺少 loader 或模块未导出对应身份时拒绝 |
| `src/core/project/projectDefinitionLibrary.ts`             | 已准备的基础仓库 + 项目模板库 → 同步联合查询视图    | 项目定义先查、内置定义兜底；项目 ID 与内置冲突时拒绝；新模板库要形成新视图  |
| `src/application/simulation/scenarioSimulationGameData.ts` | 场景 + 联合查询 → 可传输的定义集合                  | 引用无法解析时失败；Worker 重建自己的仓库与图缓存，不传函数或缓存实例       |

内置装载器可以按类别扩充目录，但页面保持同一个外壳。并发装载在 await 之后读取最新集合再合并，避免后完成的类别覆盖先完成的类别；相同类别复用任务，失败任务从登记中删除，允许后续再次请求。模块本身的浏览器缓存与模拟服务缓存是不同的所有者。

项目定义已经完整保存在存档中，origin 只供追溯，不能再按 origin 去查找必需的内置文件。项目装备引用的内置套装仍是真实依赖，需要装载；这一例外不能与 origin 混同。

Worker 数据包按场景 ID 引用缩小角色、装备、敌人、机制与全局效果集合；公共定义和完整消耗品目录仍需携带，后者用于互斥判定。selectionKey 只描述引用身份，不代表定义内容版本。同 ID 的项目定义修改必须通过调用方清空/换代模拟缓存，不能指望选择键自动发现内容变化。

实际页面还封装了一层随项目库变化的查询对象；目前它遗漏了项目全局效果查询，见[边界复现](../research/project-global-effect-reproduction.md)。这说明它与核心联合视图的覆盖范围必须分别验证。新增项目资产种类要同时检查保存/打开、查询/枚举、场景引用、数据捕获和缓存刷新，不能因某一个组合器已支持就假定所有调用者都支持。

## 应用加载与内存

定义按需加载，项目级仓库叠加自定义定义。后台模拟只接收本场需要的数据，不应因便利导入整库。缓存必须明确所有者与释放条件。

来源原文缓存、解析对象、编译结果和最终文本分别占用内存；缓存字节上限不等于 JavaScript 堆上限。性能工作先测组成，再决定减少重复读取、延后加载或缩小保留范围。

## 动作图与身份绑定

技能、Buff、能力实体各自保存完整图，干员与装备负责组织所属定义。图内连接、资源引用、分支去重、宏提取和调用状态统一见[动作图](action-graphs.md)。图的共享实现放在主包，公共契约只定义数据格式。
