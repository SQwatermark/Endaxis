# 模拟服务、输入排程与发布

应用层选择怎样运行一份场景、复用哪个前缀，以及什么时候把完整结果交给页面。它不拥有另一套战斗规则；主线程和 Worker 都调用同一场景编译、标准环境、战斗会话和结果投影。

## 实际生产调用链

```text
TimelineEditor 的项目联合仓库
  → AdaptiveTimelineSimulationService
    → WorkerScenarioSimulationService → scenarioSimulation.worker
    → 或拖动会话内的本地主线程服务
  → ScenarioSimulationService
    → 全量 / 增量前缀 / 继承前缀
  → 标准战斗会话与输入排程
  → 完整结果投影与发布
  → useScenarioSimulation 的版本检查
```

`core/pipeline/SimulationPipeline` 是另一个公开的通用阶段缓存工具，当前检索未见产品调用者，不能把它画成上述流程的实际协调器。正式工厂通过显式 GameDataRepository 装配常量与规则；页面联合仓库的已知全局效果缺口见[研究复现](../research/project-global-effect-reproduction.md)。

## 服务入口与寿命

`simulate(scenario, endFrame, signal)` 返回完整 run；`planSkillChain` 返回新场景建议和可能的 run，紧凑模式也可返回已规划前缀。规划不直接提交编辑历史，调用者需检查场景版本后作为一次编辑事务应用。

ScenarioSimulationService 绑定数据仓库和运行配置。继承方案优先走继承前缀；普通方案在启用 reuseCheckpoint、没有自定义随机样本端口且不是临时连续规划时才用增量路径，其余全量运行。三者都从正式战斗状态和历史收集结果，不把缓存当成最终事实。

本地主线程 simulate 虽返回 Promise，内部推进/投影是同步段，signal 主要在运行前后检查，不能保证帧内抢占。Worker 中已开始的计算通常也会跑完；取消消费结果不等于已经中断 CPU 工作。

## 排程与两个前缀缓存

`CombatInputSchedule` 拥有尚未提交的帧输入、连续组游标和自定义施放程序映射。它检查帧唯一有序、身份对应和当前会话 generation/帧边界；保存点组合战斗切面与排程进度。分叉可以替换未来输入，但不能重用历史 castId 或改写已经开始/停止的组定义。

增量路径只留一个候选前缀，按实际输入与构筑比较最早变化，保存点严格早于变化位置；已启动组的完整定义参与前缀键。快轴或过多回执不保留额外切面，编辑停止后定时释放。恢复/续跑失败清理相关缓存，不能拿旧候选冒充本次成功。

继承路径保留边界前的输入，边界帧及之后作为后缀；跨边界仍未全部提交的连续组明确拒绝。跨边界闪避标签只补尚未提交的后续事实，不重放历史 Dash。修改历史或改动运行环境使前缀失效；展示字段可以从键中剔除，disabled 等会影响执行的字段必须保留。

缓存键依赖服务所绑定的仓库版本不变。项目定义同 ID 内容变化时必须 clearCache/重建服务；不能只比较场景引用 ID。清理前缀不等于卸载浏览器 import 缓存，也不等于删除已发布结果。

## Worker 消息与失败边界

客户端只有一个 active 和一个最新 pending；新 pending 替代旧等待者，不无限堆积拖动中间位置。AbortSignal 结束等待者，active 的回复回来后才泵送后续请求。clearCache 换 revision 并拒绝等待者，旧在途回复不能成为新 revision 的结果；dispose 终止 Worker 并结算已知请求。

发送前复制纯对象以剥离 Vue 代理，保留 Infinity，拒绝函数、symbol 和非普通对象。定义选择集合或 revision 变化时重新发送小仓库，其余复用 Worker 内服务。协议去掉进程内回执视图，接收端重建连续历史与明确发布冻结，详见[结果边界](results.md)。

性能订阅者逐个隔离异常；结果解码失败也拒绝当前请求，并在 finally 中继续泵送。普通计算失败仍是错误结果，不因观察者出错改写为另一种计算状态。

当前 Worker 入口的数据仓库恢复/服务创建位于计算 try/catch 之前。非法数据包导致该初始化抛错时，入口本身未构造带请求 ID 的错误响应；[D14 复现与限制](../research/module-architecture-review.md#d14worker-启动失败的响应边界)记录了这一防御缺口。尚未证明正式捕获器能产生该非法包，也不能据此宣称真实页面已挂起。

## 自适应后端与页面发布

普通编辑走 Worker。开始一段拖动时，以最近完整运行耗时选择本地或 Worker，并保持该次交互选择；规划继续走 Worker。后端变化只改变执行位置，不能改变数据仓库或规则。

页面保留上一份完整结果，计算失败不发布半成品。同方案拖动期间允许先发布较旧落点的完整快照并标 stale；项目/方案切换、publicationEpoch 重置或更晚结果已发布后，旧任务不能覆盖。这是完整快照的单调发布策略，不是“只有最新请求才可发布”的简单规则。

验收要分别检查战斗状态/有序回执一致、缓存失效、队列结算、传输保护和页面版本策略。Worker 替身单测不替代真实浏览器线程崩溃/未处理拒绝验收，性能阈值也不是业务正确性依据。
