# 战斗运行时切面

运行时切面用于保存某一战斗帧已经发生的全部状态。恢复后可以从同一位置尝试不同输入，
不必重新执行此前所有帧。旧轴转换、技能拖动预览、连续组规划、输入窗口探测和随机分支分析
都应复用这一能力。

切面不是项目存档，也不是模拟结果。它只在当前进程中的同一场战斗实例上有效。

## 语义

一个帧切面只包含该帧结束前已经发生的事情：

- 当前战斗帧及各类局部时间；
- 资源、生命、失衡、Buff、状态、冷却、槽位和黑板；
- 正在执行的技能、动作序列、投射物、能力实体和定时对象；
- 已注册的事件响应、待处理请求和随机样本位置；
- 截止该帧已经生成的回执。

切面不能包含之后将要发生的技能块、外部事件或控制切换。恢复切面后，调用方再注入本次试探的
未来输入。静态游戏定义和编译程序可以共享，因为它们说明“什么能够发生”，不说明“之后会发生什么”。

恢复必须直接替换状态，不能通过重放回执、重新执行初始化动作或重新触发事件来逼近原状态。
同一切面可以反复恢复。一次试探抛错后也必须可以恢复。

## 接口边界

`RuntimeCheckpointController` 统一管理参与者。每个稳定状态所有者实现三个操作：

1. `captureCheckpointState` 返回与后续修改隔离的状态；
2. `validateCheckpointState` 在任何状态被修改前检查恢复条件；
3. `restoreCheckpointState` 完整替换自己拥有的状态。

控制器先校验所有参与者，再按注册顺序的反方向恢复。基础账本先注册，依赖它们的运行时后注册，
恢复时依赖方先撤销。第一次保存后不再允许注册新的顶层参与者。战斗中动态生成的 Buff、投射物和
能力实体由各自的稳定容器保存成员关系与成员状态，不能在生成时临时向控制器注册。

切面对象不公开内部状态，也不能跨战斗实例恢复。切面状态允许保存函数和对象身份，因此没有
序列化成本；参与者仍不得把之后会被原地修改的数组、Map 或可变对象直接交给切面。

## 运行时拆分

完整实现需要把装配输入分成两部分：

| 部分       | 内容                                               | 切面处理               |
| ---------- | -------------------------------------------------- | ---------------------- |
| 固定程序   | 干员定义、技能定义、装备效果、敌人定义、执行器工厂 | 所有分支共享，不复制   |
| 已发生状态 | 当前帧所有存活实例和账本                           | 保存并恢复             |
| 未来计划   | 技能块、外部事件、控制切换                         | 不进入切面，试探时注入 |

当前 `CombatInputRuntime` 在构造时接收整条轴，放置技能也在装配前生成独立 `SkillRuntime`。
这会让运行时提前知道未来。接入切面前需要改成可追加的未来输入队列，并让场景技能块在注入时
根据固定技能程序创建。定义内置技能仍可在开局创建，因为它们是能力目录，不代表未来输入。

## 完整性清单

以下所有状态必须接入后，`CombatRuntimeAssembly` 才能公开正式的保存和恢复入口：

| 所有者                              | 必须保存的内容                                             |
| ----------------------------------- | ---------------------------------------------------------- |
| CombatClock                         | 当前帧                                                     |
| CombatReceiptCollector              | 已提交回执边界                                             |
| CombatResources                     | SP、回能暂停、终结技能量和动态修正句柄                     |
| AbilitySystemRuntime / SkillRuntime | 当前技能、技能帧、动作序列、待施放请求、槽位和冷却         |
| Buff 和 Status 容器                 | 实例成员、层数、时长、黑板、属性修正和生命周期动作         |
| 事件中心                            | 注册顺序、启用状态、临时监听和正在处理的上下文栈           |
| TimeDilationRuntime                 | 全局及实体实例、曲线位置和结束条件                         |
| ComboWindowRuntime                  | 候选、暂停、剩余时间和消费状态                             |
| TimedMarker / GlobalCooldown        | 当前条目、到期时间和分配编号                               |
| LogicalAbilityEntityRuntime         | 实例、局部状态、子技能和实体黑板                           |
| ProjectileLifecycleRuntime          | 存活投射物、结束回调和本帧阶段状态                         |
| 伤害环境                            | 双方生命、失衡、附着、随机样本源和动态属性修改             |
| 输入队列                            | 只保存已经注入且尚未消费的当前分支输入，不保存其他未来方案 |

新增有状态运行时必须同时实现切面协议并加入完整性测试。只要清单中存在未接入项，装配层就不能
提供看似可用的残缺快照，也不能让旧轴转换依赖它。

## 性能目标

保存和恢复的成本应与当前存活状态量相关，与切面之前经过的帧数无关。静态程序保持共享；数组和
映射按所有权复制，后续可以对回执和大型只读前缀使用分块共享。第一目标是消除试探时的历史重放，
使顺序处理 N 个技能从累计重放接近 `O(N²)` 降到一次前进加各分支自身长度。

旧轴转换接入时，每确定一个技能就推进到下一个候选帧并保存切面。窗口探测从同一切面恢复后注入
一个候选技能，只执行候选后的短区间。选中最早合法位置后提交该分支，再继续生成下一切面。
