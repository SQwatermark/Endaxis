# 项目模板与编辑器

编辑器修改用户文档，编译器和模拟器解释它。允许编辑不等于保证输入可模拟；
引用失配应在使用位置报告，不暗中删除技能、改帧或替换定义。

## 模板、实例和单次覆盖

内置定义只读。项目级干员、武器、装备和套装模板使用同一套公共类型，完整保存于项目定义库。
从已有模板派生是一次完整复制，`origin` 仅记录来源，不参与运行时继承或隐式合并。
轨道保存模板引用和自己的养成实例；多个轨道引用同一项目模板时，共享定义但不共享运行状态。

记录key、模板ID与定义身份需要一致；展示资源身份单独保存。
复制或导入出现冲突时要明确分配身份并重写相关引用，不能覆盖另一份定义。
删除被引用内容应处理引用保护，不能留下隐蔽失配。
当前字段以 [项目格式](../../src/core/project/schema.ts) 为准。

整份方案复制时只生成新的方案 ID，内部内容深拷贝，轨道、技能块、连线等 ID 和引用全部保留。
内部对象在各自方案内查找；跨方案引用必须同时指定方案 ID 和对象 ID。副本可以独立编辑，
干员、武器和装备仍引用同一项目定义库。向方案内粘贴技能时则需要分配新 ID，并改写相关引用，
避免与目标方案已有技能冲突。切换方案显式清空选择和临时交互状态，不靠更换内部 ID 间接清理。

模板编辑修改整个定义，技能块编辑只修改该次释放的完整覆盖。
两处可以复用表单，但不能产生隐藏的双向绑定。详情见 [技能](skills.md) 和 [装备](equipment.md)。

随机模式、全局种子属于场景计算输入。技能块独立种子和单次命中覆盖属于该次释放的模拟输入，
放在技能详情中。它们都随项目保存并参与模拟缓存身份；切换模式、重掷种子和修改覆盖各产生一次撤销。
随机策略和各类随机行为的处理规则见 [伤害与状态](damage-and-state.md#期望计算与随机模拟)。

## 草稿、页面和历史

同一根定义的编辑共享草稿、历史和保存范围。技能、Buff、能力实体是平级定义对象，
从引用跳转应切换详情，而不是复制一份可写对象或把引用关系画成所有权。
概览、对象列表和定义详情分别承担基础配置、查找管理、结构编辑的任务。
返回与面包屑表达真实归属；浏览和选择不创建撤销事务。

图显示流程、条件和对象关系，Inspector编辑所选对象的值。
图编辑器的调用方提供与文档类型匹配的投影函数，包装字段通过读写适配器转换，
不能把界面包装层写进用户文档。

编辑提交由 [场景会话](../../src/application/editor/scenarioEditorSession.ts) 等应用层入口组织。
一次完成的操作对应一次撤销，取消、失焦和异步失败不能留下半次修改。
整组技能放置读取定义配置与输入路由，不在界面按干员名称写专用链。

## 输入区域与手势

[快捷键路由](../../src/ui/keyboard/keyboardShortcutRouter.ts) 管理逻辑区域与输入归属。
弹窗阻隔背景命令，子区域关闭后恢复父区域；Teleport改变DOM位置，不改变逻辑归属。
文本输入优先保留原生编辑行为。按住键的状态与一次性命令分开处理，失焦或区域改变时清除按住状态。

[手势会话](../../src/ui/interaction/interactionSession.ts) 区分所有者和会话身份。
只有当前持有者能够更新、提交或取消；旧清理回调不能结束后来启动的手势。
指针拖动、原生拖放和点击后跟随放置有不同结束策略，不能因外观相似就混用事件语义。
无效悬停不自动提交，Escape、pointercancel、失焦和卸载都需要明确取消路径。

图层只控制显示和命中，不能替代目标合法性或输入归属。
拖动预览不抢指针；工具栏、快捷键与菜单调用同一个编辑命令。

## 手动连续组

多选同一轨上相邻的至少两个技能，右键选择“设为连续组”。创建时去掉选中技能之间的空隙，
后段改为接续关系；以后前段受时间膨胀影响变长或变短，后段自动跟随。独立技能仍保持原来的固定时间。
若选区涉及已有组，要选全这些组；不能遗漏中间技能或包含锁定成员。组不能嵌套。

从技能库放下完整普攻或强化普攻序列时，编辑器先按正式模拟确定本次实际生成的段数和起点，
再把这些新技能按放置顺序连成一组。这是固定行为，不设关闭开关；只放下单段普攻不建组。

组上方用细线和“连续 · 数量”标记，点击标记选中全组，点击成员仍只查看该技能。
拖动任意成员、键盘微移或对齐都会移动整组，只修改组首时间；包含锁定成员时整组不移动。
锁定只阻止用户移动，不冻结由模拟决定的接续时间。后段的属性面板显示接续说明和位置，
不提供一个无效的独立开始时间输入框。

右键“解散连续组”把涉及组的各成员固定到当前显示位置。创建、解散、移动、删除和粘贴
各自只产生一次撤销记录，后台重算不产生编辑历史，也不修改存档。

- 删除中间成员会连接剩余的前后成员；删除组首后，新的首项继承原组首的开始时间。
- 复制完整组保留关系；复制部分成员时，每段缺少前驱的首项固定为复制时的位置。
  粘贴重新分配技能身份并改写接续引用，原有技能连线继续按两端是否都复制来处理。
- 暂不提供组内独立拖动、拖动重排或间隔配置；需要改变内部次序时，先解散、调整再建组。
- “紧凑排列”仍是一次性的固定排程整理，选择涉及连续组时需先解散。Ctrl+G 仍切换辅助线。

接续边界、禁用成员和冲突处理见 [时间与显示](time-and-display.md#手动连续组如何接续)。

## Buff 布局

“显示”菜单提供“紧凑”和“松散”两种 Buff 布局。紧凑模式让四条干员轨道按用户设置的比例
恰好填满顶部标尺与底部状态区之间的轨道区域，不产生纵向滚动。Buff 行过多时只显示轨道边界内的部分；可以拖动轨道间的分隔线调整可见空间，
双击分隔线恢复等高。松散模式按每条轨道当前的 Buff 行数自动增高并允许纵向滚动，保证全部 Buff
可见，此时轨道高度由内容决定，不能手动拖动分隔线。切回紧凑模式后继续使用先前保存的高度比例。

两种模式只改变显示空间，不改变 Buff 的合并、层数、持续时间和模拟结果。同一侧的 Buff 都会复用
时间上不重叠的显示行；紧凑模式的“紧凑”不是把不同 Buff 合并为一个状态。Buff 效果条处在
技能块绘制层的后面，空间不足而挤入技能区域时由技能块遮住，不允许效果条盖住技能块。

“辅助线”沿鼠标所在时间贯穿轨道区，显示时间、技力、失衡值、各干员终结技能量、敌人生命和
当前敌人 Buff。敌人 Buff 最多显示十个，图标右下角显示层数，剩余数量用 `+N` 表示。松散布局
纵向滚动时，读数固定在标尺下方 4px；框选期间隐藏辅助线。开关由 `Ctrl+G` 或“显示”菜单控制，
并保存在本机显示偏好中。

## 伤害分析

伤害分析复用旧版的三栏环形图、汇总卡和常见问题布局。按干员与按伤害类型统计只读取同一次
正式模拟发布的 `DamageApplied` 回执，颜色来自该次发布冻结的干员元素和伤害类型。
准备阶段以前的伤害不计入循环，循环时间从统计起点算到最后一次有效伤害。

外部 Buff 提供者的贡献分摊尚无稳定回执事实，因此中间卡片保留旧版位置并明确显示暂不可用，
不复制旧版的推测算法或提供无效切换按钮。

## 项目与图片导出

普通时间轴页面每次提交项目修改后，将完整项目自动保存到浏览器 IndexedDB；刷新时先读取、校验，
再按该项目实际引用加载游戏定义。临时旧轴预览页面不写入这份本地项目。
自动保存完成后刷新不再弹出“修改可能丢失”的提示；保存尚未完成或失败时继续阻止误刷新，
失败原因会在界面显示。“未导出修改”只表示尚未下载 JSON 文件，不表示浏览器自动保存失败。

工具栏的“导出”打开统一设置面板。文件名同时用于项目文件和图片；导出时长只限制图片内容，
不会修改方案或模拟时长。面板提供四种输出：

- “导出 JSON”保存完整项目，可重新导入继续编辑。
- “复制数据码”把同一份项目压缩为适合分享的文本并写入剪贴板。
- “导出小图”打开独立预览，可以调整明暗、整图宽度、轨道高度、技能块高度和可见信息。
  小图把所选时长完整排入设定宽度，适合直接分享。
- “导出长图”按实际时间比例临时展开当前时间轴工作区，截取指定时长后恢复原尺寸和滚动位置。

图片统一保存为 PNG，并用旧版相同的 `tEXt/EndaxisData` 文本块保存项目数据码，打开图片时走统一
项目打开流程。元数据写入失败视为导出失败，避免下载无法恢复项目的图片。
图片捕获只读取当前已经发布的编辑器画面和投影，不触发模拟，也不把临时展开
写回项目。捕获失败时仍须恢复界面，不能让导出改变用户正在编辑的位置。

## 语言、主题与性能

界面文本与游戏内容文本分别组织，按需要加载。语言切换在所需资源准备完成后生效，
较慢的旧请求不能覆盖新的选择；加载失败不冒充缺失翻译。
自定义名称属于用户内容，固定界面文案才进入界面翻译。

组件使用语义主题变量，主题不改变战斗规则。用户保存的自定义颜色属于项目展示属性，
不能与界面主题混为一谈。语言和主题切换不创建编辑历史或重跑战斗。

模拟服务使用同一套正式模拟器，并根据最近三次完整模拟的耗时选择拖动时的执行位置。
最慢一次不超过33毫秒时，整次拖动在主线程同步计算，让技能块和投影在同一次绘制前更新；
没有耗时样本或最慢一次超过33毫秒时，整次拖动交给Worker。执行位置只在拖动开始时选择，
拖动中不切换，也不靠平移旧投影伪造实时结果。普通编辑仍交给Worker。

状态只属于该次模拟。缓存覆盖输入和规则版本、保持容量上限，取消或失败结果不进入有效缓存。
已经开始的计算允许完成，尚未开始的请求合并为最新一次；旧结果不能覆盖更新的编辑。
实际性能和交互验收方法见 [验证指南](../development/validation.md)。
