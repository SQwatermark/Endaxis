# Endaxis Next 时间轴 UI 兼容迁移计划

## 1. 目标与边界

本文对照以下旧版只读实现与当前 Next 时间轴样机：

- `src/views/TimelineEditor.vue`
- `src/components/ActionLibrary.vue`
- `src/components/TimelineGrid.vue`
- `src/components/ActionItem.vue`
- `src/ui/timeline/TimelineEditor.vue`

迁移目标是让 Next 在用户可观察的布局、尺寸、视觉层级、图标和编辑交互上达到旧版 1:1 兼容，同时保持 Next 的项目、目录、编译、运行时和投影边界。旧版 UI 是表现与交互基准，不是新版数据架构的依赖。

**明确禁止抽取或共享旧组件。** Next 不得导入上述旧 `.vue` 文件、旧 Store、旧 composable 或旧组件内部工具。允许复用的是稳定静态资源、全局主题 token、通用无状态图标资源和经过明确边界封装的领域无关基础设施；具体 UI 必须在 `src` 内重新实现，并只消费 Next view model 与 command。

## 2. 当前差距摘要

当前 `TimelineEditor.vue` 是功能样机，不是旧版工作台的视觉迁移：

| 区域     | 旧版                                                            | 当前 Next                            |
| -------- | --------------------------------------------------------------- | ------------------------------------ |
| 页面骨架 | 七列工作台：左右 48px 活动栏、左右面板、分隔器和中央工作区      | 50px 顶栏 + 280px 技能侧栏 + 时间轴  |
| 顶栏     | 方案管理、方案标签、分析、导出、更多菜单                        | 固定标题、待实现模拟、重置、返回旧版 |
| 左侧     | 活动栏 + 可折叠/缩放技能库 + 下方工具面板                       | 固定技能侧栏                         |
| 右侧     | 属性检查器/战斗日志活动栏与可折叠面板                           | 无                                   |
| 时间轴   | 双行标尺、准备区、操作按键层、轨道头、资源/装备、效果层和连接层 | 简单秒标尺、光标、轨道身份和技能块   |
| 动作块   | 命中点、冷却/持续条、警告、锁定、连线端口、禁用/幽灵状态        | 仅类型配色和名称                     |
| 编辑能力 | 拖放、移动、多选、框选、吸附、缩放、平移、右键、轨道排序/缩放   | 点击技能库放置、点击轨道定位         |
| 响应式   | 桌面工作台为主，面板尺寸可持久化                                | 小于 800px 时侧栏缩为 220px          |

Next 当前存在的 `engine-badge`、“返回当前版本”和样机专用按钮不是兼容目标；入口切换阶段可由开发路由外壳提供，正式编辑器 DOM 不保留这些元素。

## 3. 兼容原则

### 3.1 必须 1:1 的内容

- 首屏区域占比、固定尺寸、最小尺寸、面板折叠和拖动反馈；
- DOM 的主要层级与叠放关系，尤其是标尺、轨道头、滚动视口和覆盖层；
- 技能库卡片、轨道、动作块、警告、命中标记、持续条和按键标记的外观；
- 已存在且仍有产品价值的鼠标、键盘、拖放、缩放、滚动和上下文菜单交互；
- 旧版使用的游戏图标资源和现有 Endaxis 语义 token；
- 深色/浅色主题下的可读性和 hover/active/disabled/selected 状态。

### 3.2 允许因底层数据不同而变化的内容

- Next 以整数帧保存和计算时间；旧版以秒为主的显示值可以保持一致，但定位和宽度由帧换算得出；
- 技能库来源是 Next `SkillGroupDefinition` 与编译后的 view model，不复制旧 `activeSkillLibrary`；
- 普攻链和多段技能按 Next 技能组投影为一张主卡及若干段按钮，DOM 形状兼容，但身份和放置 command 使用 Next key；
- 动作块只从稳定来源身份、本次项目输入和投影读取名称、类型及状态，不读取或持久化翻译文本；
- Next 尚未产出某类 receipt/projection 时，对应效果层可以暂不显示，但应保留独立组件插槽和 DOM 层级；不得用假数据模拟“已完成”；
- 旧版的 `triggerWindow`、派生冷却条或警告只有在 Next 有对应稳定投影后才接入。不存在于新领域模型中的旧派生字段不进入项目存档；
- 旧版 Store 直接修改操作必须改成 Next command。用户结果应兼容，调用路径不要求一致；
- 旧版导出过程依赖具体 DOM 查询。Next 应提供明确导出边界或 ref，不要求沿用旧 class 作为程序接口。

允许差异必须能够解释为数据所有权或尚未完成的投影能力，不能用来合理化间距、颜色、字体、图标或交互反馈偏差。

- [x] 位置、宽度和高度完全来自 Next 布局投影；组件不自行读取项目并计算时间。
- [x] 基础动作 lane 高 50px，动作块固定高 50px；文字和角标使用独立覆盖层，不改变几何。
- [x] 普通动作使用类型色 2px 虚线；连携和终结技使用 1.5px 实线、2px 圆角。
- [x] 普攻保留其独立细实线规则；禁用动作使用灰色斜纹、0.6 opacity。
- [x] 选中动作提升 z-index、显示选中虚线和 glow；普通块以同轨文档顺序形成稳定层级，选中与拖动分别进入独立高层，同起点不会因响应式重算随机翻转。

使用 `--ea-action-fg`、`--ea-action-fg-shadow`、技能类型色和主题语义填充。禁止把当前 Next 的 `#402427`、`#3b351b` 等临时色继续散落在组件选择器中；应由动作 paint view model 或主题 token 统一提供。

### 7.2 装饰与状态

- [x] 命中点位于动作底边：基础 6x6px 菱形，强制暴击使用独立描边和辉光；其余命中状态只读取已有投影字段，不从颜色猜测机制。

- [x] 旧版“动画阶段”覆盖层在 Next 按局部对象时间膨胀语义改造：只把运行时回执确认、归属于来源技能且落在动作实际宽度内的区间画为块内裁剪层与 shimmer，不移动后续动作、不另改块宽；减少动画偏好下停止流动。

- [x] 连接端口只在连接工具开启、hover/选中或正在连线时显示；拖拽来源不重复显示端口，重复有向目标降低透明度并禁用交互，最终文档 command 使用同一纯判定再次拒绝自连、悬空引用和重复连接。

### 7.3 数据允许差异

- Next 不保存 `action.name` 的已翻译文本，动作标签在 view model 中由 `source` 身份解析。
- Next 的动作块时长使用 `timelineBlockFrames`，不读取旧 `duration` 或 `animationTime`。
- 冷却、强化、命中、警告和连携窗口都必须来自独立 projection；不存在投影时隐藏对应 DOM，不在组件里重新模拟。
- Next 连接端点只为领域模型允许连接的命中或动作身份生成，不照搬旧版匿名/派生 ID。

## 9. 分阶段实施顺序

### 阶段一：静态工作台壳层

1. 在 `src` 重建七列工作台、活动栏、顶栏和三向可缩放面板；
2. 接入现有主题 token、图标资源和空内容插槽；
3. 移除正式 DOM 中的样机 `NEXT` badge 和返回旧版按钮；
4. 不改时间轴数据操作，只完成桌面首屏 1:1。

验收重点：整体分区、50px 顶栏、48px 活动栏、面板默认/最小尺寸和折叠行为。

### 阶段二：技能库

1. 重建旧版技能库 DOM 和 CSS；
2. 将 Next 技能组 view model 映射为主卡与分段按钮；
3. 接入点击放置，再接原生拖放和放置预览；
4. 最后接干员、武器、装备编辑入口。

验收重点：卡片尺寸、密度、类型色、图标、长名称省略和多段技能布局。技能类型是玩家排轴时的主识别，
使用更大的主标签；技能专名仅作次级确认，两者相同时不重复显示。

### 阶段三：时间轴静态骨架

1. 重建 180px 轨道头、双行标尺、50px lane 和独立滚动结构；
2. 建立统一帧到像素 layout projection；
3. 接轨道头像、名称、武器装备和动作块基础外观；
4. 接准备区、战斗边界和操作按键层。

验收重点：标尺与动作 x 坐标一致、左右行高一致、长轴滚动无漂移。

### 阶段四：选择与编辑手势

1. 单选、Ctrl 多选和两类框选；
2. 动作拖动、吸附、边缘自动滚动和右键菜单；
3. 中键空白平移、滚轮规则和缩放；
4. 轨道排序、轨道高度调整、模拟边界拖动；
5. 统一快捷键 focus scope。

验收重点：手势互斥、无事件穿透、历史记录每个 command 只提交一次。

### 阶段五：投影装饰层

1. 命中点和伤害明细；
2. 冷却、持续时间、连携窗口和技能警告；
3. 上下 Buff/效果、资源曲线、切人标记和冻结区域；
4. 连接线与连接工具；
5. 属性检查器、战斗日志和底部资源面板。

每个装饰层必须等对应 Next receipt/projection 稳定后接入，不得在 Vue 中移植旧模拟逻辑。

### 阶段六：导入、导出与辅助功能

1. 方案管理、项目加载/接收、重置和快捷键帮助；
2. JSON/分享导出；
3. 长图导出使用明确 capture root 和完整内容尺寸；
4. 分析弹窗与多语言/主题设置。

## 11. 完成定义

7. 没有为了兼容视觉而把旧派生字段加入 Next 存档；
8. 没有抽取、包装或共享旧版业务组件。
