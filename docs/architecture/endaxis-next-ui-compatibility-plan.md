# Endaxis Next 时间轴 UI 兼容迁移计划

## 1. 目标与边界

本文对照以下旧版只读实现与当前 Next 时间轴样机：

- `src/views/TimelineEditor.vue`
- `src/components/ActionLibrary.vue`
- `src/components/TimelineGrid.vue`
- `src/components/ActionItem.vue`
- `src/next/ui/timeline/NextTimelineEditor.vue`

迁移目标是让 Next 在用户可观察的布局、尺寸、视觉层级、图标和编辑交互上达到旧版 1:1 兼容，同时保持 Next 的项目、目录、编译、运行时和投影边界。旧版 UI 是表现与交互基准，不是新版数据架构的依赖。

**明确禁止抽取或共享旧组件。** Next 不得导入上述旧 `.vue` 文件、旧 Store、旧 composable 或旧组件内部工具。允许复用的是稳定静态资源、全局主题 token、通用无状态图标资源和经过明确边界封装的领域无关基础设施；具体 UI 必须在 `src/next` 内重新实现，并只消费 Next view model 与 command。

## 2. 当前差距摘要

当前 `NextTimelineEditor.vue` 是功能样机，不是旧版工作台的视觉迁移：

| 区域     | 旧版                                                            | 当前 Next                            |
| -------- | --------------------------------------------------------------- | ------------------------------------ |
| 页面骨架 | 七列工作台：左右 48px 活动栏、左右面板、分隔器和中央工作区      | 50px 顶栏 + 280px 技能侧栏 + 时间轴  |
| 顶栏     | 方案管理、方案标签、分析、导出、更多菜单                        | 固定标题、待实现模拟、重置、返回旧版 |
| 左侧     | 活动栏 + 可折叠/缩放技能库 + 下方工具面板                       | 固定技能侧栏                         |
| 右侧     | 属性检查器/战斗日志活动栏与可折叠面板                           | 无                                   |
| 时间轴   | 双行标尺、准备区、操作按键层、轨道头、资源/装备、效果层和连接层 | 简单秒标尺、光标、轨道身份和技能块   |
| 动作块   | 命中点、冷却/持续条、警告、锁定、连线端口、禁用/幽灵状态        | 仅类型配色和名称                     |
| 编辑能力 | 拖放、移动、多选、框选、吸附、缩放、平移、右键、轨道排序/缩放   | 点击技能库放置、点击轨道定位         |
| 响应式   | 桌面工作台为主，面板尺寸可持久化                                | 小于 800px 时侧栏缩为 220px          |

Next 当前存在的 `engine-badge`、“返回当前版本”和样机专用按钮不是兼容目标；入口切换阶段可由开发路由外壳提供，正式编辑器 DOM 不保留这些元素。

## 3. 兼容原则

### 3.1 必须 1:1 的内容

- 首屏区域占比、固定尺寸、最小尺寸、面板折叠和拖动反馈；
- DOM 的主要层级与叠放关系，尤其是标尺、轨道头、滚动视口和覆盖层；
- 技能库卡片、轨道、动作块、警告、命中标记、持续条和按键标记的外观；
- 已存在且仍有产品价值的鼠标、键盘、拖放、缩放、滚动和上下文菜单交互；
- 旧版使用的游戏图标资源和现有 Endaxis 语义 token；
- 深色/浅色主题下的可读性和 hover/active/disabled/selected 状态。

### 3.2 允许因底层数据不同而变化的内容

- Next 以整数帧保存和计算时间；旧版以秒为主的显示值可以保持一致，但定位和宽度由帧换算得出；
- 技能库来源是 Next `SkillGroupDefinition` 与编译后的 view model，不复制旧 `activeSkillLibrary`；
- 普攻链和多段技能按 Next 技能组投影为一张主卡及若干段按钮，DOM 形状兼容，但身份和放置 command 使用 Next key；
- 动作块只从稳定来源身份、本次项目输入和投影读取名称、类型及状态，不读取或持久化翻译文本；
- Next 尚未产出某类 receipt/projection 时，对应效果层可以暂不显示，但应保留独立组件插槽和 DOM 层级；不得用假数据模拟“已完成”；
- 旧版的 `triggerWindow`、派生冷却条或警告只有在 Next 有对应稳定投影后才接入。不存在于新领域模型中的旧派生字段不进入项目存档；
- 旧版 Store 直接修改操作必须改成 Next command。用户结果应兼容，调用路径不要求一致；
- 旧版导出过程依赖具体 DOM 查询。Next 应提供明确导出边界或 ref，不要求沿用旧 class 作为程序接口。

允许差异必须能够解释为数据所有权或尚未完成的投影能力，不能用来合理化间距、颜色、字体、图标或交互反馈偏差。

## 4. 页面工作台清单

### 4.1 根布局

- [ ] 根节点占满 `100vw x 100vh`，内部不得产生页面级滚动。
- [ ] 使用旧版七列结构：`48px / 左面板 / 1px / minmax(540px, 1fr) / 1px / 右面板 / 48px`。
- [ ] 左面板默认 200px，最小 200px；右面板默认 260px，最小 260px；二者最大 480px。
- [ ] 中央时间轴最小宽度 540px，主工作区最小高度 600px。
- [ ] 底部面板默认 240px、最小 240px，分隔器 1px；资源区折叠时按旧规则降低有效最小高度。
- [ ] 左、右、底面板支持拖动缩放、双击恢复默认值、折叠和本地布局持久化。
- [ ] 面板缩放期间使用全局 `user-select: none` 与对应 `ew-resize`/`ns-resize` 光标。
- [ ] 中央内容使用 `overflow: hidden`，时间轴自己的横纵滚动器独立管理。

必须沿用或映射以下语义 token：

`--ea-workbench`、`--ea-workbench-main`、`--ea-workbench-panel`、`--ea-workbench-header`、`--ea-activity-bg`、`--ea-border`、`--ea-border-soft`、`--ea-border-strong`、`--ea-active-fill`、`--ea-hover-fill`、`--ea-panel-chrome-bg`、`--ea-panel-chrome-bg-hover`、`--ea-shadow`。

### 4.2 左右活动栏

- [ ] 左右活动栏固定宽 48px，使用上下分组；按钮占满栏宽并保持稳定点击区域。
- [ ] 当前工具使用侧边强调线和 active 状态；hover 保留轻微上移、缩放和阴影反馈。
- [ ] 左栏顶部使用 `/icons/btn_character.webp` 作为技能库图标。
- [ ] 左栏底部保留全局设置 `/icons/setting_tab_setting.webp`、危机合约 `/contingency_contract/deco_contract_028.webp` 和敌人/资源面板图标。
- [ ] 右栏保留属性检查器和战斗日志入口，使用旧版同一静态图标资源。
- [ ] 图标常规尺寸 24px；通用图片图标基线 28px，根据具体按钮覆写为 24px。
- [ ] 图片图标使用 `object-fit: contain`；浅色主题使用已有 brightness/opacity 规则转为深色轮廓。
- [ ] 工具提示来自 i18n，活动栏按钮必须有 `aria-label`，装饰图片使用空 `alt`。
- [ ] 点击当前活动工具再次折叠对应面板；点击另一工具先切换内容再确保面板展开。

### 4.3 顶栏与方案管理

- [ ] 顶栏固定 50px，使用 `--ea-workbench-header` 和底部 `--ea-border-soft`。
- [ ] 左侧方案区高度 36px，标题组固定约 260px，剩余空间用于可横向滚动的方案标签。
- [ ] 保留重命名、复制、删除三个 24px 图标按钮；只有多个方案时显示删除。
- [ ] 标题使用方括号装饰，双击文本或点击编辑图标进入原位输入；输入宽 120px。
- [ ] 方案标签最小宽 40px、高 24px，使用两位编号；活动项使用 `--ea-tab-active-bg/fg`。
- [ ] 标签组无可见滚动条，并按两端滚动状态显示 20px 渐隐遮罩。
- [ ] 保留新增方案按钮与方案数量限制反馈。
- [ ] 右侧保留分析、导出和更多菜单；图标、文字、按钮高度与旧版 `ea-btn--sm` 一致。
- [ ] 更多菜单按“视图、项目、语言/外观”等旧区域组织，不把设置散回顶栏。
- [ ] 顶栏空白点击取消轨道选择；控件自身阻止该事件穿透。

Next 的方案创建、复制、删除和重命名必须调用项目 command/history，而不是直接修改 `ScenarioDocument`。旧版菜单中某项功能尚未迁移时，保持布局位置并使用明确 disabled 状态；不要删除后造成顶栏重排。

### 4.4 左、右、底工具面板

- [ ] 左面板内部保持“技能库主区 / 1px 分隔 / 与底部同高的敌人或全局侧区”结构。
- [ ] 底部中央面板与左下侧区共用高度，切换敌人、全局设置、活动机制时不改变工作台网格。
- [ ] 右面板在属性检查器和战斗日志之间切换；折叠后中央区占用释放出来的宽度。
- [ ] 面板 body 统一 `min-width: 0; min-height: 0; overflow: hidden`。
- [ ] 面板重置/折叠 chrome 位于右上，默认低透明度，面板 hover 或 focus-within 时完整显示。
- [ ] 底部资源监视器、属性检查器和日志的数据必须来自 Next projection/receipt；没有数据时使用空状态，不查询旧 Store。

- [ ] 保留准备区背景、战斗开始线、战斗结束线、拖动把手和原位数值编辑。

- [ ] 标尺刻度和标签由整数帧投影，不积累浮点偏移。

- [ ] 头像 44x44px、圆形、2px 边框；空轨使用虚线占位。
- [ ] 点击头像更换干员；空轨点击信息区也打开干员选择。
- [ ] 显示干员名称、形态 badge、属性详情入口和初始能量输入。
- [ ] 武器缩略图 32x32px；四件装备缩略图 22x22px；空槽使用虚线框和加号。
- [ ] 武器/装备点击打开对应 Next 选择或编辑流程。
- [ ] 套装生效提示位于装备行下方，高 22px，颜色沿用青绿色语义。
- [ ] 支持轨道拖动排序、上下按钮排序和 Tab/Shift+Tab 切换；空轨按既有规则跳过。

### 6.5 轨道内容层级

每轨至少预留以下独立层，不能把所有视觉内容塞进动作块：

1. 上方干员/装备效果层；
2. 50px 动作 lane；
3. 能力值或资源覆盖层；
4. 动作块容器；
5. 连携窗口层；
6. 切人标记层；
7. 下方 Buff 层；
8. 跨轨连接 SVG；
9. 全局冻结覆盖层。

- [ ] 视图菜单能按层和按干员隐藏效果，不改变模拟结果。
- [ ] 松散/紧凑效果布局只改变投影布局，不修改 receipt 或项目。
- [ ] 光标辅助线显示时间、技力、失衡、干员能量和敌方生命；数据缺失的行不显示。
- [ ] 光标线 1px，使用金色和轻微 glow；tooltip/读数不被滚动容器裁剪。
- [ ] 框选框使用四边虚线背景，不填充遮挡动作块。

### 6.6 网格交互

- [ ] 滚轮纵向滚动；Shift+滚轮横向平移；Ctrl+滚轮缩放。
- [ ] 鼠标中键仅在时间轴空白区域启动横纵平移，交互控件不穿透。
- [ ] 普通左键空白取消选择；放置模式下左键在当前活动轨道放置。
- [ ] Ctrl+点击动作执行多选中的选中/取消选中；Ctrl+空白拖拽对框内动作执行同样的批量切换。
- [ ] 工具栏框选采用普通替换选择；修饰键框选采用批量切换，二者反馈一致但语义分开。
- [ ] 动作拖动超过 5px 阈值后才进入移动；支持边缘自动滚动。
- [ ] Alt+点击动作边缘执行旧版边缘吸附/对齐，Shift 修饰维持旧语义。
- [ ] 右键动作打开动作菜单；右键空白打开对应时间点菜单。
- [ ] 锁定动作可选中但不可移动，并显示短提示。
- [ ] 轨道、循环线、模拟起止线、切人标记各自具有独立选择身份，互斥规则由 Next selection model 管理。
- [ ] 全局快捷键必须经过统一 focus/scope 管理；弹窗、输入、菜单或可编辑元素获得焦点时不得穿透到时间轴。

## 7. 动作块清单

### 7.1 DOM 与基础外观

Next 应新增自己的动作块组件，保持以下层级能力：

```text
action-item-wrapper
  cooldown / duration / trigger-window bars
  damage-ticks-layer
  status icons
  action-item-content
    animation-phase-overlay
  link ports
```

- [ ] 位置、宽度和高度完全来自 Next 布局投影；组件不自行读取项目并计算时间。
- [ ] 基础 lane 高 50px，动作块高度由布局投影稳定给出；不得因文字或角标改变尺寸。
- [ ] 普通动作使用类型色 2px 虚线；连携和终结技使用 1.5px 实线、2px 圆角。
- [ ] 普攻保留其独立边框规则；禁用动作使用灰色斜纹、0.6 opacity。
- [ ] 选中动作提升 z-index、显示选中虚线和 glow；同起点动作的层级保持确定性。
- [ ] 标签居中、加粗、单行，不溢出；名称变体、连携段号和普攻段号由 view model 提供显示片段。
- [ ] hover 亮度反馈在浅色主题下减弱，避免白底过曝。
- [ ] 终结技左右各保留 4px 类型色竖条。

使用 `--ea-action-fg`、`--ea-action-fg-shadow`、技能类型色和主题语义填充。禁止把当前 Next 的 `#402427`、`#3b351b` 等临时色继续散落在组件选择器中；应由动作 paint view model 或主题 token 统一提供。

### 7.2 装饰与状态

- [ ] 命中点位于动作底边：基础 6x6px 菱形，命中触发、连携增益、强制暴击分别有明确状态色。
- [ ] 命中点可点击打开伤害明细，但整个命中层除点位外不拦截鼠标。
- [ ] 锁定图标左上、禁用图标右上、合法性警告右上；图标约 12px。
- [ ] 警告 tooltip 使用现有深色 tooltip 风格，最大宽度 `min(320px, 100vw - 48px)`。
- [ ] 冷却、强化持续时间、自定义持续条和连携窗口使用独立 2px 线条、端点和 10px 标签。
- [ ] 动画不可中断阶段使用动作内部覆盖层及 shimmer，不改变动作整体宽度。
- [ ] 完美连携动作保留外框和脉冲效果。
- [ ] 连接端口只在连接工具开启、hover/选中或正在连线时显示；非法目标降低透明度并拒绝 drop。

### 7.3 数据允许差异

- Next 不保存 `action.name` 的已翻译文本，动作标签在 view model 中由 `source` 身份解析。
- Next 的动作块时长使用 `timelineBlockFrames`，不读取旧 `duration` 或 `animationTime`。
- 冷却、强化、命中、警告和连携窗口都必须来自独立 projection；不存在投影时隐藏对应 DOM，不在组件里重新模拟。
- Next 连接端点只为领域模型允许连接的命中或动作身份生成，不照搬旧版匿名/派生 ID。

## 8. 组件拆分建议

以下是 Next 内部的建议边界，不是对旧组件的共享或包装：

```text
src/next/ui/timeline/
  NextTimelineEditor.vue          工作台装配与焦点作用域
  TimelineWorkbenchShell.vue      七列布局、活动栏、面板缩放
  TimelineHeader.vue              方案和顶栏命令
  SkillLibraryPanel.vue           技能库与构筑编辑入口
  TimelineGrid.vue                网格滚动与层级装配
  TimelineRuler.vue               标尺、准备区和操作键
  TimelineTrackHeader.vue         干员、装备和轨道控制
  TimelineTrackLane.vue           单轨各投影层装配
  TimelineActionBlock.vue         动作块纯展示与局部手势
  TimelineSelectionOverlay.vue    框选、吸附和选择反馈
  TimelineContextMenu.vue         Next command 菜单
```

约束：

- 页面组件只编排 view model 和 command，不读取 core runtime 对象；
- 像素位置、行高、装饰条和层级由 timeline layout projection 统一产生；
- 鼠标手势集中到时间轴交互 controller，避免每个视觉层各挂一套 window listener；
- 主题颜色来自 token/paint model；i18n 只在最终渲染层调用；
- 与旧版相同的 class 名可以用于视觉对照，但不能成为跨版本共享逻辑的隐式接口。

## 9. 分阶段实施顺序

### 阶段一：静态工作台壳层

1. 在 `src/next` 重建七列工作台、活动栏、顶栏和三向可缩放面板；
2. 接入现有主题 token、图标资源和空内容插槽；
3. 移除正式 DOM 中的样机 `NEXT` badge 和返回旧版按钮；
4. 不改时间轴数据操作，只完成桌面首屏 1:1。

验收重点：整体分区、50px 顶栏、48px 活动栏、面板默认/最小尺寸和折叠行为。

### 阶段二：技能库

1. 重建旧版技能库 DOM 和 CSS；
2. 将 Next 技能组 view model 映射为主卡与分段按钮；
3. 接入点击放置，再接原生拖放和放置预览；
4. 最后接干员、武器、装备编辑入口。

验收重点：卡片尺寸、密度、类型色、图标、长名称省略和多段技能布局。

### 阶段三：时间轴静态骨架

1. 重建 180px 轨道头、双行标尺、50px lane 和独立滚动结构；
2. 建立统一帧到像素 layout projection；
3. 接轨道头像、名称、武器装备和动作块基础外观；
4. 接准备区、战斗边界和操作按键层。

验收重点：标尺与动作 x 坐标一致、左右行高一致、长轴滚动无漂移。

### 阶段四：选择与编辑手势

1. 单选、Ctrl 多选和两类框选；
2. 动作拖动、吸附、边缘自动滚动和右键菜单；
3. 中键空白平移、滚轮规则和缩放；
4. 轨道排序、轨道高度调整、模拟边界拖动；
5. 统一快捷键 focus scope。

验收重点：手势互斥、无事件穿透、历史记录每个 command 只提交一次。

### 阶段五：投影装饰层

1. 命中点和伤害明细；
2. 冷却、持续时间、连携窗口和技能警告；
3. 上下 Buff/效果、资源曲线、切人标记和冻结区域；
4. 连接线与连接工具；
5. 属性检查器、战斗日志和底部资源面板。

每个装饰层必须等对应 Next receipt/projection 稳定后接入，不得在 Vue 中移植旧模拟逻辑。

### 阶段六：导入、导出与辅助功能

1. 方案管理、项目加载/接收、重置和快捷键帮助；
2. JSON/分享导出；
3. 长图导出使用明确 capture root 和完整内容尺寸；
4. 分析弹窗与多语言/主题设置。

## 10. 视觉回归验收

### 10.1 固定基准场景

旧版和 Next 使用语义等价的固定 fixture：

- 四条轨道，其中三名干员、一条空轨；
- 普攻链、战技、连携、终结技、处决各至少一个；
- 至少一个长名称、多段连携和禁用/警告动作；
- 武器、四件装备和三件套提示；
- 上下效果层、冷却条、命中点、切人标记和资源曲线；
- 准备区、60 秒战斗区、模拟起止线和循环边界。

fixture 只保存稳定项目输入；旧版需要的对照数据使用独立测试适配器，不进入 Next 生产代码。

### 10.2 截图矩阵

使用 Playwright 分别截取旧路由和 Next 路由：

| 视口      | 主题       | 状态                         |
| --------- | ---------- | ---------------------------- |
| 1920x1080 | 深色、浅色 | 默认布局                     |
| 1440x900  | 深色、浅色 | 默认布局                     |
| 1280x720  | 深色       | 左/右面板展开、底部展开      |

### 10.3 比较方法

- 先做结构断言：关键区域 bounding box、列宽、顶栏高、轨道头宽、lane 高、动作块高度和滚动范围；
- 再做区域截图差异：工作台、技能库、标尺、轨道头、单个动作块分别比较，避免整页微小字体抗锯齿掩盖问题；
- 字体抗锯齿和动态图标脉冲使用遮罩或关闭动画后比较；不得用大范围容差掩盖布局偏差；
- 关键尺寸允许误差不超过 1px；颜色按 token 计算值比较；交互状态必须逐项截图；
- 每阶段保留旧版基准图和 Next 实际图，迁移完成后旧版基准仍作为兼容契约，不从旧组件实时渲染。

### 10.4 交互回归

除截图外，使用 Playwright 验证用户可观察结果：

- 面板拖动、折叠、双击重置和刷新后恢复；
- 技能点击/拖放后的轨道、帧位置和历史记录；
- Ctrl 多选、框选切换、移动和撤销/重做；
- 中键平移、Ctrl 滚轮缩放、Shift 横滚；
- 弹窗或输入聚焦后快捷键不穿透；
- 右键菜单 hover 不触发下层控件；
- 时间轴、轨道头和标尺滚动始终同步；
- 长图导出覆盖完整松散效果高度。

## 11. 完成定义

只有同时满足以下条件，某一区域才算完成迁移：

1. DOM 主要层级、尺寸、token、图标和交互清单全部通过；
2. 深色和浅色主题均通过截图回归；
3. 数据来自 Next view model/command/projection，没有旧 Store 或旧组件依赖；
4. 未完成的数据层能力显示为明确空状态，不使用伪造结果；
5. 交互进入 Next history，撤销/重做行为稳定；
6. i18n 仅在渲染层发生，显示文本不写回项目；
7. 没有为了兼容视觉而把旧派生字段加入 Next 存档；
8. 没有抽取、包装或共享旧版业务组件。
