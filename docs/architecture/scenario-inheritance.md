# 方案继承与通用编辑约束

## 决策

继承方案仍是普通方案：保存完整养成配装、敌人和战斗配置、历史输入及后续输入，
仅额外记录继承时间与可失效的来源信息。不持久化运行时切面，不复制游戏定义，不维护方案依赖链。
来源方案修改或删除不影响继承方案；来源仅供导航。使用当前游戏数据与模拟实现重新计算历史，
接受版本更新改变结果，不维护旧引擎或旧定义快照。项目自定义定义继续遵守现有共享库规则。

## 存档与创建

用 `inheritance: { frame, sourceScenarioId }` 替换尚未落地的边界引用结构。
frame 是最早允许新输入的帧 F；来源 ID 不参与有效性、循环依赖或编译检查。
复制养成、配装、敌人、配置及作者输入，保留轨道、技能与标记在方案内部的身份；
方案本身获得新 ID。禁止共享可变对象。跨项目查找来源可以失败，不引入全局项目注册表。

创建时保留 F 之前的完整输入；原方案 F 起的未来输入不自动继承。
已经提交的技能、Buff、投射物、延迟回调等自然跨过 F 继续执行。
再次继承时独立复制更长的历史前缀，来源可以指向上一个方案，但运行不遍历它。
普通方案和继承方案使用相同导入、导出、保存、撤销及模拟入口。

## 通用编辑约束

约束属于应用层编辑事务，不属于战斗规则。提供三种能力：

| 约束 | 含义 |
| --- | --- |
| 对象位置锁 | 禁止移动、删除或改变对象的位置依赖；允许修改非位置参数 |
| 对象输入锁 | 禁止改变对象所属轨道、位置和模拟参数或删除对象 |
| 历史边界与配置锁 | F 前禁止增删改输入，禁止把未来输入移入历史；锁定运行配置 |

现有 `presentation.locked` 的界面文案是“锁定位置”，不能偷偷升级为全部参数锁。
继承使用输入冻结而非位置锁。历史空白也受保护，因此不能用批量锁块替代历史边界。
冻结输入不冻结显示宽度、命中、伤害及其他模拟派生结果；颜色、备注等纯展示项允许编辑。
配置锁覆盖队伍槽位及养成配装、初始资源、敌人、机制、全局修正和随机设置。
方案名称与展示布局不锁定；结束时间可调整，但不能早于继承边界。
完整历史重放仍需要原准备帧范围，不以“继承后无准备阶段”为由删除原始 prepFrames。

所有编辑都先产生候选文档，再由公共校验比较修改前后，成功后才能更新历史、修订号和订阅者。
场景会话与项目会话都接入，直接项目命令不能绕过。校验失败整笔拒绝，不能部分提交。
项目内删除整个方案属于文档管理，可以执行；新建、打开文档是新的编辑会话边界。
撤销/重做只恢复已通过约束的事务；继承固有限制不能通过普通解锁操作解除。
手动锁可解锁，但解锁和移动应分成独立事务，不能利用一个混合事务绕过原锁。
命令仍遵守现有不可变更新约定，不复制整份文档来掩盖原地修改。

## 连续组与实际输入时间

后续成员只存 afterCastId，不能把缺失 startFrame 当成未来或零帧。
建立继承前必须完成源方案模拟，从实际输入提交结果确定历史成员；拒绝使用过期结果。
切断历史与未来间的自动接续依赖，保留历史内部关系，后半段独立编辑。
冻结检查必须覆盖前驱链，不能通过移动未锁组首间接移动锁定成员。
一般位置锁允许组内时长随当前定义重算；历史输入冻结则保护确定的历史计划及其配置。
未解析位置的候选不得乐观放行；后半段新增连续组需经输入排程器确认不会提交到 F 前。
同帧输入顺序、轨道身份、随机种子、禁用状态均属于模拟输入，不能仅比较块 ID 和开始帧。

## 重放与切面缓存

打开方案后按普通初始化流程重放 F 之前的完整输入，在 F 输入前保存切面。
后续仅恢复该切面，再提交 F 起的技能、切人、消耗品和人工事件。
切面必须对应现有完整帧边界；确认 F−1 执行完毕后的公开状态确实接受 F 输入，
首帧的 initialInputPending 单独验证，不能笼统把切面时钟当作下次输入时间。
未发生的作者输入留在外部排程器，不能随保存点把原方案未来计划带入恢复分支。

缓存归模拟服务，绑定历史输入、配置与当前数据仓库身份；前缀重放成功后才可复用。
后缀失败不污染前缀，可复用已成功保存的历史切面。后半段编辑不失效历史切面；
切换方案或打开文件时按前缀内容比较，数据仓库变化创建新服务；最多保留一个前缀。
候选技能程序登记保持分支隔离，不污染历史程序目录。释放方案时释放检查点。
失败不能自动从头跑并伪装命中缓存；取消或过期任务不能发布模拟结果。
并非保证后半段永不重算，而是保证相同冻结前缀不因后半段编辑重复推进。

## 显示与统计

继承线是编辑起点，保留绝对战斗时间，不将时间重新归零。
左侧为只读历史，可折叠或默认只展示前几秒，不叫准备阶段，不允许放置输入。
完整历史结果保留用于来源查询，不因可见窗口截断早期 Buff、能力实体和技能的来源。
右侧结果照常显示，跨线的执行效果不裁断。统计只包含 F 起结算的伤害，
包括 F 前产生、F 起结算的持续伤害。来源导航失败显示来源不可用，不阻止模拟。
禁用操作与拒绝提示复用公共约束原因，不在每个组件加入 isInherited 判断。

## 实施与验收

1. 建立公共编辑约束入口，先接通现有技能位置锁，覆盖场景与项目提交、批量原子性、
   前驱链和解锁边界。此步不开放继承功能。
2. 统一枚举技能、切人、消耗品及人工输入，加入对象输入锁、配置锁和实际帧边界校验。
   纯展示分界线独立处理，不误认为战斗输入；新增可执行标记必须登记公共输入入口。
3. 替换继承存档、来源校验及旧测试，接创建方案的独立复制与历史/未来连续组切分。
4. 接正式模拟服务的前缀重放与检查点复用，验证原有场景和首帧语义。
5. 接历史区、锁定提示与来源导航，完成保存重开和真实轴验收。

关键测试是连续模拟与保存重开后续跑的回执一致；后半段编辑时历史推进次数为零；
修改/删除来源不影响继承；全部人工输入的跨边界修改被拒绝；同帧输入不重复、不遗漏；
正在运行的技能、Buff、回调、随机流与来源查询正确续接。使用定向测试及单条真实轴，
不以全量测试或枚举所有干员代替边界验证。

当前实现与验证统一记录在[当前交接](../handoff/current-context.md)，避免在设计文档重复维护进度。

继承区域复用战前准备区的展示和交互，折叠时裁掉 F 前历史，仅留 18px 展开入口，
展开恢复绝对帧坐标；技能、曲线、标记、拖动和缩放共用该换算。这里只改变显示，不改变输入帧身份。
顶部原准备时长按钮改为继承图标，点击或边界右键打开仅含来源跳转按钮的菜单。
历史展开与折叠使用轴上的箭头；展开默认从 F−10 秒查看，更早历史仍可滚动访问。
不显示重复的模拟起始线，不通过限制滚动隐藏历史，编辑限制仍由公共编辑策略保护。
