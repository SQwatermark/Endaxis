# 事件、来源与生命周期

事件表示某件事已经发生，或某个处理阶段正在执行。动作负责改变战斗状态；事件让其他能力在正确时点响应。
发布事件、运行监听动作和记录显示结果是不同步骤，不能互相替代。

## 从定义到执行

公共协议声明事件名称、条件和动作序列；转换器根据同版本原生数据生成定义。
场景编译解析等级与引用，运行时把响应安装到所属实体。事件在当前调用中同步分发，
外层动作等待响应完成后继续，响应也可能再次触发事件。

入口分别是 [公共协议](../../packages/game-data-contract/README.md)、
[运行时事件类型](../../src/core/combat/events/combatAbilityEvent.ts) 和
[事件分发器](../../src/core/combat/events/abilityEventDispatcher.ts)。
运行时载荷可能引用可变伤害对象或Buff实例，不能把它们写进可序列化的游戏定义。

同一次发布应保留事件和载荷的引用，避免监听者改到一份无人读取的副本。
不同处理时点、输出侧与承受侧的事件则保持独立。每个实体有自己的注册位置，
不能用一个无归属的全局广播替代它。

数据动作按优先级从高到低执行，同级按注册顺序执行。
技能临时监听属于哪一阶段，要看实际注册方式，不能根据宿主名称猜测。
分发时增删监听、嵌套调用的规则由公共分发器处理，宿主不另写排序或队列。

## 几种身份分别保留

假设A给B施加Buff，后来C的技能结束它：

| 身份           | 含义                                 |
| -------------- | ------------------------------------ |
| Buff Owner     | B，Buff挂在哪个实体身上              |
| Buff Source    | A，最初的施加来源                    |
| 本次结束来源   | C及此次施法，谁导致这次结束          |
| 监听宿主       | 持有响应程序、黑板和注册句柄的能力   |
| Input、Trigger | 当前事件按公共绑定规则提供的动作目标 |

不能拿最初施加者补成本次结束者，也不能把监听宿主当作事件来源。
`SkillCastInfo` 表示施法信息，不等于动作Owner或当前执行实体。
需要区分未知来源 `undefined`、明确无来源 `null` 和已知来源对象，不能自动借用外层上下文。

## 临时上下文与持久状态

[响应作用域](../../src/core/combat/runtime/abilityEventResponseContext.ts) 在进入事件时绑定上下文，
退出或抛错时恢复外层上下文。恢复目标与来源不意味着回滚战斗效果。

黑板是动作程序的变量表。同一能力的初始化和响应可以共享它，不同能力实例必须隔离。
响应序列也有自己的状态，不能每次收到事件都重建序列，绕过重复执行或重入限制。
不要用全局“正在响应”开关屏蔽其他合法的嵌套事件。

## 结束和释放不是一回事

| 操作         | 主要职责                                             |
| ------------ | ---------------------------------------------------- |
| 本次施法结束 | 结束该次时间轴并处理明确附着于它的内容               |
| 能力禁用     | 注销该能力响应，清理启动序列和所持子Buff             |
| Buff结束     | 根据结束原因执行相应动作与通知                       |
| Buff容器释放 | 释放修正、动作、监听及显示，不补发普通结束或消费通知 |
| 投射物回收   | 先结束当前技能，再通知reset，最后清理Source          |

`BuffReleased` 用于关闭显示，不能当作新增的可配置战斗事件。
能力拥有的子Buff与附着在实体身上的Buff也不是同一份集合。

[能力生命周期](../../src/core/combat/runtime/abilityEventHostLifecycle.ts) 管理注册和清理。
初始化成功后才启用自身响应；中途失败清理已创建内容，尽量完成其余清理后一起报告错误。
这是工程上的错误恢复保证，不是新的游戏规则。宿主差异仍由技能、Buff、装备和实体各自管理。

验证必须包含嵌套来源恢复、同一载荷引用、注册失败清理和跨技能存活，不能只检查事件名齐全。
游戏依据从 [研究目录](../research/README.md)查找，尚未完成的组合验收见 [当前交接](../handoff/current-context.md)。
