2026-09-06，在独立 Chrome 无头会话中同时运行旧版 5174 和当前版 5173，
viewport 1920×1080、deviceScaleFactor 1，不读写用户浏览器项目。

- 修后：四个按钮均为 70×28px；字号、字重、行高、padding、图文间距和默认颜色一致。
  深/浅主题悬停均保持 28px 高和向上 1px 位移；实际打开“更多”和“显示”正常。
- “更多”弹层两版均为 280×280.171875px。新版额外语言 RU、项目导出与旧版接收分享码
  的内容差异保留，不据此宣称分享功能已经复刻完成。

## 待逐块核对

### SCALE 和标尺已修正的切片

- 对照旧版 `TimelineGrid`、`timelineStore`：100% = 50px/现实秒，范围 15–1200px/秒
  （30%–2400%），滑块每步 1px/秒。新版维持 30Hz 帧协议，仅在 UI 几何换算中恢复此映射。
- 加减按钮按当前秒宽约 10% 变化；原先固定增减 10 个百分点和 50%–200% 范围不是必要差异。
- 角落纵向容器中的子控件此前被 `flex: 1 0 0` 撑满，导致内容贴顶；改成自然内容高度。
  Chrome 测量两版内容均为 169×46px、滑轨 137×2px，内部位置一致，深浅主题截图已检查。
- 标尺低亮秒刻度与逐帧刻度恢复其原本颜色，去掉重复 opacity；保留新版现实时间投影。
- 修复折叠准备区后轴末端拖动仍减完整准备时长的错误，改用共用逆投影。
  Chrome 实际拖动验证：5 秒准备区折叠，60s 轴末端左拖 50px，结果为 59s，无页面异常。
- 类型检查通过；时间轴 121 文件 / 707 项通过。测试中的既有 Element Plus SSR 注入警告仍存在。
- 后续补齐顶栏 50px 内容加 1px 边框后，两版角落坐标完全一致：外框 (249,51)、
  控件 (257,57.5)、滑轨 (273,97.5)。
- 准备时长/轴长输入恢复弹窗位置、背景、边框、阴影、字体和自动聚焦；统一充能右键输入
  同样恢复完整弹窗，保留可键盘操作的新版按钮实现。
- Chrome 测量准备时长弹窗两版均为 (687,57)、116.609375×38px；输入框均为 86×24px，
  打开立即获得焦点，Escape 关闭。旧版五秒显示 300f、新版显示 150f 是 60Hz/30Hz 协议差异，
  不修改新版帧协议来伪装为旧版。
- 1920×800 下实际纵向滚动后，SCALE 和标尺命中测试仍命中各自区域，轨道内容没有覆盖顶部。
- 折叠准备区时不再向 18px 窄区投影全部负时间刻度，避免标签重叠；旧版源码同样从 0 秒开始显示刻度。
- 滑块恢复只调整比例、保持水平滚动位置；加减按钮的居中锚点排除 180px 干员栏。
  浏览器从初始位置将滑块拉到最大，当前 scrollLeft 保持 0。
- 尚未验收整个标尺区：滚轮锚点、按键帽动态高度和各种缩放下的准备区仍需逐项实测。
