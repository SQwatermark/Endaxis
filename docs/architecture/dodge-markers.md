## 产品目标

用户在时间轴上方的操作标签区添加“闪避”或“极限闪避”，像切人、使用物品一样拖动、编辑、复制和删除。
标签会实际改变模拟：取消当前技能、保留普攻连段、改变接续窗口，并在极限闪避成功后执行技力恢复、
时间膨胀、Buff、事件和干员专属 Dodge 技能。

不满足游戏执行条件时仍按用户指定的操作执行，同时在标签上标出原因。不能自动改时间、偷偷切主控、
替换技能，或只留下一个没有实际作用的标签。程序错误和缺失定义不能伪装成可忽略的操作告警。

当前模拟只有固定敌人，没有敌人主动攻击。“极限闪避”标签因此表示用户声明本次成功，
不是模拟器推测敌人此时攻击。这个假设需要在详情中明示，不要求用户另造敌方技能或受击伤害。

## 标签表示什么

| 设置     | 含义                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 闪避     | 在指定时间由指定干员执行 Dash；不自动获得极限闪避收益                  |
| 极限闪避 | 执行同样的 Dash，并在指定成功时刻提交“本次极限闪避成功”的外部事实      |
| 干员     | 明确绑定一个轨道上的干员，不随之后的主控变化重新解释                   |
| 时间     | Dash 输入时间，使用现有标记的存档帧和显示时间转换                      |
| 成功延迟 | 仅极限闪避拥有，表示从输入到成功经过的现实帧数；默认 0                 |
| 方向     | 初期支持已确认的前闪、后闪，默认前闪；有模拟消费者才进一步暴露左右方向 |

默认延迟 0 是排轴约定，表示输入当帧恰好遇到可闪避的攻击，不代表游戏要求二者同帧。
详情可调整成功延迟；不把成功时刻与输入时刻永久混成一个时间。界面显示主标签和选中时的成功定位点，
两者一起移动，不额外生成第二个可独立遗失的存档标签。切换成普通闪避时去掉成功设定。

存档增加独立的 `dodgeMarkers`，每项只保存 ID、时间、轨道、方向，以及普通/极限闪避的判别联合。
极限闪避分支保存成功延迟。不要塞进 `ExternalCombatEventDocument.operatorHit`，也不要把角色专属
Dodge 技能 ID 写进用户输入；后者由当前干员定义解析。合法性、警告、已取消技能和收益均来自本次结果。

新建标签时默认绑定当前主控；之后拖动到主控不同的时刻，绑定不变并报告非主控告警。
详情可以换干员，也可以通过单独切人标签解决告警。复制到其他轨道按已有编辑规则显式换绑定。
删除/复制标签时，相应成功事实随标签一起删除/复制；复制只生成新的标签身份，不复制运行时结果。

## 执行过程

闪避需要中心状态机。它只复刻与排轴有关的 `Free / Attack / Skill / Dash`，不复制移动、动画和相机状态。
普通闪避进入 `Dash`；极限闪避成功监听器请求隐藏 Dodge 技能，技能实际开始时才离开 `Dash`、进入 `Skill`。
攻击输入阻挡、允许接续和极限闪避后的再次 Dash 阻挡是三只独立计时器，不能合成一个“正在闪避”标志。
状态数据进入战斗切面，转换规则和回调函数由恢复阶段重新绑定。
原生中心状态每帧收到角色缩放后的时间增量。模拟器以 30 Hz 帧数保存这三只计时器，
每帧按角色当前最终时间倍率扣减；局部和全局时间膨胀都可能改变攻击接续及再次 Dash 的开放时刻。
共享连续 Dash 窗口按玩家控制器的全局缩放时间推进，不读取某个干员的局部倍率；
人工成功延迟仍使用现实帧。证据见
[原生闪避记录](../../../combat-spec/docs/dodge-runtime.md#全局输入窗口数值)。

这里不需要再建一套覆盖全角色行为的总状态机。职责分成四层：Center 状态机保存角色当前处于
Free、技能或 Dash；技能实例保存 `canInterrupt` 与本次施放的 `MarkCanDash`；AbilitySystem 保存当前技能、
接续映射、连段 offset 和本角色的连续闪避上限覆盖；PlayerController 共享状态保存全队唯一的连续
闪避计数与距上次闪避时间。Dash 输入只在这些已有状态之间发起一次转换。这样既能还原原生状态，
也不会把技能生命周期、输入候选和中心状态复制到一个难以恢复的巨型对象里。

连段 offset 不是第二个状态机。能力系统保存一个可空的限时映射，其中只有触发类型、目标技能、
剩余时间和原生控制位。普攻在 `offsetRecordFrame` 提交下一段；Dash 状态进入时只要求能力系统
按原生规则创建映射。后续 Attack 输入按 `Skill > Buff > Offset > Mode > Default` 的优先级解析，
offset 按全局缩放时间到期。切面直接保存这些纯数据，恢复时重新绑定技能目录，不保存回调或技能对象。

### 普通闪避

1. 在输入前状态上读取执行条件，生成完整诊断，不因首个失败而停止检查。
2. 为本次操作建立运行时身份和来源回执，记录是否按不合法条件强制执行。
3. 对当前技能调用正式中断入口，原因是 Dash；执行原有结束清理和事件，不绕过生命周期。
4. 按原生规则保留或建立连段偏移，不把普攻段数机械加一。
5. 进入 Dash 状态，执行体力消耗、方向及接续计时器，创建原生免疫与监听状态。
6. 后续每帧使用各自时间域推进；后续输入通过更新后的候选和可用性检查。

当前技能的尚未执行动作被取消；独立投射物、Buff 和实体按自己的生命周期继续。
技能块宽度由实际中断回执缩短，已造成的伤害不撤销，尚未产生的 hit 不得继续展示。
闪避不需要另画一个占满轨道的技能块；选中标签时可以显示 Dash 和接续窗口的辅助范围。

### 极限闪避成功

在成功时刻读取当时状态，并定位本次 Dash。状态机先验证该 Dash 仍可声明成功；标签随后只发布一次
`beforeTakeDamage` 成功机会，来源为固定敌人、目标为该干员，不创建伤害结算。安装在干员身上的
`buff_common_dash_behit_listener` 继续按原生条件检查主控身份和防重复标记，并执行技力、体力返还、
成功免疫、事件、时间膨胀与隐藏 Dodge 技能。投射物路径另使用 `beforeHitByProjectile`，保留投射物自身的
极限闪避冷却与免疫等级条件。UI、标签处理器和状态机都不能写死“加 7 技力、加半份体力、冻结若干帧”。

状态机不复制成功效果。它只负责 Dash 是否仍有效，以及原生 `CastSkill` 请求真正启动 Dodge 技能时的
`Dash → Skill` 迁移。Buff 监听器是成功规则的唯一数据来源，因此普通受击路径、投射物路径和人工标签
不会形成三套不同的奖励实现；防重复标记和条件分支也不会被人工输入强制判真。

同一标签只能消费一次成功事实。一个标签的重试、恢复或重复提交不得重复返还资源、创建成功技能或膨胀。
两个不同标签则是两次不同输入：即便间隔不合法仍执行并告警，但真实存在的公共防重复条件仍会影响结果。

隐藏 Dodge 技能复用通用技能运行时和生成程序，内部施放身份从标签派生。技能运行时不区分
“伤害技能”和“非伤害技能”；是否造成伤害只由编译后的动作序列决定。当前原生公共 Dodge 技能没有
伤害动作，只承载极限闪避阶段及其接续行为。它产生的 Buff 和技能事件仍归属到真实程序，来源图可以
继续追溯到本次闪避标签。不能为了提供伤害入口而给 Dodge 类型增加虚构 hit，也不能在通用运行时写
`skillType === 'dodge'` 的伤害特例。

## 不合法但仍执行

执行前检查与实际执行分开。诊断只说明原生条件是否允许，不决定排轴输入是否被删除。

| 情况                                 | 模拟行为                                           | 标签说明                           |
| ------------------------------------ | -------------------------------------------------- | ---------------------------------- |
| 干员不是主控                         | 在该干员上执行，不切主控                           | 非主控，已按设定执行               |
| 当前终结技不允许 Dash                | 仍以 Dash 原因取消当前技能                         | 当前终结技尚不能被闪避取消         |
| 极限闪避期间禁止再次 Dash            | 开始本次 Dash                                      | 两次闪避间隔不足                   |
| 已确认的状态/标签禁止闪避            | 仍执行 Dash，不清除禁止标签                        | 列出真实限制及来源                 |
| 体力账户                             | 内部按原生规则计算消耗与返还，但不阻止闪避         | 不显示体力或体力告警               |
| 成功时已离开窗口或有禁止极限闪避标签 | 仍提交人工成功事实并进入公共成功流程               | 极限闪避条件不满足，成功由用户指定 |
| 同帧存在互斥主控操作                 | 按已规定顺序执行全部输入                           | 同帧操作冲突                       |
| 缺少尚未取证的原生输入窗口数值       | 执行已确认的 Dash 中断和状态转换；窗口查询返回未知 | 未验证，已执行可确定部分           |
| 干员缺少 Dodge 程序                  | 执行普通 Dash；不伪造 Dash Buff 或成功技能         | 未生成该干员的闪避程序             |
| 已声明极限闪避但隐藏技能无法启动     | 保留 Dash 和声明事实，不终止整场模拟               | 极限闪避技能未启动及具体原因       |
| 已有程序引用损坏或恢复图不完整       | 报模拟/数据错误，不伪造结果                        | 显示可复制的具体错误               |

“仍生效”指输入与成功事实会送入真实执行流程，不能理解为绕过所有原生效果条件。
例如非主控干员的被动仍按真实主控条件判断，防重复标记仍可能阻止部分成功收益。
详情分别列“输入已执行”“用户指定成功”“实际产生的效果”，不把三者合成一个成功布尔值。

未知规则不能直接显示为合法。尚未取得证据的检查显示“未验证”，与已确认违反条件区别开。
原生普通 Dash 的标签门已经闭环：定身 `InImmobilized`、复合禁止闪避查询 `InDisableDash` 和
霸体标签 `SuperArmor` 分别诊断；非法的时间轴声明仍然执行。玩家动作开关、移动步态和空中状态尚未进入
当前固定木桩场景，这些用户可自行判断的移动条件不产生常驻“未验证”提示。
`PlayerController._OnMaxDashCountSynced` 从账号同步值
`ServerGameVarDashEnergyLimit` 计算账户容量；本地 `GlobalConst` 的 `480 / 60 = 8` 只是允许的最大容量，
不能推出当前账号的容量。生成器保留最大值和每次消耗，模拟内部记录相对消耗与返还，不以未取得的
账号容量阻止闪避，也不在界面显示体力。在移动侧事实补齐前仍不能宣称闪避合法性完全复刻。

## 连段、候选与连续组

普攻开始时保存当前段，到达原生 `offsetRecordFrame` 后才更新为下一段。闪避保留当时的目标，
不是无条件把段数加一。例如佩丽卡 A1 的记录点是技能第 8 帧；过早闪避仍接 A1，经过记录点后
闪避才接 A2。编译程序中的记录帧必须通过实际技能运行时提供给能力系统；只在编译数据中保存
这个字段，会导致实际模拟始终接回当前段。`dodgeLifecycle.test.ts` 用佩丽卡和洛茜的生成数据
验证了这条链路；强化普攻与 Dodge 专用后续攻击仍需单独验收。

游戏普攻连段和编辑器连续组是不同概念。前者由原生 ComboController 的偏移、映射和接续窗口决定；
后者只是自动安排用户指定的一串技能。两者不能共用一个“下段序号”。

- Dash 中断按原生条件保存连段偏移；过期、换招和清理也按原生规则处理。
- 极限闪避后的攻击候选读取角色自己的 `AllowNextSkillAction`，不能统一设一个可接普攻时间。
- 用户明确放置的技能保持原身份；与当前候选不符时按现有技能输入策略执行并告警，不自动换段。
- 新拖入的普攻可以由已有候选查询给出建议；查询和正式执行必须调用同一规则。
- 固定时间的后续技能不会因闪避自动移动。连续组成员则按更新后的实际结束和接续时刻重新安排。

连续组对 Dash 增加明确处理：保留尚未执行成员，记录前段已被 Dash 结束，
等待本次 Dash/Dodge 的攻击接续窗口后再交给已有组调度器继续。不能因前段块提前结束，就在闪避当帧抢放下一段。
等待只处理此次闪避的接续时间，不扩展成“等资源够、等冷却好、等某个候选出现”的无限自动修复。
窗口开放时仍不匹配的指定技能按现有规则执行并告警。
其他显式技能接管、用户停止组等仍沿用已有中断规则；闪避后再次闪避更新等待条件，不叠加虚构的技能队列。

首次实现必须核对原生 offset 的建立、消费和过期，并覆盖普通普攻、强化普攻以及 Dodge 专用后续攻击。
不要仅凭教程的“连段不中断”实现所有攻击统一保段。

## 同帧顺序与时间膨胀

保留当前每帧系统更新和输入阶段的相对位置。输入阶段内的产品顺序规定为：

1. 切主控；
2. 使用物品；
3. Dash 标签；
4. 到期的人工极限闪避成功事实，包括本帧零延迟成功；
5. 技能输入与连续组接续；
6. 原有外部事件阶段。

这是排轴的确定性约定，不宣称游戏同时接受全部互斥按键。同阶段多个标签按文档声明顺序，
不按随机 ID 排序。零延迟极限闪避先完成 Dash 再成功；技能不会读到一半初始化的状态。
若多个标签抢占同一干员，保留各次执行结果并报告冲突，不静默合并。

成功动作产生的膨胀使用现有时间系统。全局作用域继续显示特殊轴效果；
仅干员或实体局部作用域只影响对应模拟，不新增全轴拉伸。
不能给极限闪避套用终结技专属交互或强行移动后续标签。
成功延迟使用现实帧；中心状态的三只输入窗口计时器使用角色缩放时间。
共享连续 Dash 窗口使用全局缩放时间；Buff、Dodge 动画和恢复计时器仍须分别核对各自的原生时间域。
0.33 秒不能未经现有时钟量化规则处理就硬编码为 10 帧。

## 状态、切面和数据流

```text
闪避标签存档
  → 编译：Dash 输入 + 可选的成功事实及绑定
  → 应用排程：仅提交当前帧
  → 运行时：检查 → 执行 → 生命周期/资源/事件/时间系统
  → 回执：操作结果、限制原因、实际收益及来源
  → 投影：标签角标、详情、技能结束、资源曲线、伤害与膨胀
```

Dash 输入属于玩家操作；人工成功属于外部事实。可以共用一个标签编辑，但语义不合并。
有成功延迟时，之后的成功事实留在应用排程器，不能在 Dash 输入时提前放入战斗切面。
保存切面后可以在分支中删除或改变之后的成功事实，过去的 Dash 状态保持不变。

切面保存已发生的 Dash 身份、阶段、方向、计时器、连段偏移和已消费的成功状态。
原生 Buff、当前 Dodge 技能、资源和时间膨胀继续由各自已有状态结构管理，不能再复制一份“闪避专用镜像”。
新状态并入 `combat/state` 的现有层次；执行逻辑放在技能/输入相关模块，整帧装配只负责连接。
临时操作身份在所有消费者结束后回收；历史回执负责长期查询，不能保存整场闪避 Map 阻止回收。

应用排程切面另存输入游标和连续组等待信息；它不属于纯战斗切面。
恢复不重发成功、不重新中断技能、不再次创建 Buff。动态程序解析与固定技能定义仍走现有登记机制。
Worker、逐帧试跑、完整模拟、恢复分支共用输入入口，不另写转换器专用闪避算法。

## 标签和告警外观

- 复用切人/物品所在标签区、拖动吸附、选择和重叠避让；不增加常驻状态栏或改变轨道高度。
- 普通闪避用闪避图标；极限闪避用同一主体加清楚的成功装饰，优先复用游戏资源和现有图标规范。
- 条件不合法时在标签右上角放约 8～10 像素的警告角标，并使用警告描边。
  角标占固定叠加位置，标签内容预留安全间距，不遮图标，也不因出现告警移动标签。
- “未验证”用问号提示，数据/程序错误用错误标记。不能只靠颜色区分；键盘聚焦与鼠标悬停都能读说明。
- 多个问题只显示一个角标，tooltip 列出全部原因；打开详情可以选择并复制完整文本。
- tooltip 跟随鼠标/焦点锚点，不按技能或 segment 长度计算位置。
- 详情展示输入/成功时间、绑定干员、方向、合法性、取消的技能、实际接续状态、实际技力变化、
  产生的 Buff 和时间膨胀，并提供来源追溯入口。显示实际执行差值，不显示未经结算的固定收益。
- 模拟重算期间沿用完整的上一份结果，整批完成再替换；新结果的告警不能挂到旧身份上。

标签角标先由闪避接入，再让同类操作标签按需要复用。技能块现有告警布局无需一并重做。

## 实现范围与步骤

1. **补齐证据和生成定义。** `BattleCommandMappingConfig` 实例和 Dash→Free 控制流已经取得；继续确认
   其余计时器的时间域、体力账户与扣减恢复规则，以及连段 offset 完整生命周期。
   复核成功动作的参数和 IFix 边界。生成角色 Dodge 程序、接续窗口和公共成功动作。
   `MarkCanDash` 已完成审查和接入。`dashLimit` 已确认会覆盖当前主控的连续 Dash 上限，负数表示
   `int.MaxValue`，并在动作结束时回滚。覆盖值、连续 Dash 计数与距上次 Dash 帧数已经进入切面；
   计数和时间属于全队唯一的 PlayerController 共享状态，切换干员不会清零，角色 AbilitySystem 只保存
   本角色当前生效的上限覆盖。共享计时由单独运行时每帧推进一次，不能放进每名干员的 Center 状态；
   默认移动配置按原生 0.3 秒内侧间隔和 0.8 秒外侧窗口判断。其他剩余分类仍需逐项审查，
   影响模拟的动作不能继续当纯表现丢弃。
2. **补全运行时链路。** Dash 输入、中断、成功事实、相对体力变化、公共成功收益、专属技能、
   连段 offset 和基础诊断已接通。资源变化与时间膨胀的创建回执已保存实际执行宿主，和 Buff 一样
   可以沿产生关系追到精确闪避标签；结束回执不能把创建者误写为结束操作的直接执行者。
   延迟施放请求现在保留提交动作的来源，隐藏 Dodge 技能的普通 `SkillStarted` 回执也能追到标签。
   技能取消及其他后续效果仍需逐项核对来源。账号容量尚无输入，不能把最大容量当作账号值。
3. **补全切面和排程。** 普通/极限闪避、零/非零成功延迟和分支恢复已共用正式入口；连续组会保留
   Dash 中断后的成员，并等待 Center 的攻击接续窗口开放后再提交下一段。
4. **补全编辑器投影。** 标签、详情、角标、撤销/重做、删除、导入导出和只读继承边界已接通；
   实际执行与强制执行原因已进入可复制详情，选中极限闪避时显示延迟成功定位点；复制粘贴会
   保留方向与成功延迟并给新标签分配独立 ID。详情按回执产生链列出实际 Buff、技力、时间膨胀、
   派生技能与伤害，每条事实可打开来源图；没有产生链的同帧效果不归入闪避。继续核对技能取消、
   更多后续行为和效果的展示完整性。当前公共
   Dodge 技能无伤害动作，不虚构伤害入口。
5. **真实轴和浏览器验收。** 完成下列矩阵。旧轴转换已把标准闪避块转成普通闪避，并在智能顺延时
   保留其相对前项的顺序；旧格式没有成功证据，不补极限闪避收益。

预期修改范围包括生成器/公共定义、项目输入、核心输入与技能接续、切面、结果投影和标签 UI。
跨层是因为新增真实输入，不应需要逐个修改所有 Buff、伤害公式或干员手写文件。
若每个效果都要新增闪避分支，先检查是否复用了公共成功动作、生命周期和事件入口。
本设计不引入通用敌人 AI、空间碰撞模拟、通用输入回放框架或第二套时间系统。

## 验收矩阵

| 类别       | 必须验证的结果                                                                         |
| ---------- | -------------------------------------------------------------------------------------- |
| 技能取消   | 命中前取消不出伤害；命中后取消保留已发生伤害；已生成投射物继续；附属对象按真实规则清理 |
| 合法性     | 普攻、普通技能、终结技允许/禁止窗口、非主控、状态限制、资源不足均有明确执行与诊断      |
| 极限闪避   | 普通闪避无成功收益；指定成功只执行一次；禁止/过期仍执行并告警；不产生假的受击事件      |
| 成功分支   | 公共防重复标记、不同成功时刻、成功前再次闪避/切人/释放技能，均按当时状态结算           |
| 连段       | 多名干员、普攻和强化普攻、Dodge 专用攻击；允许窗口内外与 offset 过期边界               |
| 连续组     | 闪避不丢后续成员，也不当帧抢放；再次闪避更新等待；其他显式技能仍可结束组               |
| 时间       | 全局/局部膨胀、零延迟、窗口最后有效帧与首个无效帧；标签位置与实际回执一致              |
| 资源与被动 | 内部体力和技力实际差值正确；体力不限制闪避且不进入 UI；成功相关装备和天赋正常触发      |
| 同帧       | 切人→闪避→成功→技能的顺序稳定；重复输入有诊断，执行和来源不会串线                      |
| 切面       | Dash 中、成功前后、Dodge 技能中恢复，与从头运行的状态及回执一致                        |
| 分支       | 同一切面后指定成功/不成功/不同时间互不污染；战斗切面不含尚未提交的成功事实             |
| 来源       | 技能取消、成功收益、Buff、内部技能及伤害能追溯到精确标签，无图标也不丢 hit             |
| 编辑       | 拖动、撤销、复制、删标记、导入导出、禁改历史范围和 Worker 输出一致                     |
| 视觉       | 密集标签、深浅主题、缩放及小图标角标可辨认；tooltip 不漂移；告警可复制；重算不闪动     |

测试优先覆盖边界和副作用顺序，不用源码字符串断言证明规则正确。
重型测试串行、单 worker；真实轴比较保留输入与结果，不能以总伤害相同替代逐项生命周期验证。
最终交付区分原生证据已确认、排轴约定、尚未验证三类结论。
