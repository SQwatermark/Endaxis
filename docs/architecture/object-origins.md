# 战斗对象来源查询

状态：2026-09-17 第一阶段已实现：公共出生/执行事实、只读查询与实际 hit 分类。用于 hit 分类、来源说明和开发审计；伤害贡献仍遵守
[有限直接归因](damage-contribution.md)，不因能继续追溯就继续分配贡献。

## 决策与范围

建立已发布战斗结果上的只读对象查询。对象可枚举，关系有明确类型，按需向上展开成图；
界面可将某次查询结果展开成树。事实保存在原有回执历史中，查询索引可随时丢弃和重建。
不保活已回收实例，不维护第二份运行时来源目录，不把整条祖先链复制到每个 hit。

第一批消费者是命中颜色和来源审计；直接加成提示复用同一对象寻址和名称解析。
不建立黑板依赖图、逐层 Buff 数值历史、全事件因果图或通用图编辑器。
本期查询历史结果；实时原生 Source 查询继续使用现有运行时端口。

## 现有事实与缺口

| 对象或记录       | 已有可复用信息                                                                          | 不能据此推断的内容                                                                   |
| ---------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 能力实体、投射物 | 共用实体编号；各自状态有 `source`，回调/子技能知道实际宿主                              | Source 是实体身份，不包含创建它的 Buff 实例；回收后活动目录无法查询                  |
| Buff             | `BuffReference` 为 ownerId + instanceId；状态有 sourceId、sourceActionId、skillCastInfo | Buff 定义 ID 不是实例；施加者、属性来源和创建它的执行对象不是同一概念                |
| 全局 Buff        | 独立实例编号、来源和投影出的子 Buff 引用                                                | 不能与普通 Buff 编号混用；当前历史中没有完整保留这段关系                             |
| 技能             | 时间轴 castId、SkillStarted 回执、继承的 SkillCastInfo、实际宿主                        | skillCastId 可被回调继承，不是每次子技能执行的唯一编号；programId 也只是固定程序身份 |
| DamageApplied    | 回执 sequence、castId、hitId、stepKey；直接 Buff 伤害有 executingBuff 身份              | hitId/stepKey 可重复执行；sourceId 常为归属干员，不能反推出执行实体                  |
| 直接加成         | AppliedDamageModifier 的实际数值、buffId、sourceId、sourceActionId                      | 当前没有精确 Buff 实例引用，不能按定义 ID 猜成某个实例                               |

第一阶段已补齐以下原有缺口：

- `AbilityEntitySpawned` 现在冻结实际 Source 与创建执行者。
- 投射物在同步 `projectileLaunched` 通知前记录 `ProjectileLaunched` 出生回执。
- Buff 回调中已有 executingBuff，能力实体子技能/投射物回调中已有 actionOwnerAbilityEntity；
  这些身份经 `operationProducer` 统一进入对象创建和伤害回执。
- Buff 分配后、Start/Enable 前新增独立出生事实；全局 Buff 同样记录创建者。
  `BuffApplied` 保持施加/刷新语义，直接接收实际实例，不再按定义 ID 反查。

代码入口：`combat/state/{instanceState,foundationState,abilityState}.ts`、
`combat/skills/skillRuntime.ts`、`combat/runtime/{combatRuntimeAssembly,standardPlayerDamageEnvironment}.ts`。
上述路径均相对 `src/core/`。这些是 Endaxis 数据缺口，不是新增的原生规则。

## 对象与关系

查询引用使用带类型的联合，只包装已有身份，不分配一套新的全局对象 ID：

| 查询对象                     | 身份                                                                       |
| ---------------------------- | -------------------------------------------------------------------------- |
| 实体                         | 复用 RuntimeTargetRef；投射物是 abilityEntity 的子类信息                   |
| Buff                         | 复用 BuffReference                                                         |
| 全局 Buff                    | 独立 kind + 既有 instanceId                                                |
| 一次伤害、一次技能开始等事实 | 所属结果内的 receipt sequence                                              |
| 一项直接修正                 | DamageApplied sequence + appliedDamageModifiers 数组下标                   |
| 技能块、装备、天赋等程序来源 | 已有 castId，或所属对象 + sourceActionId；明确表示程序来源，不冒充执行实例 |

所有引用都在一个查询会话内有效，会话绑定固定 CombatReceiptView 和本次发布的元数据。
跨会话传递句柄必须校验所属结果。分支可能重复使用实体编号和回执 sequence，不能按裸编号全局缓存。
不凭 frame、同帧邻近、定义 ID、名字或字符串前缀猜测实例关系；既有身份编码通过统一适配口解释。

第一期关系如下，查询时显式选择，不能沿全部关系混着寻找“来源”：

| 关系          | 回答什么                            | 用途                                       |
| ------------- | ----------------------------------- | ------------------------------------------ |
| producedBy    | 哪个执行对象直接产生了这个对象/结果 | Buff 派生伤害判断、产生路径                |
| runtimeSource | 原生语义中的实体 Source 是谁        | 展示、诊断；不自动视为 producedBy          |
| ownedBy       | 归哪个实体持有或管理                | 对象说明；不证明创建关系                   |
| originCast    | 继承自哪次来源施法                  | 对应技能块；不证明直接创建关系             |
| modifiedBy    | 本次结算受哪些已记录直接修正影响    | 乘区明细和有限贡献                         |
| providedBy    | 某项修正的直接提供者/程序来源       | 复用 Buff 图标来源名称，不继续分配上游贡献 |

关系附带已有事实定位（回执序号及必要的步骤信息）。SkillAffix 持有集合、附着 Buff、
reset 订阅等是寿命管理关系，不直接转为 producedBy；也不把任意对象属性当作图边。
全局 Buff 明确执行子 Buff 创建时可记录产生关系，但不能仅凭任意 children 集合反推。

```text
小箭雨伤害 ─producedBy→ 小箭雨实体 ─producedBy→ Buff 实例
                      └originCast→ 终结技技能块

普通攻击伤害 ─producedBy→ 普攻技能块
            └modifiedBy→ 一项攻击加成 ─providedBy→ 武器/直接提供者
```

第二例不能因为加成来自 Buff 就把普通攻击判成 Buff 派生伤害。
来源图允许共享节点，但历史因果关系必须形成 DAG。同一实例在不同时间的状态是不同节点，
不能把早期来源替换成后续状态而造成循环。
节点去重依据是实例在某次已记录变化后的状态，不是实例 ID 本身，也不是帧号。
同帧发生两次变化也要分别参与布局；多条边引用同一个历史状态时才共用节点。

## 怎样补足事实

只在事实发生处记录直接关系，查询时再连接。不要向生成定义加入颜色或来源分类字段。

1. 在公共记录边界从当前动作宿主读取直接执行者。Buff 动作用已有 executingBuff，
   实体子技能和回调用已有 actionOwnerAbilityEntity；普通技能或初始化动作使用其真实宿主信息。
   同步事件的触发者不能覆盖响应 Buff 的身份，currentTarget 也不能冒充执行者。
   复用一个读取/记录入口，不让各消费者重复编写判断。
2. 实体和投射物创建回执记录既有实例编号、实际 Source 以及直接创建者。
   Buff 在分配身份后、Start/Enable 可产生后代前记录出生事实；不改变公共战斗事件顺序。
   BuffApplied 继续表示成功施加/刷新，直接使用实际返回的实例，删除按定义 ID 反查的歧义。
   刷新、增强、继承不重写出生来源，也不新增虚假的实例。
3. DamageApplied 记录直接执行对象引用，保留已有攻击者和施法归属字段的含义。
   补录必须在当前执行上下文有效时取得；不把祖先字段沿伤害公式各层转发。
   子技能名、步骤键可作为本次事实的说明，不为每个步骤另建对象或编号。
4. 直接修正仍以已冻结的数值和提供者解释公式。确需跳转 Buff 实例时，在采集修正的公共入口
   补既有 BuffReference；之前只有定义来源的记录如实停在该层，不按 buffId 找最近实例。
5. 跨帧延迟动作优先从恢复后的真实宿主取身份；只有原请求确实丢失直接执行者时，才在该请求
   保存一个直接引用。不能用全局临时变量跨帧追踪，也不能把 originCast 当作缺失生产关系的替代。

出生事实对同一实例只记录一次；恢复切面不重新发出生回执。查询所需的最少事实进入现有公共回执、
冻结、Worker 传输和导出流程，不新增旁路文件或单独的图导出。若需要类型封装，只在回执公共入口维护，
不为每种消费者各建解析格式。本期不替换整套回执协议或重构技能运行时。

这会增加少量直接引用事实和查询类型，但不新增可恢复的祖先图，也不存 Buff 层数的历史快照。
本期不为所有内部子技能建立独立执行身份；有实体宿主的路径通过该实体连接。
需要区分同宿主的多次技能开始时，使用真实开始回执；没有明确关联的地方返回未知，不能合并猜测。

## 查询接口、时间与成本

公共模块放在 `src/core/projection/combatObjectOrigins.ts`，第一期集中实现，避免拆散成每种对象一个文件。
依赖方向为运行时 → 公共回执 → 来源投影 → UI/审计；运行时不调用投影来决定游戏行为。
对外提供四类能力：枚举对象、按引用取得描述、列出直接关系、沿指定关系向上查询。
遍历返回匹配对象及路径，并区分“完整查找后没有”“事实缺失”“循环”“超出上限”。
不能把后三种情况转换成已确认不存在。

一次发布建立一个查询会话，按需扫描回执建立引用到事实的索引；保存回执引用/序号即可，
不复制每个对象的整份状态。单次索引成本 O(回执数 + 修正项数)，单次遍历成本 O(访问节点 + 边)。
批量命中分类共享索引，不对每个 hit 全量扫描；目前不额外缓存遍历结果。
普通显示不复制整张图，切面也不复制查询缓存。

查询以回执 sequence 截止，不能只按 frame：同帧存在嵌套、刷新和多次结算。
解释某次伤害只使用该次伤害发生时已有事实及其冻结的修正；后续刷新不能改变过去的解释。
发布新结果或切换分支使用新会话，名称解析使用发布时元数据，不读取新草稿。
先采用每个固定结果独立建索引；没有测量依据时不增加跨分支增量缓存。

## 消费者规则与推进

- hit 显示先确定归技能块还是独立效果图标。独立效果默认白色，技能块普通命中默认红色；
  技能块 hit 的 producedBy 路径包含 Buff 时标黄。随机/强制暴击均以红色加金边覆盖普通颜色。
  消费强化蓝色必须另有明确的消费影响事实，不能凭消费事件同帧或整条图中存在 Buff 判定。
- Buff 名称、武器名等继续复用 `publishedBuffSource` 的展示规则；查询核心不生成本地化文本。
- 伤害明细读取直接修正；总贡献止于直接提供者，未分解算自身。
  查询路径的深度不会扩大归因深度，也不从“存在关联”推导数值比例。
- 缺失关系保持默认显示并记录开发诊断，不能在生产查询里退回定义树猜测。

按两段交付：先补公共出生/直接执行事实并提供枚举、关系查询，用 hit 分类和开发审计验证；
随后让直接加成提示复用对象寻址。第一段完成时，删除 `collectTriggeredHitStepKeys` 的静态定义扫描、
发布元数据中的触发步骤集合及其传递逻辑，不保留两套生产规则。

定向验收围绕结构边界：同一子技能分别由普通技能和 Buff 创建；嵌套实体/投射物；
Buff 的 Start 当场产生伤害；刷新与同定义多实例；对象回收后查询；恢复分支编号重叠；
修正关系不污染产生路径；共享节点、循环和缺失引用。最后用真实旧轴对照小箭雨、
连携持续伤害、梨诺声波与法术爆发，并核对数值、时序和切面续跑结果不变。
不因来源查询跑全量测试，也不把样本颜色正确当作图关系完整。

第一阶段已删除上述静态扫描和步骤集合。查询引用复用既有编号；新事实只进入公共回执，
没有向 combat/state 添加来源图。创建者、Source、归属、施法和修正关系分别查询。
已覆盖回收后查询、分支隔离、同帧截止、嵌套 Start、刷新与历史导出恢复。

直接加成提示、来源图和贡献投影已共用 directModifiers；修正记录提供精确 Buff 实例时可跳转。
尚未为无实体宿主的每次内部子技能增加独立执行身份。缺失关系返回未知，不用来源施法或定义树填补。
外部贡献只分配已支持的直接修正，边界见[伤害贡献归因](damage-contribution.md)，不沿来源图递归分账。

## 可视化入口

七乘区属性修正只在结算实际注入该属性时进入命中回执，不把双方完整属性明细当作生效来源。
例如电属性增幅不进入自然伤害的解释；已注入属性不再重复追加未分区副本。
回执统一过滤中性操作，图和详情不维护 Buff 黑名单，也不通过逐项移除重算建立计算图。
非乘区来源在基础计算分支及最终公式读取处收集，固定值不带攻击来源，指定属性不带其他基础属性，
真伤不带抗性来源。攻击读取计算前阶段；四维与派生系数复用已冻结攻击明细，零系数四维不作为来源。
回执同时解释实际和期望伤害，暴击来源不能仅因本次未暴击而删除。
攻击快照未保存历史来源时留缺口，不用当前 Buff 替代；不做逐项移除或钳制后的边际效果判定。

hit 伤害详情底部的“对象来源图”按钮打开独立 `CombatObjectOriginGraph.vue` 面板。
默认查看“产生与增益来源”，同时追溯实际加成及其提供者；可切换纯产生者、全部上游关系或单类关系。
所有模式都只向前追溯，不通过 `castEvent` / `buffEvent` 反向展开施法效果或实例过程历史。
增益复用命中回执的直接修正记录，沿提供行为的归属关系到干员，不按 Buff 定义猜实例，也不参与产生路径判定。
展示层按历史状态身份去重，使用 SVG 节点与有向连线保留共享来源，不再复制成树形列表。
支持拖动画布、滚轮/按钮缩放、适应画布、节点选择和完整标识详情。最多显示 128 个对象，超限明确提示。
布局使用 `@dagrejs/dagre` 的 network-simplex 分层、交叉消减和坐标分配；多重边及跨层边由库统一路由。
布局输入为每条关系增加一个不显示的中间点，分别连接两端，再将两段路由接回一条线。
这是为了避开 Dagre 3.1.1 对分支 DAG 中平行边的矩形交点异常；4 节点、5 边的合法无环图可复现。
中间点不进入来源节点、详情或贡献统计，不合并或删除关系，也不能用来掩盖历史因果环。
每条来源边按该关系自身的回执序号定位此前的 Buff 状态；命中序号只是整图的最晚截止，
不能用于替换每个历史来源。例如 A 产生 B、B 随后增强 A，应显示 A₂ → B → A₁，不能变成 A₂ ↔ B。
对象引用自身不画成来源边；自增长必须指向增长前的状态。不能靠布局去环或绕线掩盖错误关联。
SVG 沿库输出的路径点做平滑连接，不另写排层、排序或顶部绕行规则。库只参与显示，不修改事实中的关系方向。
打开时以可读比例定位命中；适应画布用于全图总览。关系标签只显示选中节点的相邻边，其余可悬停查看。
每次查询截止到该 hit 的回执序号。
行为节点继续沿明确标注的归属关系展开到所属干员，干员名称由已发布方案与元数据解析。
其他对象目前展示技术标识、对象类型及回执帧数，用于核对关系；尚未接完整名称解析。
节点及详情接入干员头像、技能/天赋、武器/装备、Buff、元素与法术爆发图标。
图标从已发布展示元数据解析；Buff 按所属对象和实例编号、查询截止序号查找，叠层与消费等过程复用目标 Buff 图标。
直接来自武器的 Buff 与时间轴保持武器图标优先。没有独立图标或图片加载失败时保留文字，不猜实体图标。
组件只依赖发布结果查询，不新增运行时字段，不建立可编辑图或影响模拟。

### Buff 过程关系

施加/刷新、实际层数变化、叠层尝试、消费、吸收、结束/回收使用独立回执节点，连接实际 ownerId + instanceId。
`buffEvent` 连接实例与其过程记录；`castEvent` 只表示回执明确携带的来源施法，不表示该技能直接执行了所有事件。
事件分别通过 `appliedBuff`、`changedStacks`、`attemptedStacking`、`consumedBuff`、`absorbedBuff`、`endedBuff` 连接目标。
消费事件的 sourceId 作为 `eventSource`，不能冒充当前执行者；已知施加执行者仍使用 `producedBy`。

实际增减层在层数写入后、增强动作前观察，记录前后值，包含定时自然增长；不额外触发原生事件。
满层仍发生的增强尝试单列，不能把通知的 +1 当作实际增长。独立实例叠加仍表现为各自施加记录，
不按相同 Buff 定义 ID 合并成一个实例。消费/吸收复用原有成功通知，只保存实例和涉及层数，不复制黑板。
所有关系按回执序号截止，消费完成通知晚于某次伤害时，不反向补进那次伤害的解释。
没有新增可恢复的层数历史状态，也不把消费关系用于标黄或自动推导伤害贡献。
