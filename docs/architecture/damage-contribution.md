# 伤害贡献归因

伤害分析的左图回答“伤害由谁直接造成”，中图回答“这些伤害中有多少由各干员的自身数值和外部增益贡献”。
贡献归因只分解同一次正式模拟已经结算的 Hit，不重跑时间轴，不从最终总伤害反推状态。

## 目标和边界

- 每笔伤害分解为攻击者自身贡献与各外部提供者贡献，总和严格等于该笔回执的 `value`。
- 期望与随机模式分解各自已发布的伤害口径，不在 UI 重算暴击、抗性或随机状态。
- 投射物、Buff 周期伤害和元素爆发保留真实执行实体，但提供者归因使用稳定的干员身份。
- 不把回执顺序、Buff 名称或同帧事件当作来源。无法证明的修正留在攻击者自身项，并通过诊断暴露缺失来源。
- 这是模拟结果的解释层，不改变伤害、Buff、元素反应或失衡的执行规则。

## 冻结的输入

贡献计算位于伤害公式已经得到完整结果、`DamageApplied` 尚未写入的边界。一次 Hit 需要冻结：

1. 实际结算值和已有公式分项：基础伤害、暴击期望或本次暴击、防御、抗性、增伤、易伤、庇护等。
2. 本 Hit 实际参与计算的修正列表。每项修正包含计算阶段、数值、来源实体、来源 Buff/装备/技能身份及最终提供者干员。
3. 只保留伤害来源干员自身修正后的“自身基线”公式分项。它在当前 Hit 的冻结快照上计算，不重放技能或时间轴。
4. 失衡、连携或反应消耗层等非普通修正的来源份额。这些份额由对应状态账本在发生时冻结，伤害分析不遍历当前容器补猜历史。

来源身份是运行时数据，不应塞入每个生成技能的文本或为每名干员配置特例。属性修正、伤害处理器和 Buff 实例已经知道自己的来源，装配层只负责把这个身份带到伤害上下文。

## LMDI 分解

新实现沿用旧版的对数平均迪氏指数方法，但不复用旧版独立的属性、敌人状态和伤害公式。

设完整伤害为 `D_actual`，仅自身伤害为 `D_self`，且两者都大于零：

```text
L = (D_actual - D_self) / ln(D_actual / D_self)
乘区 k 的外部贡献 = L * ln(F_actual[k] / F_self[k])
```

同一乘区内多个提供者的份额，按该乘区中实际参与计算的可加修正绝对值比例分配。
不能直接按比例合并的独立乘区，必须在伤害上下文中保留每个修正的实际因子。
最后用余数保证零残差：

```text
self = D_actual - sum(external)
```

下列情况不强行使用对数：

- `D_actual <= 0` 时所有贡献为零。
- `D_self <= 0`、乘区非正数或数值不能稳定分解时，该笔记录诊断并将未分配余数留给攻击者，不产生 NaN 或丢失伤害。
- 负面外部效果允许得到负贡献；界面不应因为饼图不适合负数就篡改结果。首个版本若只展示非负贡献，必须明确诊断并保留完整回执。

## 特殊状态归因

- **元素反应**：反应伤害本身的来源是当前触发者；法术强度和普通乘区按修正来源分解。导电、腐蚀、破防等状态的收益支持“按施加者”和“按层来源”两种投影。这两种模式只改显示分配，不重跑模拟。
- **失衡**：进入失衡时冻结该轮有效失衡值的提供者份额。溢出失衡值不能获得贡献。失衡窗口内的增伤按冻结份额分配。
- **消耗层数**：连携、附着和反应只分配本次实际消耗的层；消耗时冻结实例来源份额，不用伤害帧的当前层数。
- **自身、武器和装备**：归属到装备者。它们可在详情中保留更细的来源类型，中图的顶层切片仍按干员聚合。
- **无干员来源**：关卡、敌人或全局机制的修正进入明确的环境桶，不假装成任一干员贡献。

## 回执与显示契约

`DamageApplied` 增加可选的冻结结果，语义形状为：

```ts
interface DamageContributionResult {
  self: number;
  external: readonly {
    providerOperatorId: string | null;
    sourceKind: 'buff' | 'equipment' | 'status' | 'stagger' | 'mechanic';
    sourceId: string;
    value: number;
  }[];
  unallocated: number;
  diagnostics: readonly string[];
}
```

正式契约应使用现有可读标签和来源类型，实际字段在实现时与回执公共结构合并；上述只固定所需语义。
回执保存分解结果，不保存 Buff 容器、属性集或处理器的可变引用。切面恢复只需恢复战斗状态；已发布回执仍是不可变历史。

中图使用两层结构：

- 内圈是每名干员的总贡献。
- 外圈把同一干员拆成自身直接伤害和对别人伤害的外部贡献。
- 饼图扇区面积使用贡献绝对值，文字和提示保留正负号。这样减伤等负贡献不会被截成零，正负贡献相抵时内外圈也不会出现结构矛盾。

点击切片应能下钻到提供者及来源 Buff/装备/状态；顶层图不复制战斗日志。

## 实施顺序

1. 在属性修正和伤害处理器上贯通稳定来源，不改变现有叠加与执行顺序。
2. 从当前伤害上下文提取纯数据的实际乘区、自身乘区和来源份额，实现无 UI 依赖的 LMDI 函数。
3. 先覆盖普通伤害的攻击、增伤、暴击、易伤、减抗和承伤乘区，把结果写入回执。
4. 接入中间双层饼图与单 Hit 详情，对每笔伤害验证零残差。
5. 接入失衡、连携、元素反应与消耗层来源，恢复“按施加者／按层来源”投影切换。
6. 用单 Hit 公式边界、真实多干员场景、元素反应、失衡窗口和旧轴做对照；贡献开启前后的战斗状态与伤害回执值必须不变。

## 当前实现进度

普通生命伤害已经接通第一版完整链路：

- Buff 创建的属性修正和伤害处理器会保存提供者干员与 Buff 定义编号。
- 每个 Hit 同时冻结实际属性和排除其他干员来源后的自身属性；攻击、暴击、防御、抗性、增伤、易伤、庇护与承伤都使用同一份命中快照计算。
- 直接修改计算值和七个伤害乘区的处理器保留各自来源；同一来源的多项影响在分解前合并。
- `DamageApplied.data.contribution` 保存纯数据结果。护盾在公式之后吸收伤害时，各项贡献同比缩放并重新闭合。
- 伤害分析中图已经显示双层贡献图：内圈汇总干员总贡献，外圈区分自身伤害和给队友的增益。
- 单 Hit 伤害详情会直接展开该回执冻结的自身贡献和外部来源，并通过现有 Buff i18n 显示名称。
- 总伤害面板会按提供者、来源类型和来源 ID 汇总外部贡献；正负数都保留，可从干员总贡献继续核对到具体 Buff、状态、装备或机制。
- 元素附着、爆发和复合状态由元素子系统明确标记为 `status`，失衡增伤 Buff 由失衡子系统标记为 `stagger`；公共 Buff 运行时不按 ID 猜类型。
- 增强型状态逐层保存施加者。多名干员叠加同一状态时，属性修正会按当前仍存在的层分别归因；减层从最后加入的来源开始移除。
- 一个伤害修正器用聚合黑板值表示多层效果时，修正只执行一次，归因元数据按当前逐层来源拆分。加算乘区线性拆分，乘算乘区按幂拆分，因此拆分前后的实际伤害不变。

消费事件已经冻结本次实际消费层的来源列表。后续仍需逐项审计真正读取消费层数并产生伤害的动作，只有数值确实由这些层提供时才使用这份列表；不能把同一 `buffConsumed` 响应中的所有伤害都归给被消费层的施加者。

## 验收条件

- 每个已支持 Hit 的 `self + external + unallocated` 与 `DamageApplied.value` 在明确的浮点误差内相等。
- 删除、移动或分支模拟不会让旧回执改用未来状态重算贡献。
- 同值修正调换注册顺序不改变按提供者汇总的结果。
- 投射物、子技能和 Buff 伤害归到真实来源干员，不因实体回收丢失身份。
- 按施加者和按层来源只改变特定状态的展示份额，两种模式的总伤害及总贡献相等。
- 期望与随机模式都使用本次已发布回执，切换页面显示不会触发新模拟。
