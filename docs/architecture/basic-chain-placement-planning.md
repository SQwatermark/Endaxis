# 普攻链放置建议与真实输入边界

## 问题和边界

2026-09-06：施放当帧零 delta 修正之后，默认布局已包含到下一次输入的一个边界帧。
这修正了佩丽卡的基础连段，但不能补偿近战命中停帧、攻速和场景中的其他时间膨胀。
`timelineBlockFrames` 是显示边界，不是具体下一技能的可释放判据。不得把显示回执拿来
控制实际中断，也不得通过裁切前一技能的 hit 或后续效果消除告警。

运行时已有的 `evaluatePlayerInputInterruption` 才是当前接续门禁：允许接续窗口、
优先级、保护区间和已确认的旁路。操作映射是独立判断；“能中断”不代表操作会选择
作者指定的下一段。原生还存在输入缓存，见复刻库 `docs/combo-input.md`，不能把
未来的编辑器建议声称为完整复刻了输入缓存。

## 实现方案

1. 对本次新拖入的链创建临时规划请求，固定首段的作者现实帧、技能身份与顺序。
   既有技能、标记及其他轨道的现实帧完全不变；分组不进入正式模拟协议。
2. 规划实例复用正式编译与战斗运行时。在每次真实输入阶段，用同一操作映射和中断
   查询判断下一段，不能另写一套根据静态帧数、停帧长度相加的判断。
   查询必须无副作用，并明确发生在当帧技能更新之前。
3. 首段执行后，只有操作身份匹配且接续门禁明确允许时，才把下一段确定在该现实帧。
   查询未知、映射始终不匹配、被既有技能插入破坏连段，或到达轴末仍不能接续时，
   返回明确的未解决结果；不能跳过未知条件后声称合法，也不能悄悄替换技能。
   冷却、资源、标签等诊断仍独立保留；不通过无限延后消除所有告警。
4. 规划仅产生建议。最终仍以全部显式现实帧重新跑一次正式模拟并检查目标链，
   不向用户存档加入“自动延后释放”语义，不改变硬着头皮释放的既有模拟策略。

## 编辑器提交与性能要求

- 新链作为一次撤销事务提交。异步计算完成时必须核对场景版本、游戏数据版本和拖放
  请求身份；旧结果不得覆盖后续编辑、撤销、切换方案或取消拖放。
- 预览和落地消费同一规划结果；计算中不能假装静态预览已保证合法，放下后也不能
  在后台再次移动技能。错误时保留可解释诊断，不吞掉整条链。
- 不在每次鼠标移动时逐候选完整重跑场景。不将本次测试的穷举探针作为产品实现：
  产品需要复用一次临时战斗实例逐帧查询，测量长准备期和长轴的成本，再接 UI。
- 不缓存“某干员固定多加 N 帧”；命中停帧和实际攻速属于具体战斗输入。

## 验收

- 佩丽卡与黎风：首段不移动，连续默认链的后续段无中断误报；每段提前一帧的反例
  保持有效。显示端点仅按真实投影与同轨裁切规则绘制，不参与合法性判断。
- 加入准备期、攻速变化、其他轨道终结技、既有技能穿插、轴末、条件未知、操作
  映射不匹配，以及撤销/重做、取消和异步过期结果。
- 原始场景保持不变；最终正式模拟的技能身份、时刻及诊断与规划一致。

## 2026-09-06 已接入的范围

- CombatInputRuntime 仅在临时实例显式启用 continuationPlan：固定首段，后续每实际帧
  最多消费一段；固定输入不移动，同干员其他作者输入插入时停止规划。
- ScenarioSimulationService.planSkillChain 复用正式模拟环境与原生操作映射/中断查询，
  一次临时运行后再以显式帧正式复跑，不将规划结果混入普通模拟缓存。未完成不返回
  部分改动的场景；UI 保留默认链并提示查看诊断，运行失败则不提交。
- 时间轴整链拖入和点击放置已接入。SkillPlacementTransaction 检查项目 revision、
  请求身份和取消状态；整链只提交一次撤销事务，单技能不规划。
- 黎风浏览器测试：首段 25，重击 92；命中点存在、无接续告警、块体相接，Ctrl+Z / Ctrl+Y
  一次移除/恢复整链。独立测试方案通过撤销清除，恢复原方案。
- 尚未完成：全干员/变体覆盖，攻速与跨轨组合的扩大验收；鼠标抓取时的静态总时长
  提示仍为未确定落点时的基础建议，不承诺与包含场景停帧的最终总长一致。未改变该提示
  的既有样式，不在每次鼠标移动时跑完整场景。后续需要单独设计低成本的预览刷新。

禁止使用统一常数、伤害裁切或屏蔽告警替代实际接续判断。
