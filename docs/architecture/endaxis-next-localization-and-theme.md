# Endaxis Next 本地化与主题边界

## 目标

Next 的渲染层需要同时支持更多界面语言、更多游戏内容语言和深浅主题，并满足以下约束：

- 存档、游戏定义、编译器和模拟器只保存稳定身份与数值，不保存翻译结果或主题颜色；
- 首次加载只请求当前语言资源，不能把全部语言静态打入首包；
- 游戏内容可以按 `operators`、`weapons`、`gears`、`enemies`、`terms` 分片准备；
- 语言切换必须原子完成，不能出现界面与游戏内容分属两种语言的中间状态；
- 组件只使用语义主题变量，不根据“深色/浅色”分支执行领域逻辑。

## 语言资源

### 资源族

界面文案和游戏内容保留不同的数据结构，但共用加载、缓存、回退和激活流程：

```text
locale
├── ui
├── operators
├── weapons
├── gears
│   ├── gearpieces
│   └── gearsets
├── enemies
└── terms
```

`gears` 对外是一个资源族，内部两张表必须同时加载成功后再注册。调用方不会观察到半套装备文本。

### 加载顺序

一次语言切换按以下顺序执行：

1. 标准化目标 locale；
2. 并行加载 UI 包和调用方要求的游戏资源族；
3. 所有资源成功后写入缓存并向 vue-i18n 注册 UI 消息；
4. 最后一次性更新当前 locale、`document.lang` 和本地设置；
5. 任一步失败都保留旧语言。

并发切换采用 latest-request-wins，较慢的旧请求不能覆盖用户后来选择的语言。

### 同步读取边界

现有 `getOperatorGameName()` 等读取函数可以继续保持同步，但调用前必须由页面或应用入口确保对应资源族已经准备。读取未加载资源时应抛出明确错误，不能退化为 humanized slug；后者会把加载竞态伪装成缺失翻译。

旧时间轴兼容阶段在挂载前准备当前语言的全部游戏资源族。Next 页面逐步改为按页面需求准备，例如干员选择器只要求 `operators`。浏览器已经加载过的模块无法卸载；“按需加载”约束的是首次请求和未使用语言，而不是强制清除浏览器模块缓存。

### 回退

UI 与游戏内容的回退分别配置。当前游戏内容映射为：

```text
zh-CN -> zh
en    -> en
ru    -> en
```

未来加入俄语游戏文本后只需把 `ru` 映射改为原生资源。UI 的俄语包目前并不完整，在关闭 vue-i18n 中文运行时回退前必须先补齐缺失键，或在构建阶段生成自包含语言包。

## 主题

主题只作用于 UI 根节点或全局应用外壳。组件依赖 `theme.css` 暴露的语义变量，例如：

- 背景与表面：`--ea-bg`、`--ea-workbench-panel`、`--ea-fill-soft`；
- 文本：`--ea-fg`、`--ea-fg-secondary`、`--ea-fg-muted`；
- 边界与阴影：`--ea-border`、`--ea-border-strong`、`--ea-shadow-strong`；
- 命令语义：`--ea-gold`、Element Plus 的 danger 等语义色。

组件不得硬编码只适合深色背景的遮罩、阴影或文字颜色。伤害元素、技能类型和用户自定义动作颜色属于领域或项目数据，不进入界面主题。

## 配置 UI 的调用边界

干员、武器和装备选择器在打开前请求自己的游戏文本资源族；目录对象只提供 slug、类型和数值定义。选择器返回稳定 slug，项目命令创建或更新 Build，渲染器再通过当前语言资源解析名称。主题切换不会触发项目更新、历史记录或战斗重算。
