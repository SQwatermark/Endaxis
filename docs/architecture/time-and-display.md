# 时间、变速与显示

项目直接保存用户安排的实际战斗帧。时间冻结或变速改变各对象在每帧消耗的局部时间，
不会把项目中的后续技能自动右移，也不需要先保存另一套“逻辑帧”再换算显示坐标。

## 战斗帧与局部时间

[CombatClock](../../src/core/combat/runtime/combatClock.ts) 以30 FPS推进整数战斗帧，
不使用电脑的墙上时钟。技能、Buff和冷却按各自规则消费时间增量，因此同一战斗帧内，
一个对象可以暂停，另一个对象继续推进。

[TimeDilationRuntime](../../src/core/combat/runtime/timeDilationRuntime.ts) 管理全局和实体倍率、
槽位竞争、优先级和时间实例寿命。它提供时间增量，不替技能或Buff决定该使用哪种时钟。
能力系统区分原始、全局变速、自身变速和技能冷却四路增量，调用者按对应规则使用。

曲线、标签和槽位配置属于版本化游戏数据。命名曲线与内联曲线只是来源不同，不能据此判断作用范围。
缺失配置应明确报错，不能补上旧版的固定冻结秒数。游戏依据见
[槽位与曲线研究](../research/combat/time-dilation-slot-and-curve-config.md)。

## 哪一层负责什么

- 定义和编译器保留有证据的变速动作、目标与参数，不修改其他技能的放置帧。
- 运行时创建、替换和结束变速实例，记录来源及实际发生帧。
- 显示层读取这些记录，绘制技能块和命中；不重新计算槽位竞争。
- 只有作用范围为全局的时间膨胀才在时间轴上显示区间、高光和悬停联动。实体级时间膨胀
  仍按原规则参与模拟，但在时间轴上没有特殊显示和交互。
- 终结技时间膨胀必须保留这些特殊效果。运行时将它记录为全局实例，槽位为 `ultimate`，
  因而与其他全局实例走同一条显示投影，不需要按干员或技能写特例。
- 编辑操作保存用户选择的战斗帧，不把显示宽度或变速区间写回技能定义。

持续动作的执行器必须转发不属于自己的 `execute`、`evaluate` 和 `end`。
漏掉结束调用会导致变速实例无法按动作生命周期清理。

## 技能块宽度从哪里来

定义中的 `timelineBlockFrames` 是局部显示边界，既不是技能自然寿命，也不能直接表示变速后的实际宽度。
[SkillOperableBoundaryRuntime](../../src/core/combat/runtime/skillOperableBoundaryRuntime.ts)
累计施法者变速后的局部帧，到达边界时产生一次记录。此跟踪独立于技能是否自然结束，
也不能替代下一技能的输入路由或中断判断。

[显示投影](../../src/ui/timeline/timelineDisplayTime.ts) 配对 `SkillStarted` 与
`SkillOperableBoundaryReached`，得到实际宽度。边界是在本帧输入结束后的技能更新阶段观察到的，
因此显示区间覆盖到下一输入边界，宽度计算包含这一个帧间隔。

没有边界记录时，投影不编造结果，界面使用定义宽度作为保底显示；这不代表已经验证了实际宽度。
中断记录可用于裁切技能块，但不能据此取消独立存在的Buff或投射物。
技能自然结束、可操作边界和投射物回收的区别见 [技能定义、编辑与执行](skills.md)。

## 变速区间和结果有效性

显示层将全局变速的开始与结束记录按实例配对。仍未结束的实例只绘制到本次模拟终点，
重复开始或缺少开始记录等损坏数据应报错。来源技能内部的全局区间按实际重叠部分裁切，
不能把多个变速实例合成一个从技能起点开始的固定动画长度。

命中、资源和状态显示使用模拟记录的发生帧。编辑后需要检查结果版本和取消状态，
避免把上一轮模拟结果当作当前输入的结果。

旧版双坐标与冻结带设计保存在 [历史稿](../archive/next/history-time-freeze-and-projection.md)，
其中的时间映射和未完成事项不再作为当前开发要求。
