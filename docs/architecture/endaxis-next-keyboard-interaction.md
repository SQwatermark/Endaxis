# Endaxis Next 按键交互架构

## 目标

新版不允许各组件随意向 `window` 注册快捷键。所有页面级快捷键通过统一路由器按当前交互作用域分发，确保弹窗、菜单、输入控件和时间轴之间不会发生按键穿透。

## 作用域层级

由高到低建议使用以下优先级：

1. 模态弹窗和需要独占输入的浮层。
2. 右键菜单、下拉菜单等临时操作面板。
3. 获得焦点的编辑面板，例如属性编辑器、技能编辑器。
4. 时间轴编辑器。
5. 页面全局命令。

同一时刻可以有多个活动作用域，但只有最高优先级且愿意处理该按键的作用域执行命令。独占面板即使不处理某个按键，也可以通过 `blockLowerScopes` 阻止按键落到下层编辑器，同时保留输入框自身的浏览器行为。

## 当前实现

`src/next/ui/keyboard/keyboardShortcutRouter.ts` 提供：

- `KeyboardShortcutRouter`：按优先级排序和分发按键，核心逻辑可以脱离 DOM 测试。
- `useKeyboardShortcutScope()`：在 Vue 组件作用域内注册，并在组件销毁时自动注销。
- `isTextEditingTarget()`：识别输入框、下拉框和可编辑文本，避免抢走原生复制粘贴。

时间轴目前注册两个作用域：

- `next-timeline-overlay`：弹窗或右键菜单打开时阻断时间轴快捷键。
- `next-timeline-editor`：没有上层面板时处理动作复制、粘贴、撤销、重做、删除、位置微调、吸附精度、光标辅助线和轨道循环切换。

旧版 `src/utils/shortcutScope.ts` 仍服务旧页面，其中包含扫描 Element Plus DOM 的临时兼容逻辑。Next 不依赖该模块；旧页面迁移完成前两者会并存，但新增功能应接入新的注册式路由器。

## 接入规则

- 组件只声明自己负责的命令，不直接依赖其他面板的 DOM 结构。
- 判断作用域是否活动应使用响应式界面状态，不依赖 `document.querySelector()` 猜测弹窗是否存在。
- 文本输入控件保留操作系统和浏览器的 `Ctrl/Cmd+C`、`Ctrl/Cmd+V` 等默认行为。
- 只有命令确实执行时才调用 `preventDefault()` 和 `stopPropagation()`。
- 弹窗内新增快捷键时，应注册更高优先级作用域，而不是向时间轴处理函数追加弹窗特例。
- 快捷键只负责调用应用命令；撤销历史、文档修改和选择状态仍由各自模块维护。

## 后续迁移

吸附精度和光标辅助线可见性都是 UI 会话状态，不进入存档。精细吸附为 1 帧，粗略吸附为 0.1 秒；当前固定 30 FPS，因此粗略模式对应 3 帧。技能库放置、动作拖拽和位置微调必须共用该规则；`Ctrl+G` 与工具栏按钮共用辅助线开关。`Tab` 与 `Shift+Tab` 只循环已有干员的轨道，不会打开空轨道的选择弹窗。F1-F4 和框选辅助键等旧版快捷键迁入新版时，应逐项注册到对应作用域。待面板焦点模型完善后，可以在路由器之上增加“最后聚焦面板”状态，但不应改变现有的优先级和阻断语义。
