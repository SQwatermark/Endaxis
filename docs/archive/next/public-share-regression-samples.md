## 读取链路与证据

- 页面及公开构建模块可正常 GET；前次浏览器超时不代表没有公开数据。
- 页面构建 `index-Vz8no3YH.js` 引用 ShareSquare/ShareDetail，二者引用
  `shareStore-DZiF7CCR.js`，明确使用 `GET /api/shares` 和 `GET /api/shares/:id`。
  本次只调用公开读取路径，没有登录、点赞、复制到账号或发布。
- 详情的 `shareCode` 是 base64url + gzip + JSON；依据旧源码
  `src/utils/gzipUtils.ts` 与 `src/stores/timeline/persistence.ts`，不是猜测压缩格式。
- 上游只读工作树 `D:/Projects/Endaxis-upstream-main`：
  `src/utils/timeSerialization.ts` 仅在 `timeUnit === 'frame'` 时按存档 FPS 还原秒；
  没有标记则保持旧值。新版 `src/core/project/schema.ts` 使用 30 FPS。
- 旧 `src/stores/timeline/shifts.ts:refreshAllActionShifts` 从 logicalStartTime
  和连携/终结技演出推导 startTime；还有 compiled timeContext，不能仅比较字段名就
  宣称已经还原屏幕真实时间。样本中庄方宜终结技为 343 / 413（60 FPS），说明差异实际存在。
- 新 `src/core/project/serialization.ts` 目前识别并拒绝直接加载 legacy 文档。
  本次不改变该边界。

## 下一步使用顺序

1. 先重放低星碎冰轴，按旧源码定位普通技能身份及显示时间；抽取一个短片段在新版
   原生模板下重建，检查状态转换、伤害节点和操作衔接。比较流程和可见事实，不要求总伤害一致。
2. 再使用莱万汀与庄方宜样本检验强化入口、连续分段和演出占用。历史 `_variant_` ID
   可能对应人工修改内容，不能按名称或 ID 尾号直接映射原生技能。
3. 若抽取自动化有价值，先做只读审计/显式映射的测试夹具构建器，输出未映射清单。
   只有能保留放置语义、养成和配装身份时才考虑用户可用的升级组件。

旧存档中的 damageTicks、physicalAnomaly、stats、weaponAppliedDeltas 等是旧定义或
派生/编辑数据，不能整体塞入新版模拟。应使用当前游戏模板重算，人工自定义与未识别
内容必须单独标明，不能静默丢弃后仍称“完整转换”。

## 2026-09-06 低星动作序列首轮重建

只供回归测试，不在生产导入入口使用。陈千语 basicAttack_seg1…5 对照当前定义明确
对应 basicAttack1…5；四名干员战技/连携使用当前同语义技能键，不解析历史 variant ID。

- 35 个动作全部保留，按 `round(sourceFrame / 60 * 30)` 定位，9 个坐标发生量化，
  最大误差 1/60 秒。每个坐标保留源帧和误差，未隐瞒取整。
- 当前模板、统一 90 级/技能 12、零潜能、无武器装备/天赋的测试配置；没有复制原轴
  派生面板、伤害/效果列表，也没有迁移罗丹目标或旧原生时间计算。不是伤害对照基线。
- 完整模拟成功且输入 JSON 不变；产生冻结反应伤害，真实实例可对应可见持续段。
- 本次观察到 4 次不可中断、3 次连携窗口不可用、2 次技能冷却不可用告警。
  不把这些数量锁为正确性断言：养成/配装、原生规则与旧版时间表达均可能改变它们。
  也不因告警移动、删除技能或拒绝重建。
- 尚未进行旧版浏览器重放和逐块屏幕坐标比对；本次证明的是公开动作模式可用于
  当前模拟/投影回归，不证明新旧施放时刻/伤害完全一致。
  已读 `simulation/compiler/compileTimeline.ts:resolveAction`：它还会从 action.startTime
  根据 stopSources/sourceShiftMap 算 realStartTime，因此即使存档的两种 startTime 相等，
  也不能推断与最终屏幕时间相等。本夹具明确重放存档坐标，而非声称还原最终旧版轴。

## 2026-09-06 直接执行旧编译器的时间探针

只读使用上游 `4dadc55f2b54cfe621ed8641fc4be9e1e4269dfc` 的真实
`deserializeProjectData` 和 `compileTimeline`，没有另写一套模拟其时间规则。
临时 esbuild harness 位于 `tmp/audit-legacy-display-time.mjs`；产物和结果均在 tmp。
探针输入保留原动作时间/时长/类型，但 hits 置空，因此只检查时间编译，不代表命中、
效果或伤害复现。i18n 被设置为调用即抛错的端口，未参与计算；旧工作树未修改。

| 方案                      | 块数 | 起点仅发生毫秒取整 | 超过 1ms 的起点位移 | 旧编译器截断块数 |

| 猛击控制轴                | 35   | 23                 | 0                   | 3                |

最大起点差约 0.000333333 秒。结论限于这些样本：已有 startTime 再经此编译器没有
明显追加推移；不能推广为任意旧存档的逻辑时间都可直接使用，也没有覆盖旧 store
加载后的自动刷新/模板覆盖，更不等同于浏览器完整重放。

低星轴 943/60 和 1390/60 秒开始的第二段普攻被旧编译器裁为 0.366 秒，原时长
22/60 秒在其 round(…,1000) 下为 0.367 秒；邻接第三段起点又向下取整。这类
1ms 数值伪截断不作为新版的模拟或显示目标。436/60 秒开始的重击则有真实的后续
战技重叠，二者不能混为同一种问题。

新版回归保留原始整数帧后直接量化，不能先经过旧版毫秒显示值：623/60 秒按 30 FPS
应取 312 帧，若先用旧编译结果 10.383 秒再取整会误取 311 帧。新增专门回归断言。
下一步可对低星片段进行浏览器层面的新旧状态排版核对，不复刻上述数值伪截断。
