# Buff 周期触发实验与基线噪声对照

**不修改生产算法。** 两个独立候选的收益尚未被当前测量精度证实，不能称为加速，也不能据此断言没有效果。相同基线的 A/A 对照用于检查测量噪声；随后先改进测量并校准，没有继续堆叠局部候选。

生产基线为 `16bd46e09adff8f581cbe5f28956eaf6bafcfe44`；实验从仅增加研究文档的 `57005ee0a35c1a0d2e7fdb20a7eee4de5a21738b` 建立隔离工作树。两个候选均已撤回，没有缓存、调度器、专属 Buff 规则或产品行为变化。

## 先确认每帧工作及状态归属

沿用普通模式的生产 SSR CPU 采样，Buff/时间相关函数的合计 self 样本占稠密轴约 17.06%、电队约 19.95%。这不是全部可节省时间，也不能与调用次数直接换算。`CombatBuffContainer.tick` 必须按当前成员数组遍历；每个未暂停、未结束实例都会增加可保存的 `passedTime`，之后还有周期、持续动作、增长与寿命处理。

另在构建时注入只计数的探针，各跑一次完整模拟，不使用这些运行的耗时：

| 项目                           | 稠密 104 块 `6aba2a…` | 电队 39 块 `6a91c4…` |
| ------------------------------ | --------------------: | -------------------: |
| 实例 tick 调用                 |               160,822 |              176,717 |
| 入口已经结束                   |                   206 |                   64 |
| 入口暂停                       |                     0 |                    0 |
| 入口启用                       |               149,716 |              156,508 |
| 入口有限寿命                   |                90,841 |               89,673 |
| 周期触发端口构造表达式到达次数 |               150,268 |              156,751 |
| 其中次数耗尽或没有周期         |     147,246（97.99%） |    148,726（94.88%） |
| 回收阶段检查 / 实际结束        |         160,870 / 474 |        176,767 / 233 |
| 属性详情捕获调用               |                 1,974 |                  930 |
| 属性详情扫描槽 / 输出行        |      169,752 / 21,219 |       33,024 / 4,128 |

端口调用包含启用时的立即检查，因此不等于 tick 数。构造表达式次数也不等于 V8 实际分配的对象数量或字节。本轮没有用分配采样验收候选，不能声称堆分配减少了某个比例。

**95–98% 周期检查没有工作，不代表 95–98% Buff tick 可以跳过。** `passedTime`、寿命、当前许可状态和同步回调顺序仍必须保留；这排除了按定义静态跳过实例。回收比例低同样不能直接推出可跳过扫描，结束状态对外暴露为可变数据。

属性详情必须读取实际注册的修正器身份，再与 Buff 当前修正器相交。替换修正值、直接状态修改和切面恢复都使“按启用标记推断”或持久详情缓存不等价。详情还必须保留 Buff、修正器、own 槽位顺序及新建结果的隔离性，本轮没有为此增加索引或特殊分支。

## 两个独立候选

1. **实例级绑定周期触发端口。** 将 `triggerInternal` 每次创建的对象和两个闭包改为实例私有字段；回调仍读取当前状态与定义，不进入切面数据。没有改变周期算法或调用顺序。但它给无周期实例也增加了长寿命端口对象，必须以端到端测量判断取舍。
2. **当前触发状态的提前返回。** 保留原临时端口，仅在构造前检查 `remainingCount === 0 || intervalSeconds === null`，与 `advanceBuffTriggers` 的原有首个返回完全一致。仍执行其余 tick 工作，保留负数无限次数、直接状态变更、恢复和同步重入；原底层检查也保留供其他调用者使用。没有与第一种候选叠加。

第二种候选的电队变化随版本顺序反号，不能挑较快轮次或用跨轮平均掩盖。实例端口的稠密 CPU 也没有显示节省。现有证据不足以接受其中任何一种生产改动。

## 相同基线 A/A 对照

两份源码恢复为同一基线后，沿用相同四轮协议。源码指纹相等，**全部 403 个可执行 bundle 文件逐字节相同**，没有真实实现差异。

| A/A 指标              | 稠密              | 电队             |
| --------------------- | ----------------- | ---------------- |
| 四轮墙钟变化范围      | −5.59% 至 +9.47%  | −6.60% 至 +7.49% |
| 墙钟变化绝对值中位数  | 3.84%             | 5.94%            |
| 四轮 CPU 变化范围     | −7.09% 至 +12.24% | −6.29% 至 +6.18% |
| CPU 变化绝对值中位数  | 4.08%             | 5.40%            |
| 配对墙钟几何均值变化  | −0.05%            | −0.83%           |
| 配对墙钟近似 95% 区间 | −4.55% 至 +6.46%  | −5.94% 至 +4.57% |

区间按每轴 **4 个配对进程中位数的对数比值**进行百分位 bootstrap，枚举全部 4⁴ 个重采样组合；不把进程内 20 次测量冒充 20 个独立进程。四对样本很少，不能据此给出精确最小可检测收益。A/A 的区间覆盖零不等于已经具有高精度，其单对变化已与候选效果相当。

当前状态返回候选的配对墙钟估计为稠密 −1.03%（近似区间 −5.15% 至 +3.15%）、电队 −3.08%（−9.59% 至 +3.90%），均跨零。实例端口的稠密 CPU 在本次候选配对里稳定偏慢，但 A/A 同样存在显著跨进程波动；不能把局部区间当成普适精度保证。

**本环境与当前协议尚不能证明能稳定分辨几个百分点的收益。** 未证实收益不是零效应证明；也不应因小候选反复反号就断言所有这些方向无效。A/A 没有证明所有波动都由顺序引起，候选中的顺序相关迹象仍要求控制。

后续先改进测量：

- 采用较短固定块内的随机、平衡 A/B 顺序，明确每个进程对的边界，避免连续跑完一类后再跑另一类
- 把 A/A 对照嵌入同一测量批次，记录共享宿主干扰；有条件时使用隔离资源
- 预先规定热身稳定窗口与停止条件，按进程对计算区间，不能仅增加同一进程内重复次数
- 先证明测量能分辨目标幅度，再评估新候选；顺序反号时不选择较快顺序，也不用平均值隐藏它

改进工具与校准结果见下一节；没有新增优化候选。

## 随机平衡短块校准

新增可复用的[独立进程配对校准工具](../../tools/performance/README.md#小幅变化的独立进程配对校准)，然后只做了一批相同源码校准，没有直接重试候选：

- 同一 bundle 路径和可执行字节，两个标签各自启动新进程，避免同进程跨版本的 V8 优化状态互相影响
- 种子 `20261001`；每轴六对，每轴 AB/BA 顺序各三对，轴和组顺序随机平衡；每进程固定五次测量
- 冷首跑后热身至少八次、最多二十次；最近两个四次窗口的墙钟/CPU 中位数比须在 `[1/1.03, 1.03]`，各窗口相对 MAD ≤5%，连续两次满足。相邻判定重叠，这只是有界启发式，不是两次独立确认或 JIT 稳态证明
- 预声明准确度门槛：每轴墙钟、CPU 的配对进程近似 95% 区间均包含 1 且完全位于 `[1/1.03, 1.03]`，所有进程通过暖态规则。整批预算 900 秒，不重试或追加样本

**24 个进程全部完成，但仅电队的 2 个进程在第 20 次热身达到启发式；其余 22 个耗尽上限。** 共 480 次热身、120 次正式测量、24 次冷首跑。失败暖态块没有丢弃，按原计划完成全部六对，均明确标为不可用于候选推断。输入、完整 Worker 结果、有序回执、源码和 bundle 核验通过；退出码 2 表示敏感度未建立，不是正确性失败。

| 轴   | 暖态通过 / 进程数 | 墙钟 B/A 变化的诊断区间 | CPU B/A 变化的诊断区间 |
| ---- | ----------------- | ----------------------- | ---------------------- |
| 稠密 | 0 / 12            | −6.25% 至 +3.48%        | −11.31% 至 +7.76%      |
| 电队 | 2 / 12            | −12.52% 至 +11.00%      | −12.65% 至 +11.08%     |

这里采用六对进程中位数对数比的 Student-t 近似区间；由于暖态不合格，只能作为诊断，不能宣称已测得候选的真实效应。新旧协议的批次发生在不同时间，也不能由区间宽度比较断言工具让性能变好或变差。

**本次改进仍未建立 3% 分辨能力，按预声明规则停止；没有重测提前返回候选，没有增加预算。** 因而此前几个百分点的变化继续属于未证实，不能写成这些候选已被证明无效。工具把测量顺序、条件、失败块和不确定性显式保留下来，便于在更可控环境中复核。

残余波动不能全部归因于共享宿主：普通模拟的 JIT/GC、测量后的 Worker 结果投影、结果/输入哈希、每轮报告写入以及运行环境都可能影响下一轮。它们虽在计时外，仍会改变后续堆和系统状态；本轮未分解各自贡献。

工具专项 5/5、性能工具类型、生产 SSR 构建烟测通过。`npm run type-check:tools` 全部工具类型检查、语法/格式及 `git diff --check` 通过；没有将工具检查冒充战斗内核全量验收。

## 方法与验收范围

2026-10-01，Node 24.19.0 / V8 13.6.233.17-node.51，AMD EPYC 9V74，共享云环境。全部重型本地任务串行；不保证宿主机器独占。

每项实验采用相同协议：两轴、四轮、每版本每轴独立进程；每进程冷首跑一次、热身五次、正式二十次。奇偶轮逆转轴顺序，版本顺序按轴和轮次交替。两候选及原协议 A/A 合计 48 个进程、960 次正式测量，含冷首跑和热身共 1,248 次。普通回执，清理每轮服务缓存并关闭切面复用；不可变定义缓存保留产品正常寿命。构建、加载、哈希、复制和语义验证不进入正式服务计时。原始证据保留每次计时、p95、CPU user/system、环境、输入/源码摘要。

- 所有计时运行检查输入、完整 Worker 结果和有序回执摘要；跨版本、跨轮一致
- 当前状态返回候选通过 Buff 专项 22 文件 / 348 项，含一个临时回归：空周期之后直接改变当前触发状态，再验证同步重入停用与保存恢复的独立实例。实验测试随候选撤回，完整源码保存在压缩证据中
- 两个候选均未进入六轴完整状态、逐帧 HUD、切面及全量应用 tests/types/build 的接受阶段，不能称已完成生产验收
- 本轮没有重测伊冯轴 126/127 帧的已知 `missing projectile reset handler 0`，不能把未运行写成通过
- 没有引入 CombatSpec 运行时或测试依赖；最终提交只含离线测量工具、工具测试、说明与压缩证据，生产模拟代码未改变
