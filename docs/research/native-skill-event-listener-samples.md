# 原生技能事件监听样本

## 目的

本文盘点当前 `SkillData` 中由技能时间线注册的 `EventListenerAction`。这些监听器只在外层动作的
`startFrame` 至 `endFrame` 区间内有效，技能结束或中断时注销。它们不等同于常驻的天赋、潜能、
武器或装备触发器，也不能提升为技能起始帧上的无条件动作。

数据范围为当前生成审计中的 29 名干员、308 个入口技能。共发现 8 个技能、10 个监听器。

## 中间层现状

`SkillEventListenerSource` 保留注册区间、事件名和响应序列。每条响应序列同时保留：

- 原始动作类型摘要，供覆盖审计和未知动作诊断使用；
- 可解析的 Buff 应用摘要，供依赖收集使用；
- 完整的有序 `actions` 控制流树，供后续生成正式 DSL 使用。

`actions` 复用普通技能的条件与叶子动作中间模型。位于同步序列中的检查会作为顺序守卫包住其后的
动作，因此 `CheckDamageDecorateMask -> CompareFloat -> CreateBuffAction` 不会被错误展开成三个互不相关
的动作。原生伤害掩码在中间层继续以 `checkType + mask` 原样保存；进入 DSL 时，只转换已经由反编译枚举和
全量数据交叉确认的位，出现未知位会立即报错。
`CheckBuffIdInContext` 同样保留事件上下文中的 Buff 身份，不混同于查询目标身上的 Buff 实例。
监听动作自身的 `priorityLevel/priorityOffset` 也会原样保留；当前 10 个样本均为 `Default/0`，在尚未确认原生优先级枚举映射前不转换成运行时排序值。

原生掩码混合了两类含义，不能全部塞进 `DamageTag`：

- 技能分类写入 `DamageTag`，例如普通攻击、普攻末段、战技、连携技和终结技；
- 伤害行为写入 `DamageFeature`，目前确认了可破弱、碾压、击飞、持续伤害和残留区域。

`CheckDamageDecorateMask` 会按这两组属性生成 `eventDamageTagsMatch`、`eventDamageFeaturesMatch`，必要时
再用 `all`、`any` 和 `not` 还原原生组合规则。普攻末段是普通攻击的细分类：技能入口声明普通攻击即可，
实际命中仍同时保留 `normalAttack` 与 `normalAttackLastCombo`。

## 转换顺序

1. 先补齐事件负载模型：受击前、添加 Buff、击杀后、技能结束前后和击飞输出前。
2. 让伤害、Buff、生命值和技能生命周期运行时在原生顺序点派发这些事件。
3. 补齐可复用动作：动态黑板修改、内联 Buff 应用与结束、冷却修改、技能内跳转。
4. 继续将可证明的中间层动作树编译为 `listenForCombatEvents`，对未知事件、条件和叶子动作严格失败。
5. 逐个解除剩余入口技能的 `event-listener` 阻塞，并用全量生成审计确认覆盖率提升。

其中技能内跳转会改变当前时间线游标，不能用“立即执行一个普通序列”近似。洛茜的 `OnSkillEnd` 也
不能先做成无负载的通用结束通知，因为原始 `FinishBuffAdvanced` 读取的是该结束事件携带的 Buff 上下文。
