# 初次 Reset 延迟绑定实验：未保留

**结论：撤回候选，不修改生产执行器。** 对能证明没有准备副作用、始终无内部状态的叶子，延后创建操作对象确实减少了构造次数；但两个真实长轴的完整服务耗时没有稳定改善。不能把少创建对象直接解释成加速，也不因此扩大豁免规则。

基线为 `41396fd94850dd61ab93e6fa483b9f344312a612`。实验仅使用已提交的[公开轴夹具](../../tools/performance/fixtures/public-timelines/README.md)，首个独立方案、原统计结束线、普通回执模式。未添加角色、技能、Buff ID 特例，未缓存最终计算值，未改变战斗输入或规则。生产源码和实验测试均已恢复到基线，只保留本报告与精简证据。

## 为什么不能直接省略初次 Reset

[图执行器](../../src/core/combat/actions/actionGraphExecution.ts)的 Reset 不只是把生命周期写成 pending：

- [叶子操作](../../src/core/combat/actions/combatActionSequenceRuntime.ts)的 Reset 会调用完整宿主准备路径；[攻击快照](../../src/core/combat/damage/playerDamageOperationExecutor.ts)必须在当时捕获，不能延到 Execute
- [条件和 Switch](../../src/core/combat/actions/branchActionExecution.ts)重置尚未选择的分支，内联 guard、宏和外部资源也有自己的子执行边界
- 监听、作用域、重复动作和目标循环拥有不同状态；已有实例的清理、同步回调以及恢复绑定不能跳过
- 尚未执行的节点仍保存在切面中，End 也会把它们标为 ended。删除它们会改变中间状态，不能只用最终伤害相等证明正确

## 被拒绝候选的具体边界

候选保留原图遍历和所有节点数据、生命周期、操作身份目录。仅在初次 Reset 创建叶子绑定时，允许宿主明确声明下面三项同时成立：构造无外部效果；整个生命周期的数据都是 `stateless`；未执行前的准备路径始终无效果。未声明时走原路径。

符合条件的叶子用共享方法的轻量包装保存原数据，第一次执行才创建原操作对象；一旦创建，后续 Reset/Tick/End 仍调用原方法。直接 Execute 创建和切面恢复保持即时绑定。持有登记、Buff 引用或攻击快照的动作，以及控制节点均不进入此路径。

准备能力只沿原来实际调用的链传播：装配层的 `withTerminalPreparation` 本来就只调用终端 Prepare；Heal、KnockDown 的 Prepare 本来只转发；PlayerDamage 对非攻击快照动作原本立即返回。未覆盖的执行器和动态回调包装保守保留原实现，没有为了扩大命中率给全部装饰器追加规则。内联宏使用同一个参数替换对象和调用位置身份。

这不是“跳过节点遍历”的实验：图绑定、状态和枚举都还在，省下的是部分叶子操作对象与原逐叶闭包。

## 完整服务筛选结果

2026-10-01，Node 24.19.0 / V8 13.6.233.17-node.51，AMD EPYC 9V74，共享云环境。本地重型任务串行，未控制宿主调度或频率。

生产 SSR，通过 `createScenarioSimulationService(repository, false, 'standard')`，每次清服务缓存、关闭切面复用，保留不可变定义缓存的正常寿命。每个版本、每轴、每轮独立进程：冷首跑 1 次、热身 5 次、正式 20 次。第二轮反转轴顺序和成对版本顺序。下面是完整服务暖态中位数，正值表示变慢；构建、加载、验证、哈希和复制不在此计时内。

| 轴              | 第一轮：基线 → 候选 ms |   变化 | 第二轮：基线 → 候选 ms |   变化 |
| --------------- | ---------------------: | -----: | ---------------------: | -----: |
| 提决佩洁 104 块 |        328.49 → 346.69 | +5.54% |        343.25 → 346.88 | +1.06% |
| 别汤赛决 75 块  |        254.11 → 250.63 | −1.37% |        223.14 → 244.86 | +9.73% |

稠密轴两轮均未改善，别汤赛决只有一轮轻微下降。每种工况只有两个独立进程，进程内重复不等于独立样本；不由这些数字归因具体 JIT、GC 或分支成本，也不将第二轴的单轮下降当作收益。

## 操作对象减少，但图绑定没有减少

另外构建仅计数的版本，每轴、每版本独立进程，运行一次冷模拟和第二次完整模拟。两次计数一致；计数运行的耗时不纳入性能证据。

| 轴       | 图绑定创建，前后相同 | 叶子操作对象：基线 → 候选 |         少创建 | 候选延迟包装 |
| -------- | -------------------: | ------------------------: | -------------: | -----------: |
| 提决佩洁 |               10,141 |             5,301 → 3,154 | 2,147（40.5%） |        3,517 |
| 别汤赛决 |                3,296 |             2,002 → 1,536 |   466（23.3%） |        1,137 |

“叶子操作对象”计数位于实际原操作构造入口；延迟包装有自己的对象，不等于零分配。图绑定数包含控制节点，不能与叶子操作对象相加或相减后当作总分配量。没有测量分配字节、同时存活峰值或可回收内存，也没有减少静态图、生命周期次数或节点枚举。

## 正确性与验收范围

- 8 个无插桩进程的 208 次完整服务运行，输入、方案、游戏数据、完整 Worker 结果和有序回执 SHA-256 全部一致；160 次为正式计时样本
- 两轴逐项深比较完整结果、完整状态、逐帧 HUD、被动 UI 曲线和 Buff 时间段，与基线相等。另做保留 Map/Set 顺序、对象别名、非有限数和负零的确定性图摘要，两版也相等
- 选定事件边界及轴中点共 11 个切面点，两版全部分叉恢复并续算通过；不是所有帧的穷举恢复
- 原生 Endaxis 定向测试 6 文件、123 项通过，包括 2 项新对照测试，覆盖内联宏、未执行叶子的 End/Reset/恢复状态、未选分支攻击快照时点、持有登记的动作与未知准备路径。没有依赖 CombatSpec
- 应用类型检查默认 2 GiB Node 堆耗尽；使用 `NODE_OPTIONS=--max-old-space-size=4096 npm run type-check` 重跑通过。修改文件格式与 `git diff --check` 通过
- 因性能筛选失败，没有扩大到六轴语义验收、全量应用测试、生产构建或浏览器交互验收。这里的 HUD 投影相等不能替代浏览器交互测试

候选与实验测试已撤回。下一步若研究阶段专用遍历计划，应独立证明哪些节点在该阶段没有状态写入或实时宿主检查；不能从本实验推导出可以删除 Reset、Tick 或 End 节点。
