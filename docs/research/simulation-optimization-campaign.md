# 模拟热路径第一轮优化

目标是降低同一套 v3 规则、数据和输出下的完整重算成本，不追数值与旧版对齐，也不承诺回到旧版耗时。基线为 `483f437aedd539b034618747030659afa8a517af`，使用独立只读工作树，当前分支不切换。

## 计划与验收

1. 先索引技能可用性诊断所需的详情回执，消除每条诊断全量扫描。索引只在一次投影内存活；重复序号和乱序输入仍取原输入中第一个对应事实，不能改成最后覆盖或按序号排序。
2. 单独实验 Buff 添加冷却及局部时间倍率的临时数组消除。保留冷却阈值、旧数组隔离、成员变更的同步可见性、时钟推进和浮点乘法顺序。
3. 只有前两项不足且能证明重入安全，才考虑图遍历绑定复用；本轮不重写图生命周期，不改变同步 End/Jump、宏内联和来源身份。

每项单独测量和提交。六条已提交的公开轴、18 名干员使用同样生产 SSR 构建方式及正式服务入口；禁用切面复用并逐轮清服务缓存，定义缓存保留产品正常寿命。每轴基线与候选各一个新进程，相邻轴反转顺序；冷首跑单列，再热身 3 次、正式 20 次。逐次验证完整 Worker 结果、有序回执与输入摘要一致。主要轴补反向独立进程验证，避免把共享云噪声当作收益。

不得删回执、诊断、字段、冻结、tick 或数值规则。相关专项与恢复/分支测试、全量类型/应用/编译器/工具测试及生产构建必须通过。最终有意义的组合复采稠密与电队 CPU/分配；采样耗时不作为性能基线。短命索引与数组的分配流量不等于存活堆，不以持久缓存换速度而不披露其所有权与寿命。

## CPU 与分配复采

稠密、电队均沿用优化前工具：每模式两次独立进程，5 次热身、12 次采样模拟，第二轮倒转 control/CPU/allocation 顺序；共 12 进程、204 次模拟。输入、完整输出、有序回执摘要与优化前逐一一致。采样配置及限制见[优化前热点](simulation-profile-hotspots.md)，复采的[机器摘要](simulation-optimization-profiles.json)保留全部采样轮计时与前 40 个 self 热点，原始 traces 和 source maps 不入库。

| 轴   | 优化前估算分配 MB/次，两进程 | 最终版 MB/次，两进程 | 均值下降 |
| ---- | ---------------------------: | -------------------: | -------: |
| 稠密 |                352.7 / 353.4 |        341.7 / 342.3 |  约 3.1% |
| 电队 |                274.6 / 275.8 |        258.5 / 259.0 |  约 6.0% |

这是 V8 统计估算的分配流量，包括采样期间已回收对象，既非精确对象数量，也非存活堆或峰值。没有强制 GC；没有宣称内存占用下降相同百分比。最终优化没有新增长寿命缓存：诊断索引只在一次投影调用内持有；冷却仍创建新的结果数组以隔离旧引用；倍率循环不持有额外对象。未保留的图适配器常驻对象不在最终版中。

两个轴的诊断全历史筛选回调已不再进入 CPU self 前 40，局部倍率函数也不再进入分配 self 前 40；这不表示零成本，也不能把 source map 的入口归属当作精确分配行。图 generator、节点绑定、Buff tick 与不可变程序检查仍是大头。稠密 GC self 份额从 5.97–8.05% 到 5.52–7.09%，区间重叠；电队从 5.78–6.25% 到 4.43–5.72%。只据此不能精确解释墙钟改善。

采样会明显扰动耗时，分配模式更甚，所以性能收益只使用上一节无采样的同批交替基线，不用本节采样耗时替换。旧热点采样与此次复采不是同一组时间对照，比较的是相同输入/输出下的分配与采样归属。

## 下一步边界

本轮到此停止扩大改动；后续改变回执合同的实验应单独记录，与此处逐位输出等价的优化分开验收。优先研究不可变程序的只读结构访问，减少 `rootActionSteps` / 兼容检查的反复物化，但不能缓存一个忽略 flags、截止和定义覆盖的“通过”结果。图适配器复用已得到负面实验结果，不能再把“少建对象”直接当作更快；更大遍历改造需要独立方案和重入/宏/结束/恢复验收。删回执或降低诊断粒度会改变本轮的完整输出合同，不属于这些优化。
