# 真实轴暖态 CPU / 分配热点

这次只做剖析，没有改生产代码。两个独立进程的模式一致：时间分散在逐帧图执行、Buff、伤害属性/来源明细、回执与诊断投影，没有发现一个能单独解释 v3/旧版差距的函数。优先尝试减少重复遍历和临时对象，同时保留所有战斗规则、回执与恢复语义。不能据此保证恢复旧版耗时。

## 样本与方法

- 稠密轴：`6aba2a13c9fb961339acd766`，104 技能块，截止 2481 战斗帧
- 电队：`6a91c4241854aefb13172209`，39 技能块，截止 3600 战斗帧。它不是伊冯碎冰轴 `6aa952…`
- 测量 checkout：`f471df1630d0a1fa4d3dce14a1dc175f8cc9a6ae`；引擎最后修改 `62a48ec156225d9a334b7121e5acf002a1ebdb42`，游戏数据提交 `f1bc5af07a49046a3a1c6132094e27aa763d7539`、revision `1.5.3@10506507-7`。生产目录和锁文件无 diff，工具为本次新增
- 2026-10-01 UTC，Node v24.19.0 / V8 13.6.233.17-node.51，AMD EPYC 9V74，共享云环境，不保证硬件独占；已协调避免其他本地重型任务
- Vite 生产 SSR；每个轴的 control、CPU、allocation 各两次独立进程；各进程先热身 5 次、测量 12 次。共 12 个进程、204 次全量模拟。第二轮反向排列模式以暴露顺序漂移，不是随机化实验
- 禁用切面，逐次清服务缓存，保留定义级正常寿命。采样包围正式 `simulate`，包括编译、装配、推进、结果收集与正式投影；不包括加载、构建、哈希与复制。每次停止采样后才验证结果。没有测浏览器、Worker 往返、Vue/UI
- 每轮输入不变；完整 Worker 结果与有序回执摘要跨模式/进程一致，并与此前同轴基线一致。[机器可读摘要](simulation-profile-hotspots.json)保留每次服务计时和摘要

CPU 1000 µs 采样，以下百分比是 sample count 比例，不是精确 CPU 时间。JSON 的 cpuMs 是进程 user+system CPU，包含后台线程，不能与主线程采样值混用。Inspector 启停边界仍出现在原始 trace，尤其 timeDelta 可包含大段启停开销；原始时间权重不能解释为模拟时间。source map 指到函数入口，不证明具体某行分配，JIT 内联也可能移动归属。self 为叶帧；inclusive 包含后代且每条栈同名帧去重，各行可能嵌套，不能相加。

分配采样间隔 32768 字节，包含采样期间回收对象，报告的是 V8 统计估算分配量，不是精确分配数、存活堆或峰值。没有强制 GC；验证哈希、profile 序列化与写文件产生的临时对象虽然在采样区间外，也可能影响后续 GC。采样字节不能用于证明泄漏。

## 分配：哪里值得追临时对象

稠密每次模拟的总估算分配约 352.7 / 353.4 MB，电队 274.6 / 275.8 MB（十进制 MB）。这是分配流量，不是运行时需要这么大的存活堆。

| 叶帧                  | 稠密 self 分配比例 | 电队 self 分配比例 |
| --------------------- | -----------------: | -----------------: |
| Buff 容器 tick        |         7.23–7.26% |       10.38–10.69% |
| 原生 generator `next` |         6.63–6.75% |         7.76–7.95% |

## 排序后的优化假设与验收条件

排序综合了反复出现程度和语义风险，不是承诺收益。

1. **图执行与逐帧容器的临时分配**。`actionGraphExecution.ts:659–682` 每次遍历建 generator，并为调用建 host/闭包；`timelineActionExecution.ts:74–81` 每 tick 复制 active、补 due 再排序。可实验稳定 host/直接遍历或有界 scratch buffer，分别改、分别测。必须保留 macro inline、同步 End/Jump、closed 状态、配置顺序与回调重入；不能将活动项和新项分两阶段以换速度。验收完整有序回执、状态快照、恢复/分支与图生命周期专项测试
2. **Buff / 时间倍率热路径减少数组中间结果**。`buffContainerExecution.ts:20–29` 冷却逐帧 map/filter 创建数组；`timeDilationRuntime.ts:512–519` 每次倍率读取 filter/reduce；容器 tick 的 live member 顺序和 `advanceTimeDilation` 每次倍率修改后的继承刷新必须保留。先以窄循环替换临时数组为假设，不合并时钟、不减少 tick、不粗粒度跳帧。验收 Buff 添加/回收重入、冷却阈值、多个时钟、hit-stop、继承倍率与停止/恢复边界
3. **不可变程序的结构检查避免反复物化**。稠密 `rootActionSteps` 分配约 4.1–4.3%，兼容性 `inspectSequence` 子树约 7.8–7.9%。源码 `actionProgramInspection.ts:8–81` 每次建数组并复制分支对象，兼容检查再逐项递归。可探索只读访问器或按不可变 graph/entry/callSite 缓存结构元信息；兼容性依赖 flags、endFrame、调度与定义，不能缓存一个无条件“通过”。验收错误路径/顺序完全一致，定义覆盖、宏参数、短截止与未支持功能仍正确拒绝
4. **诊断回执关联索引**。`skillAvailabilityDiagnostics.ts:62–64` 每个诊断 `entries.filter` 再 `receiptSequences.includes`，是明确重复扫描；可在本次投影内建 sequence 索引/由 reducer 带出关联，保持顺序和所有诊断字段。该回调约 3–4% CPU self，可能是范围小、风险低的首个实验，但不是解释总体差距的主因。验收诊断内容、sequence 顺序与完整结果哈希逐位一致
5. **属性读取和伤害来源明细**。`readCombatAttribute` 已经避免临时数组，仍逐次扫描全部 modifiers；`captureAttributeModifierDetails` 每命中建 Set 并遍历来源；静态面板贡献也重复转换。可以分别验证稳定定义片段缓存或按属性索引，不能复用会随 Buff/目标/随机/恢复变化的最终伤害快照。验收 modifier 注册顺序、浮点累加顺序、失效点、伤害明细、随机种子和恢复分支

回执 append 虽稳定占几个百分点，但复制和冻结承担不可变历史/分支隔离职责，不应先通过去掉冻结、丢字段或少记事件提速。所有候选都必须同规则、同数据、同输出验收；GC 下降也需要实际实验，不能把采样占比线性换算成总耗时收益。
