# v3 重构前后的同轴性能对比

六份相同来源、相同方案的真实公开轴，在同一机器上显式对齐统计截止后，当前 v3 正式重算流水线的暖态中位耗时为旧版的 **2.30–3.25 倍**。这是两代实现处理对应用户工作负载的成本对比；数据、规则、装配边界及输出不同，不能解释成同等计算的纯内核回归。

## 版本选择与可复现性

- 旧版：`13b6905ca767579f018512de1f1fa646a375a0cc`，本地分支 `perf/pre-v3-13b6905c`。它是重构提交 `861bda8c084c641718e1aecdce8cc5f0fc71133f`（“重构 Endaxis 战斗模拟与时间轴编辑器”）的直接父提交；重构提交新引入 core/application 与 game-data-contract 的体系。选择有 Git 父子关系和代码边界依据，不是用后来 main 的头冒充重构前版本。
- 新版：`6bf78c474ff374df2693e0610d1a9195d573c194`，生产引擎内容与既有基线一致。两份生产工作树无改动，旧分支和当前分支各用独立工作树，没有切换或回退当前分支。旧分支仅在本地建立，没有推送。
- 旧版数据是该提交的手写数据树；完整树 ID 与两版锁文件 SHA-256 见结果 JSON。新版为 `1.5.3@10506507-7` 的生成数据，不声称两版游戏数据相同。
- [原始来源、哈希、方案索引与转换诊断](../../tools/performance/fixtures/public-timelines/README.md)、[复现命令](../../tools/performance/README.md#v3-重构前后对照)、[机器可读逐次结果](pre-v3-performance-comparison.json)。原始存档不入库，构建 bundle 也不入库。

## 输入和测量边界

每轴有三组：旧版原生截止、旧版同截止、新版。三组分别使用新 Node 进程，串行运行；相邻轴交换新旧顺序。每组冷首跑 1 次、额外热身 3 次、正式 20 次，合计 18 个进程、432 次模拟。每组内部结果摘要一致，输入未变。统计为 20 次样本，p95 为 nearest-rank 第 19 个排序值；未强制 GC，也没有独占硬件保证。

环境：2026-10-01 UTC，Node v24.19.0 / V8 13.6.233.17-node.51，Linux x64，AMD EPYC 9V74，运行时报告 9 个逻辑 CPU。具体环境由 JSON 中每个新版子进程记录。两个版本都使用 Vite 生产 SSR bundle；构建、模块加载、数据/仓库加载、旧版导入与 watcher 稳定等待都不计入冷首跑。冷首跑并不是页面打开耗时。

旧版通过正式 `fetchGameData`、`importProject` 和方案选择恢复配装、技能覆盖、控制干员、连携冷却、强制暴击、初始效果等。构建适配器仅捕获原 composable 的实际依赖并原样委托，不改旧生产逻辑；每次创建新 composable，重新编译、模拟并执行完整 `projectOptimizerResult`。旧版 store 已预计算的配装属性、被动和刷新后的技能命中在计时外；新版正式服务的场景运行时准备在计时内。因此总计列描述各自已有架构的重算路径，边界并不等价。

新版沿用正式基线入口，`reuseCheckpoint=false`，每次 `clearCache`；不使用继承前缀或旧结果。不可变定义编译缓存保持产品正常寿命。旧版基于新编译时间轴的 WeakMap 缓存不会跨次复用。哈希/输入验证以及新版额外 structuredClone 均在总耗时外，这些验证的分配仍可能影响后续 GC。

旧版摘要覆盖正式投影、日志、冷却区间，保留 Map/Set/非有限数；不覆盖含方法的完整状态实例。新版摘要覆盖正式 Worker 可传输结果及有序回执。不同版本的哈希不要求相等，未为追求数值相同修改轴。

## 为什么另保留旧版原生截止

旧版没有结束线时，配置的战斗长度只限制投影范围，模拟继续到事件队列耗尽；长效状态到期可把最终时间推到千秒左右。新版基线明确推进到配置截止。旧版同截止组显式给正式 `endlineTime` 传入原结束线，或“准备期 + 战斗时长”；只作用于适配器的输入引用，不回写源文件。故同截止组是清楚标注的控制变量，不是声称原存档完全未变。旧版引擎会在队列耗尽后将状态时间补到显式截止。

## 实际计算内容并不等价

保留同一来源的 6 个方案、104/75/17/36/35/39 个输入技能块、准备期、配装及位置。旧版读取原 60 FPS / 1.0.0 存档；新版使用正式 preserve 转换的 30 FPS 夹具，最多约 16.67 ms 量化误差。零未知技能、零省略技能；提决佩洁有两次技能形态解析，低星队陈千语普攻自定义覆盖在新版明确忽略。旧版导入同样会按旧版数据刷新技能命中和装配，并不是原始 JSON 原封不动送入裸内核。

各组旧版 requisiteWarnings 为空，但它不等于新版的可用性检查覆盖。新版 executionDiagnostics 为零不代表每个技能都实际成功执行；可用性与连携诊断、资源/冷却/中断规则会影响输出。下表仅暴露差异，不把任意一版伤害作为原生游戏真值。

这次同机测试支持的结论：当前 v3 对这些真实用户轴的完整服务重算成本明显更高，后续优化应优先 profile 当前模拟推进与结果收集。它不支持将倍率全部归因于某个重构模块，也不支持通过删诊断、少算事件或改变规则恢复旧版数字。若要归因到等语义引擎效率，需要另建规则/数据/输出完全一致的小场景；若要判断编辑体验，需要补浏览器 Worker 传输及 UI 测量。

本次只新增适配器、可复现报告与结果数据，没有做生产性能优化；未测内存峰值、泄漏、浏览器帧率或缓存收益。
