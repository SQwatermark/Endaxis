# 可选动作执行跟踪回执

本页说明普通模拟省略四类执行跟踪的边界、消费者审计和验收方法。输入使用已提交的[六份公开轴](../../tools/performance/fixtures/public-timelines/README.md)，不修改技能安排、战斗截止或游戏定义；不能用旧作者标题中的 DPS 证明模拟正确。

保留源端不安装普通追踪回调的简单实现。编辑器和战斗日志都使用普通结果；详细模拟仅保留为后端能力，未来结合技能图查看内部执行链路时再显式请求，本次不实现该功能。原六轴对照显示语义等价、记录与复制减少；完整模拟计时有升有降，不能据此确认算法回退，也没有证明变慢只来自宿主波动。下方保留原始证据及其版本边界。

## 普通与详细记录的边界

普通 `standard` 模式不生成以下四类记录；详细 `detailed` 模式保留：

| 回执                       | 含义                 | 省略的影响                   |
| -------------------------- | -------------------- | ---------------------------- |
| `CombatStepReached`        | 动作序列到达一个步骤 | 不再逐步列出执行轨迹         |
| `CombatConditionEvaluated` | 条件的种类及真假结果 | 不再列出每次内部条件求值     |
| `TimelineActionStarted`    | 时间轴动作开始       | 不再列出内部时间轴动作开始行 |
| `TimelineActionEnded`      | 时间轴动作结束       | 不再列出内部时间轴动作结束行 |

这不是“关闭诊断”。输入处理、技能开始/结束/打断、施放与消耗失败、冷却、伤害、治疗、资源、Buff、连携窗口、实体、投射物、时间倍率以及被动 UI 的事实仍然记录。可用性、执行失败和连携窗口诊断继续从这些事实生成。普通模式保留战斗结果与战斗日志所需的事实，打开日志直接显示已有结果，不再补取详细历史。战斗日志不承担逐节点解释执行链路的职责；详细模式供离线研究及未来的技能图执行链路查看器使用。

`SkillRuntime` 在创建动作序列和时间轴观察者时选择是否安装追踪回调。普通模式不安装这两组回调；技能转 Buff 路径中的条件追踪也在创建数据对象之前判断模式。条件仍然求值，动作仍然执行，语义事件仍然派发。收集器不承担这四类事件的后置筛选，因此不是先构造完整回执再从输出删除。

这一点不能仅凭普通输出里没有事件证明：六轴对照负责行为等价，源端观察者选择及专门的低层回归负责确认没有进入记录入口。禁止把四类名字扩成所有步骤、所有条件失败或所有诊断记录的通用黑名单。

## 收集级别、缓存与切面

底层收集器、运行时、通用场景服务及编辑器模拟与规划均以普通模式为默认值，只有调用方显式指定 `detailed` 才收集内部执行追踪；需要这些事实的离线分析和执行轨迹回归显式选择详细模式。战斗日志复用普通发布结果。打开和关闭日志不改变模式、不触发重跑，也没有执行详情专用的加载或重试状态。结果仍携带实际 `receiptDetail`，后端仍支持调用方显式请求详细模式；未来技能图执行链路查看器的界面和按需重算流程留待后续实现。

级别属于一次会话的固定观察配置，不写入游戏定义或项目存档。普通和详细服务各自拥有增量/继承前缀；切换级别不能复用另一模式缺少或多出的历史。公共缓存清理同时清理两个模式。Worker 请求携带级别，定义仓库可以共享，但会话、历史、结果和请求发布仍受各自身份约束。

切面另外保存收集级别，恢复必须一致。若调用方要求用不同级别恢复，候选装配会被拒绝，已有会话保持不变；需要从头重算才能得到另一种完整历史。恢复不是在已有详细前缀上追加普通后缀，也不是在普通前缀上仅补未来的追踪。

## 消费者审计

对四类名字的全部引用以及通用回执引用、状态计数和投影读取路径进行检查：

- 生产者集中于 `src/core/combat/skills/skillRuntime.ts`。动作执行和条件判断不从这四类回执读回状态；时间轴推进使用自己的运行状态
- 普通结果投影、HUD、资源/生命/失衡曲线、Buff/被动 UI 时间段、技能警告和伤害来源分析不以这四类记录驱动行为。日志列表会展示已有回执，不要求四类内部追踪存在。`timelineBattleLogEntrySummary.ts` 仍能格式化已有条件追踪的真假信息，但这不构成日志请求详细模拟的理由
- 原有技能与 Ardelia 集成回归读取这些事件判断执行轨迹，必须运行详细模式。编译器优化对照工具已有对步骤和条件追踪的排除逻辑；不能由这个工具的过滤推断生产运行没有构造对象
- 回执序号是当前历史的身份。省略追踪会让后续序号前移；伤害来源中的 `kind: 'receipt'` / `kind: 'modifier'`、诊断引用、曲线点和 Buff 起点引用必须随各自历史一起使用
- 连携窗口的 `sequence` / `nextSequence`、动作序列及技能施放编号是另一套状态，不能因为同名就当回执身份重写
- 增量模拟用 20,000 条历史记录作为是否保存前缀的上限。普通模式记录更少，可能让以前超过门槛的轴获得缓存资格；这是缓存策略上的影响。本报告性能对照关闭切面复用，不将这项间接变化算作执行记录收益

## 复现与等价条件

命令及参数见[性能工具说明](../../tools/performance/README.md#可选执行跟踪验收)。工具使用同一生产 SSR bundle，在独立 Node 进程中执行两种模式；每条轴每种模式每轮独立进程，按轴交替模式顺序，第二轮反向轴顺序并反转同轴的模式顺序。没有开发服务器、Vitest 或采样器参与正式计时。

比较器独立列举唯一允许省略的四类事件，不调用生产过滤或选择代码。它按详细历史中的保留顺序建立一对一身份映射，检查两份历史的序号连续性，然后比较所有保留字段与完整可传输结果。只允许结果的 `receiptDetail` 元数据及经过检查的真实回执身份不同；任何保留对象指向被删除/不存在回执都会失败。非回执状态计数不重映射。

此外比较完整战斗状态、从准备段到截止帧的每帧 HUD、被动 UI 时间段和 Buff 时间段。HUD 逐帧深比较，另用显式标记非有限数、正负零及 undefined 的 JSON 计算哈希；状态保留 Map/Set 并逐项深比较。原始二进制、SSR bundle 和 source map 仅保存在本机忽略目录，不提交个人输入或本机路径。

恢复探针在第一个实体生成、时间倍率开始、Buff 伤害前后以及轴中点保存并分叉，核对立即恢复状态/历史及继续到终点后的状态/历史/结果。它不是完整浏览器缓存操作验收，也不替代跨模式缓存及 Worker 过期响应回归。

## 性能口径

每个进程首跑一次、热身三次、正式测量二十次。每次关闭切面复用并清缓存，定义级不可变编译缓存保留产品正常寿命。首跑不含构建、模块或仓库加载；服务 `simulationMs` 包含编译、装配、推进和核心结果收集，`projectionMs` 是其后投影。语义检查、哈希、文件输出与 `structuredClone` 不计入服务耗时。

另测正式 Worker 可传输结果的 `structuredClone`，不含带方法的进程内历史视图；它不是 Worker 往返耗时。JSON 编码大小只表示一种可复现的结果编码体积，不是实际浏览器传输字节。没有强制 GC；回合间哈希和复制产生的垃圾仍可能影响后续 GC，不能把所有 GC 都归因于模拟本身。不报告 FPS、精确对象分配数、存活堆或泄漏结论。

共享宿主的性能波动是合理的候选解释，应同时看两轮和不同机制的轴；本次实验没有控制到足以证明“只有宿主波动”或排除所有运行时影响。少生成追踪回执减少了确定的记录工作，但墙钟耗时还受调度、JIT、GC 等因素影响，不能从删掉工作直接推出每组耗时必降，也不能从较慢样本反推已定位到 JIT 或 GC。二十次样本的 nearest-rank p95 是第十九个排序样本，不能当稳定尾延迟保证；冷首跑也不能由单样本推出稳定改善。

## 稠密轴的有限调查与保留决定

保留初始全部数据后，在同一生产源码摘要下单独再跑稠密轴：仍是正式验收 runner，冷首跑一次、热身三次、正式二十次，两组相反顺序；仅关闭计时后的额外 HUD/切面检查。每种模式完整结果与回执哈希均与最初六轴两轮一致。

| 第一对       | 341.30 → 352.62 (+3.3%) | 462.31 → 481.34 (+4.1%) |          31.34 → 24.64 |

只在临时生产构建中做了两种替代，未修改或保留生产源码：普通模式安装四个同名空函数（`noop`），或者始终安装真实回调、在回调内部判断级别后才构造数据（`innerguard`）。这组控制使用 profiling runner，热身四次、正式二十次、每方案两个相反顺序的进程对，没有启用采样。它不逐次执行 `structuredClone`，也不持有第一次完整结果，与正式验收 runner 的 GC/JIT 环境不同，不能跨工具直接拼接耗时。

额外 CPU/分配采样分别在五次热身后捕获六次模拟：1000 µs CPU 间隔，32768 字节分配采样，包含采样期间已回收对象。估算分配流量由 322.06 → 316.80 MiB/次（约 -1.6%），历史追加的 self 估算分配为 7.67 → 5.87 MiB/次。省略的回执只是总分配的一部分；这些数值不是存活堆、峰值或精确对象计数。

因此保留简单的源端选择方案，目标限于不生成不需要的内部执行追踪、减少记录与复制；**现有测量不足以证明普遍降低模拟延迟**。游戏语义、恢复级别隔离和后端详细追踪能力不为追求耗时数字而削弱。完整跟进样本、未保留方案以及采样摘要都在同一份机器摘要（原始 JSON 上传待补），不上传原始 traces 或源码映射。

## 已知限制

伊冯公开轴的额外恢复探针在既有版本中已存在 `missing projectile reset handler 0`，本项不修复该问题。工具默认将恢复失败视为失败；显式使用已知故障选项时仍保留失败的轴、帧、消息和 `semantic-equal-with-checkpoint-failures` 状态，绝不计为切面通过。普通/详细的失败边界也必须相同，否则验收失败。

完整全量模拟等价与切面恢复通过是两项不同结论；详细模式的回执数量、序号和完整输出哈希不会与普通模式相同。
