# 核心架构排查

本文记录非界面核心的架构研究、证据和待验证项，供决定后续修改范围使用。它不是已经落实的新设计；稳定职责仍以[架构概览](../architecture/README.md)及实现为准。此研究记录按项目所有者要求保留在当前研究分支，完成后的稳定结论应归入相应主题页。

## 范围与证据标准

- 代码基线：`399dfd56b563ef701f32ddf44f5c6c891bb9a565`。后续提交仅更新研究文档，除非明确注明，否则代码定位均针对该基线。
- 从原始资源、离线生成、共享契约、项目与场景编译，追踪到应用模拟、战斗执行、记录投影和 UI 消费。
- 先查责任、数据归属和跨系统约定，再评估局部热点；文件大或类大本身不构成拆分理由。
- 区分已复现缺陷、结构风险、待确认语义。每项建议需要代码证据、影响范围、最小修改和验收条件。
- 以 Endaxis 原生代码与测试为验收依据；外部战斗研究仅用于理解差异，不引入其依赖、运行器或夹具。
- 本阶段只研究和维护文档，不修改生产代码。已完成的装配统一、输入结果区分、恢复、冷却工厂、替换预校验及事件写入边界只检查回归，不作为未完成工作重新列出。

## 计划与进度

| 阶段 | 小目标                   | 状态 | 交付                                                  |
| ---- | ------------------------ | ---- | ----------------------------------------------------- |
| 1    | 职责与真实依赖图         | 待查 | 编译器区别、导入边界、核心独立性与 UI 写入口          |
| 2    | 数据归属与生命周期       | 待查 | 定义、程序、状态、输入、记录、切面及缓存的创建到销毁  |
| 3    | 子系统协作与时序         | 待查 | 输入、替换、嵌套 Buff、清理、延迟伤害的责任与失败边界 |
| 4    | 结果与公共 API 不变量    | 待查 | 主线程/Worker、增量/继承、取消/过期、恢复与历史       |
| 5    | 按证据排序的局部热点     | 待查 | 复现、风险、最小方案及验收要求                        |
| 6    | 验证缺口与分阶段整改建议 | 待查 | 原生测试矩阵、实施顺序及需要确认的语义                |

每完成一个小目标更新本文，并独立提交；研究过程中发现的猜测不能直接升级为缺陷。
