## 1. 职责与真实依赖

### 实际运行路径

| 边界             | 输入 → 输出                                    | 决策与写入责任                                     | 代码入口（基线）                                                                                                    |
| ---------------- | ---------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |

| 数据契约与装载   | 契约类型 + 生成定义 → 同步查询仓库             | 契约不做求值；数据层负责登记和按需加载             | `packages/game-data-contract/src`；`src/data/projectGameDataRepository.ts:20–39`、`:51–95`                          |
| 项目与编辑事务   | 存档/命令 → 新项目版本与撤销历史               | 用户意图、定义覆盖、继承限制；不保存活动战斗对象   | `src/core/project/serialization.ts`；`src/application/editor/projectEditorSession.ts:59–83`                         |

| 应用装配与调度   | 场景请求 → 本地/Worker 模拟结果                | 选择数据子集、完整/增量/继承执行、缓存和取消       | `src/application/simulation/createScenarioSimulationService.ts:12–30`；`adaptiveTimelineSimulationService.ts:48–72` |

### 导入核查

方法：用仓库 TypeScript 解析器扫描 `.ts/.tsx` 的静态 import/export 和字面量动态 import，排除 `*.test.*`、`*.bench.*`，对生成器再区分 `test/` 支持代码；规范化相对路径与 `@/`。另查 Vue 页面中的服务装配与可变运行时引用。

- 核心到应用、UI、正式数据、平台、设计系统、工具以及 Vue/Pinia 的直接导入：未发现。
- 应用生产 TypeScript 到离线工具、契约到包外模块的直接导入：未发现。
- 生成器生产代码到主包有 10 条导入，指向图校验/数据节点、定义校验和数值比较。沿这些入口追踪的 16 个模块只包含上述纯逻辑和契约；没有通过共享代码加载 UI、应用状态或正式数据仓库。
- 生成器测试支持代码会引入正式仓库和模拟服务，用于对比优化前后行为；这是测试边界，不能误报成生产反向依赖。
- 检索 UI 未发现 `CombatRuntimeAssembly` 或 `stateGraph` 直接访问；正式结果由会话复制状态、固定回执后收集。UI 对项目通过编辑事务写入，但项目对象引用是否足够隔离留到数据归属阶段核对。

这些结果支持现有总体分层，不支持为了目录“更整齐”搬移职责。静态扫描不证明不存在运行时别名修改，也不穷举字符串计算式加载；Vite 的 `import.meta.glob` 已人工检查为生成定义装载。

### 初步关注点

1. 核心依赖约束目前主要靠约定和现有编译配置，而非覆盖应用全图的自动化禁止导入检查。属于防回归风险，尚无违规实例。
2. 场景编译输出同时携带固定程序与可变运行环境端口（`operatorRuntimeBindings`），并非可以随意序列化/复用的纯数据程序包。下一阶段检查这些端口的寿命和恢复规则，避免把“编译纯函数”误读成“所有返回对象永久不可变”。
