# 时间冻结与时间投影

本文记录连携技、终结技等动作造成全局时间冻结时，Endaxis Next 应遵守的跨层语义。战斗规则以反编译证据和 C# 复刻库为准；旧版 Endaxis 只用于参考编辑器表现，不是规则来源。

## 1. 核心结论

时间冻结不是释放者技能自身时长的一部分，而是一次作用于全局时间域的运行时事件。

- 技能定义描述自身的步骤、可操作边界和触发冻结的原生动作。
- 场景存档只保存用户编排的逻辑起始帧，不保存冻结后的坐标或宽度。
- 模拟器执行冻结事件，并按原生规则决定哪些时钟继续、暂停或变速。
- 投影层根据模拟结果计算实际起止帧，再绘制技能块、命中点和持续效果。

因此，不能为了让技能块看起来更宽而把冻结帧直接加进 `timelineBlockFrames`，也不能在编辑命令中把后续技能的逻辑位置永久右移。

## 2. 两类时间

编辑器至少需要区分以下两类坐标：

| 时间     | 含义                               | 是否进入存档   |
| -------- | ---------------------------------- | -------------- |
| 逻辑时间 | 用户编排动作时使用的游戏时间       | 是             |
| 实际时间 | 模拟执行冻结和变速后得到的展示时间 | 否，由模拟派生 |

冻结期间，逻辑时间可能停止，而实际时间继续推进。拖动动作时最终写回逻辑帧；从实际时间轴读取鼠标位置时，需要通过模拟产生的时间映射换算，不能把投影坐标直接写进项目。

## 3. 旧版 Endaxis 的表现

旧版维护 `logicalStartTime` 与 `startTime/realStartTime`，编译时生成全局 `TimeExtension`：

1. 连携技或终结技创建冻结区间。
2. 冻结来源动作通过 `sourceId` 排除自己的冻结，避免再次延长自身。
3. 冻结期间开始的其他动作被推迟到冻结结束。
4. 已开始但结束时间跨过冻结点的其他动作会延长。
5. 后续动作整体向右投影。
6. UI 使用模拟后的 `realStartTime` 和 `realDuration` 绘制技能块。

旧版还会：

- 在来源技能块内标出动画阶段；
- 绘制贯穿时间轴的冻结区域；
- 让受冻结影响的技能块、命中点和持续效果按实际时间对齐；
- 提供游戏时间与实际时间两种刻度。

这些表现直观，Next 应尽量保留。

## 4. 旧版规则不能直接照搬

旧版冻结计算包含面向编辑器的近似：

- 连携技通常硬编码为 0.5 秒；
- 终结技缺少配置时回退为 1.5 秒；
- 连续冻结会按相邻动作间距裁剪；
- 通过来源动作 ID 整体排除自身；
- 默认延长所有跨过冻结点的动作和效果。

这些做法只能解释旧版 UI，不能进入 Next 战斗核心。Next 必须继续从反编译结果确认：

- 冻结由技能内哪一帧触发，持续多久；
- 是否存在变速曲线；
- 动作序列、冷却、Buff、DOT、资源回复和投射物分别使用哪个时钟；
- 来源技能内部哪些步骤在冻结期间继续执行；
- 同帧或嵌套冻结如何排序、合并或覆盖。

## 5. Next 的职责划分

### 技能定义

`SkillDefinition` 只声明经证据确认的冻结动作及其触发位置。`timelineBlockFrames` 仍表示技能块自身的可操作/体感宽度，不附加全局冻结长度。

### 编译器

编译器将冻结声明转换成明确的运行时程序，但不提前改写项目中其他技能块的位置。未经证实的默认冻结时长不得在此层补算。

### 模拟器

模拟器拥有时钟推进和冻结状态，输出足以还原以下事实的 receipt：

- 冻结开始、结束和来源；
- 各动作实际开始、结束；
- 各命中、效果和资源事件的实际发生帧；
- 必要时记录所使用的时钟域。

### 投影层

投影层把 receipt 转换成逻辑时间与实际时间的映射，以及动作的实际布局。它可以复刻旧版的冻结带、动画阶段标识、双刻度和块体拉伸，但不得重新猜测冻结规则。

### UI

未得到有效模拟结果时，时间轴按逻辑时间显示。模拟结果有效时，技能块的位置和宽度以投影结果为准；项目文档保持不变。任何模拟失败或过期状态都应明确显示，不能继续展示上一轮投影并让用户误以为是当前结果。

## 6. 当前实现边界

- 原生 `TimeDilationAction`、`UltimateTimeAction`、公共曲线、优先级和槽位规则已经在证据文档与 C# 复刻库中闭环。
- Next 已建立独立的 `TimeDilationRuntime`，复现同槽优先级替换、跨槽最小倍率、施法者忽略、实体倍率叠乘和自然结束边界。
- 版本相关标签、曲线和槽位规则由装配层传入，不写死在战斗运行时。
- `SkillDefinition` 已支持普通时间膨胀和终结技专用时间膨胀；编译器保持动作参数，执行器负责创建实例并按动作生命周期结束。
- 生成器会严格读取根技能时间轴上的两类原生动作。嵌套动作、未知字段和无法建模的能力实体目标会明确报错，不会静默丢弃。
- 技能时间线、技能冷却、Buff 生命周期和失衡恢复已分别接入自身所用时钟。标准伤害入口会装配公共优先级、槽位规则和已完整恢复的命名曲线。
- 内联曲线属于动作定义，随技能一起编译；命名曲线属于版本化公共配置。二者只改变数据来源，不改变全局或实体作用范围。
- 终结技在 Next 内使用独立语义槽位，避免为尚未恢复的原生固定标签伪造数值；槽位竞争行为与原生一致。
- 当前公共配置只登记已恢复完整关键帧的 `ComboSkill` 和 `RESETto1`。`interrupt_weakness` 的切线和权重尚不完整，遇到该名称会严格失败。
- `CombatTimelineClock` 按全局倍率推进项目逻辑帧，场景输入到达逻辑帧后才会提交；模拟入口会继续推进实际帧，直到到达指定逻辑终点。
- 时间实例的开始、拒绝、替换、自然结束和动作结束均记录来源回执；`TimelineTimeSampled` 提供非正常倍率期间的逻辑时间事实。
- `projectTimelineTimeMapping` 已提供逻辑帧与实际帧的双向映射。UI 冻结带、技能块实际布局和拖拽逆映射的组件接入仍待实现。
- 所有带后续执行器的操作适配器必须转发 `execute`、`evaluate` 和 `end`。缺少 `end` 会使时间实例等持续步骤无法结束。

实现后续阶段时仍须遵守：不把旧版硬编码冻结时长迁入 `SkillDefinition` 或项目存档；投影测试必须覆盖冻结期间开始、跨越冻结、连续冻结和同帧冻结。
