# 生成武器库的存档迁移边界

2026-08-26。当前生成武器仍是候选，本文描述显式迁移能力，不表示默认库已切换。
这是 Endaxis 的存档兼容规则，不是原生游戏机制，不向 combat-spec 添加产品迁移规则。

## 身份与词条

`registerGeneratedWeaponDefinitions` 以精确图标资源身份连接旧友好 slug 与生成武器 ID。
但项目保存的 `traitLevels` 是数组；数组下标只在对应旧版本定义内有意义。
旧 `adaptSharedWeapon` 按 skill1/2/3 依次适配并过滤空项，保留原键；新编译器则按
`WeaponBasicTable.weaponSkillList` 的槽位生成键。不能一概按位置迁移。

真实差异分为三类：

| 武器                                                                 | 旧词条键       | 新词条键               | 迁移要求                                    |
| -------------------------------------------------------------------- | -------------- | ---------------------- | ------------------------------------------- |
| `freedom-to-proselytize`、`dreams-of-the-starry-beach`、`golden-age` | skill1、skill3 | skill1、skill2、skill3 | 保留原两键等级，显式选择新 skill2 等级      |
| `type-42-solemn-phalanx`、`former-finery`                            | skill1、skill2 | skill1、skill2、skill3 | 保留原两键等级，显式选择新 skill3 等级      |
| `jiminy-12`、`darhoff-7`、`peco-5`、`opero-77`、`tarr-11`            | skill1、skill3 | skill1、skill2         | 显式将旧 skill3 改名为新 skill2，无新增等级 |

最后五把的旧 skill3 和新 skill2 均是第二条固定攻击加成，已分别检查旧定义和新生成定义；
测试锁定其 `panelStat/attackFlat` 身份，但迁移器不会按属性、数值、星级或武器名称自动猜映射。
新表保留未舍入的数值，迁移只复制用户等级，不覆盖新表行为。

注册诊断现同时检查词条键顺序、数量和等级容量，报告 10 项差异。相同长度不再被误认为兼容。

## 执行协议

- `core/project/weaponInstanceMigration.ts`：按稳定键和可选的显式键别名迁移单个实例。
  新增键未指定等级时失败；重复键、删除旧键、两个旧键合并到一个新键、越界值等均失败。
  不夹取等级、不丢弃旧输入、不自动选零、一级或满级。
- `application/weaponGameDataMigration.ts`：实现现有 `GameDataRevisionMigrator`，要求精确的
  源/目标仓库版本。遍历全部场景与轨道，先验证源项目，在副本上转换，再验证目标项目。
  任一失败不返回半成品；只有全部成功才得到新版本项目。
- 显式策略由调用方传入并在创建迁移器时快照。新等级选择生成警告，明确它不是恢复出的旧值。
- 已物化的项目自定义武器不更新、不重新派生；其历史 origin 也不改写。技能块 ID、时间、连线、
  场景及轨道身份均不迁移，只修改内置武器引用和对应等级。
- `openProject` 仍只报告 `game-data-migration-available`，不会擅自执行迁移或覆盖存档。
  对已迁移的新版本项目再次运行同一迁移器会失败，避免重复换序。

测试用新增等级 4 只是显式选择样本，**不是产品默认**。测试传入的五把三星键别名也是显式
迁移策略，不是按 ID 进入公共模拟器的行为特判。

真实伤害，技能块身份和时间不变。尚未接入默认迁移注册表和选择新词条等级的 UI。
