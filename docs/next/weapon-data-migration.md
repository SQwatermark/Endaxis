# 生成武器库的存档迁移边界

更新于 2026-08-27。77 把生成武器已切入默认库，旧项目必须经显式确认和备份迁移后打开。
这是 Endaxis 的存档兼容规则，不是原生游戏机制，不向 combat-spec 添加产品迁移规则。

## 身份与词条

`registerGeneratedWeaponDefinitions` 以精确图标资源身份连接旧友好 slug 与生成武器 ID。
但项目保存的 `traitLevels` 是数组；数组下标只在对应旧版本定义内有意义。
旧 `adaptSharedWeapon` 按 skill1/2/3 依次适配并过滤空项，保留原键；新编译器则按
`WeaponBasicTable.weaponSkillList` 的槽位生成键。不能一概按位置迁移。

真实差异分为三类：

| 武器                                                                 | 旧词条键       | 新词条键               | 迁移要求                                    |
| -------------------------------------------------------------------- | -------------- | ---------------------- | ------------------------------------------- |
| `freedom-to-proselytize`、`dreams-of-the-starry-beach`、`golden-age` | skill1、skill3 | skill1、skill2、skill3 | 保留原两键等级，显式选择新 skill2 等级      |
| `type-42-solemn-phalanx`、`former-finery`                            | skill1、skill2 | skill1、skill2、skill3 | 保留原两键等级，显式选择新 skill3 等级      |
| `jiminy-12`、`darhoff-7`、`peco-5`、`opero-77`、`tarr-11`            | skill1、skill3 | skill1、skill2         | 显式将旧 skill3 改名为新 skill2，无新增等级 |

最后五把的旧 skill3 和新 skill2 均是第二条固定攻击加成，已分别检查旧定义和新生成定义；
测试锁定其 `panelStat/attackFlat` 身份，但迁移器不会按属性、数值、星级或武器名称自动猜映射。
新表保留未舍入的数值，迁移只复制用户等级，不覆盖新表行为。

注册诊断现同时检查词条键顺序、数量和等级容量，报告 10 项差异。相同长度不再被误认为兼容。

## 执行协议

- `core/project/weaponInstanceMigration.ts`：按稳定键和可选的显式键别名迁移单个实例。
  新增键未指定等级时失败；重复键、删除旧键、两个旧键合并到一个新键、越界值等均失败。
  不夹取等级、不丢弃旧输入、不自动选零、一级或满级。
- `application/weaponGameDataMigration.ts`：实现现有 `GameDataRevisionMigrator`，要求精确的
  源/目标仓库版本。遍历全部场景与轨道，先验证源项目，在副本上转换，再验证目标项目。
  任一失败不返回半成品；只有全部成功才得到新版本项目。
- 显式策略由调用方传入并在创建迁移器时快照。新等级选择生成警告，明确它不是恢复出的旧值。
- 编辑器迁移可传入 `instanceAddedTraitLevels`，按 `scenarioId + trackId` 定位实例；同一武器的
  不同实例可以选择不同新增等级。该模式与原来的按目标武器种类 `addedTraitLevels` 批量模式
  互斥；重复选择、未知轨道及对自定义模板的选择均失败，不能静默忽略。
- 已物化的项目自定义武器不更新、不重新派生；其历史 origin 也不改写。技能块 ID、时间、连线、
  场景及轨道身份均不迁移，只修改内置武器引用和对应等级。
- `openProject` 仍只报告 `game-data-migration-available`，不会擅自执行迁移或覆盖存档。
  对已迁移的新版本项目再次运行同一迁移器会失败，避免重复换序。

测试用新增等级 4 只是显式选择样本，**不是产品默认**。测试传入的五把三星键别名也是显式
迁移策略，不是按 ID 进入公共模拟器的行为特判。

## 预览与确认用例

`application/weaponMigrationReview.ts` 的 `prepareWeaponMigrationReview` 接收原项目及精确
源/目标仓库，先校验原项目，再捕获项目、别名策略和本项目引用的新旧武器定义快照。
`core/project/weaponInstanceMigration.ts` 的预览与执行共用身份规划，不复制词条映射算法。

预览按实例列出源/目标 slug、目标词条键及容量、保留的来源键/等级。没有来源键的词条就是
新增待选项，不填默认等级；改名也显式显示来源键。项目自定义模板计数展示但不参与替换。

确认调用需要显式 `confirmed`、逐实例等级、当前文档读取端口及异步 `persistBackup`：

1. 检查原项目和所用武器数据仍与预览一致，包括 revision 相同但内容变化的情形。
2. 复用既有迁移器生成并校验副本。任何选择缺失或非法都在备份前失败，不返回半成品。
3. 将原项目 JSON、源/目标 revision 和引用的旧内置武器定义交给备份端口。
4. 只有备份成功且当前项目/定义仍未变化，才返回可打开的新项目；用例本身不替换编辑会话。

等待期间重复确认返回 busy；成功后的同一会话不能重复执行。备份失败可重试；项目或数据变化
需重新预览。预览、备份和外部策略是隔离副本，外部改动不能改变已确认的迁移。

`endaxis-weapon-migration-backup-v1` 的 `projectJson` 是原项目，可交给原版本打开入口；
`sourceWeaponDefinitions` 保存本项目引用的旧内置武器（去重），自定义模板已在原项目内。
它**不包含完整旧干员/装备/机制库，不是可独立重现旧模拟结果的整库快照**。
底层只依赖备份端口报告；现已接浏览器 localStorage 适配，写入并回读一致才报告成功。
浏览器内持久化不等于导出文件已下载或云备份；清理站点数据会丢失备份。

验证：77 把真实武器逐把通过预览、显式选择、备份端口和重新打开；同武器跨场景选择不同等级、
取消、重复确认、备份失败/抛错、并发、文档/定义过期和自定义模板均有测试。佩丽卡实际战技
迁移后仍产生伤害，放置身份与现实帧不变。全量 295 文件/3201 项及两侧类型检查通过。

## 正式发布与 UI

迁移后的 77 把真实武器能通过目标定义校验，且放置佩丽卡战技的项目可迁移、重新打开并产出
真实伤害，技能块身份和时间不变。正式目标版本为 `endaxis-next-definitions-v2-weapons-1.4.4-r2`。
`prepareDefaultWeaponMigration` 只接受精确 v1 与 `endaxis-next-definitions-v2-weapons-1.4.4-r1`；未知版本不猜测。
本次 r1→r2 更正两把武器反应光环的来源/目标投影，不改变 ID、词条键或已保存等级。
r1 原值以 `data/revisions/weapons-v2-r1` 的两把差量快照和 75 把未变项保留，完整旧库哈希锁定。
77 把 r1 武器逐项确认、备份与重新打开均验证；迁移副本仅 revision 变化，自定义模板不改。
旧武器的 77 把完整快照固定在 `data/revisions/weapons-v1`，来源提交、哈希及重建方式见其 README。
这只解决武器存档兼容；源查询端口其他定义来自当前库，不承诺历史全库重放。

`NextTimelineEditor` 在加载精确 v1/r1 文档时展示 `WeaponMigrationDialog`。新增等级保持空选项，
全部选择后才可确认；备份成功才替换当前项目，迁移副本标记为未导出。对话框阻断下层时间轴快捷键，
文件读取和异步备份期间编辑变化都会拒绝过期替换。项目自定义模板原样保留。

`weaponMigrationBackupStorage` 用 UUID 键存原项目与旧武器快照，回读验证、禁止覆盖；配额/禁用/
回读错误均阻断迁移。顶部“迁移备份”可查看并导出原项目或备份包；损坏条目报告错误且不删除。
下载通过公共 Blob/anchor 入口触发，并延迟释放 URL；它不作为持久化确认端口。

浏览器验收：同武器跨场景分别选 2/8 级，缺项禁用确认，迁移后已打开且标记未导出；热重建后仍可
列出备份。截图布局检查通过。工具的下载事件等待超时，**导出文件落盘尚未完成端到端验收**，
不将该操作写成已验证成功。原备份在浏览器中保留。全量 298 文件/3290 项及两侧类型检查通过。
2026-08-27 诀模板常驻定义正式接入后，8 项黑板阻塞已闭合，候选武器交叉模拟 966/966 成功、0 豁免。
默认库切换已完成；后续仍应验证关键被动分支及下载落盘，不以运行通过代替全分支审计。
生成器若改变正式武器内容，revision+哈希发布门禁会失败，必须明确决定新版本及相应迁移边。
