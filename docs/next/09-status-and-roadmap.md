# Endaxis Next 当前状态与路线图

本文只给出架构级状态。逐功能的定义、编译、执行和 UI 门槛以[功能迁移矩阵](../architecture/endaxis-next-feature-matrix.md)为准。

## 1. 当前状态

### 已接入

- V2 项目 schema、结构校验、序列化和迁移端口；
- 只读游戏目录接口与默认目录装配；
- 干员/武器/装备/敌人的选择和部分编辑流程；
- 场景 build 解析、装备贡献、敌人编译和干员面板解析；
- 技能 DSL、等级值编译、时间轴输入编译；
- 编辑会话、撤销/重做、复制粘贴和基本时间轴命令；
- 战斗时钟、资源、技能、冷却、黑板和回执基础；
- Buff、Status、Marker、属性、伤害和附着的若干独立运行时模块；
- 技能与内联 Buff 共用的同步有序步骤执行器，以及按 Buff 实例隔离的生命周期序列适配器；
- 技力、终结技能量、失衡、附着、状态和技能诊断的投影基础；
- 标准生命伤害场景的编译、能力预检、模拟和最终生命结果；
- Next 页面、按需游戏文本、主题基础和部分旧版兼容 UI。

### 部分接入

- 干员目录：正式 Next 定义覆盖有限，生成器仍在扩充完整行为、天赋和潜能。
- 武器与装备：选择、静态面板、定义严格校验和动态事件装配已接入；真实特殊效果数据覆盖、内部冷却样本及装备触发伤害的来源分类仍待闭环。
- 敌人：通过旧数据适配器过渡；当前 82 个定义已从 1.4.4 模板资产捕获原生 `rank`，并贯通项目实例、编译与 `CheckEnemyRank` 条件求值。失衡节点阈值语义已验证，节点 Buff 与节点事件仍待闭环。
- 元素系统：基础附着和复合工厂模块存在，完整反应目录和场景装配未闭环。
- Buff 行为：内联定义、等级编译、严格校验、实例级生命周期执行器和正式战斗操作链已贯通；技能编辑器可为八个生命周期阶段搭建与技能相同的有序步骤。外部元素 Buff 的旧低层动作协议仍待迁移。
- 伤害：标准生命伤害、处决伤害与连续失衡账本的执行/恢复已贯通；处决会按敌人配置和技能倍率回复技力，目录驱动元素附着已接入标准环境。失衡节点效果、生命汲取和状态依赖分支仍需扩展正式环境。
- 时间轴 UI：主要布局和编辑基础存在，尚未达到旧版全部交互和投影能力。
- Pipeline：通用 revision/cache 基础存在，正式应用入口尚未全面采用分阶段缓存。
- 连携窗口：干员级首段注册、伤害/附着语义事件、内部续段步骤、按干员候选账本、暂停计时、同帧轨道排序、候选黑板传递、当前激活项消费和窗口失败诊断已接入；复杂条件覆盖、立即施法和 UI 激活间隔尚未闭环。
- 时间膨胀：技能定义、编译器、生成器、普通/终结技动作执行器、公共配置以及技能、冷却、Buff、失衡各自的时钟已接入标准模拟。项目输入按逻辑时间调度，实例生命周期回执与逻辑/实际时间双向映射已贯通；UI 已接入实际起点、双标尺、光标、拖拽逆映射、连线、曲线宽度及全局/实体时间区间。技能编辑器可以查看和编辑两类时间膨胀步骤，包括公共命名曲线与完整内联关键帧。实体变速后的技能块实际宽度仍待完成，关键帧不完整的公共曲线继续严格拒绝。
- 能力实体：已从 1.4.4 模板资产建立 54 个严格证据定义，并按零距离、全范围、单敌人约束接入场景级逻辑目录、生成步骤、owner/tag Context 组查询、可选计数输出、稳定句柄迭代、有限时长读取/比较/赋值、生命周期推进和审计回执。生成器已闭环庄方宜的 `Context ForEach -> LT -> InputTarget/Assign` 时长形状，并对全语料 10 个时长赋值做严格载荷校验。原生反汇编已证明 `setMultipleTarget=false` 是一次单目标调用；生成器现在只对“此前确定逻辑生成且未被普通目标组复用”的命名 Context 建立 0/1 单例证明并复用统一迭代逻辑。Li Zhiyan 的八个赋值满足局部生产者形状，但对应逻辑生成仍受位置目标投影阻塞。能力实体 `TimeDilationAction` 的 owner/tag 与命名 Context 查询已进入正式 DSL/执行器；全局和终结技动作会按原生数据把这些实体加入排除集合，Entity 分支也能逐实例安装倍率，标准模拟会让能力实体有限寿命消费该倍率。子 SkillData 仍是静态父时间轴投影，因此生成器继续显式阻塞 Entity `effectTargets`，全量审计保持 318 个可解析、280 个可编译。空间组件不建模；一般多实例 Context 的单目标选择顺序、实体目标 Buff、目标变更和子技能动态调度仍待闭环。

### 尚未闭环

- 全干员、全武器、全装备和套装的严格可执行目录；
- 完整玩家主动战斗环境；
- 终结技、连携窗口、活动机制和所有特殊资源的端到端模拟；
- 完整战斗日志、伤害归因和分析界面；
- 旧存档迁移的真实样本覆盖；
- 与旧版 UI 的完整视觉和交互回归；
- `/timeline` 正式入口切换。

生成版佩丽卡现已作为第一条单干员生产模拟验收样本。该样本从项目文档出发，覆盖完整普攻链、连携、战技、终结技、下落攻击和处决，并保留连携与终结技的原生时间膨胀动作。Arclight 与佩丽卡组成的双轨样本进一步覆盖主控身份、共享技力、跨干员伤害以及连携窗口的开启和消费；场景装配会从轨道和主控切换记录推导主控身份，不要求外部环境重复注入。它们证明生成产物可以进入正式多干员模拟入口，但不代表时间投影、全部特殊机制或全干员目录已经闭环。

除首个佩丽卡样本外，当前生成目录又注册了九名技能主体可完整转换的干员，其中最新接入的是大潘。生成器会从稳定技能类型与 `SkillPatchTable` 自动恢复非零费用和冷却，并已接入纯静态属性、终结技费用乘算、稳定技能组上的黑板修正、条件减速动作、根技能来源时间膨胀目标及严格子集的能力实体生成。用户已经排入时间轴的技能不会再被根 `SequenceAction` 守卫取消；内部序列仍按动作帧保留局部短路，且只有目标身份与尾部消费权均已证明时才允许生成。时间膨胀即时搜索中的当前主控角色保留为独立 `controlled` 身份，并在执行帧查询场景控制时间线，不静态近似为施法者。隐藏天赋技能、附加技能、复杂 Buff、能力实体集合操作/时间膨胀和混合养成载荷继续作为明确缺口保留，不能因载荷名称可识别而误报为完整。

## 2. 当前优先级

### 第一阶段：实例选择和编辑

优先贯通干员、武器、装备和敌人的选择、配置、筛选、面板查看与持久化。技能实例高级编辑暂缓。

在官方干员实例流程稳定、`OperatorDefinition` 结构收敛后，按[自定义干员设计](../architecture/endaxis-next-custom-operators.md)接入项目级自定义干员。自定义干员与官方干员复用定义、校验、编译和模拟链；支持复制现有模板与从空白模板创建，不建立第二套战斗模型。首个稳定存档版本前不为这一过程中的 schema 变化编写迁移。

### 第二阶段：时间轴编辑

补齐轨道选择/排序、技能库、拖拽、框选、多选、复制粘贴、上下文菜单和快捷键作用域，并保持旧版主要视觉。

### 第三阶段：完整模拟

以当前标准伤害闭环为基础，按状态所有权逐步接入：

1. 敌人 `CombatVitals` 的场景共享所有权；
2. 失衡执行和恢复；
3. 扩大实际 Buff 和装备事件的数据覆盖，闭环内部冷却与叠层样本；
4. 元素附着与反应；
5. 扩大连携条件求值覆盖，接入立即施法、UI 激活间隔、终结技和特殊干员机制；
6. 完整 receipt 与运行时结果。

Buff 生命周期装配应先于扩大全干员生成范围：由场景装配层按来源与所属实体建立 Buff 操作上下文，使伤害、资源、状态、事件归因都使用 Buff 自身身份。不得直接复用某次技能释放的 `SkillRuntime`，也不得在缺少操作链时忽略生命周期步骤。

### 明确重点待办：时间膨胀的 UI 投影

原生动作、时钟、输入推迟、生命周期回执和双向时间映射已接入。下一阶段不再重做冻结算法或在 UI 猜测时长，只消费模拟结果：

- 补充实体变速后的技能块实际宽度事实；
- 持续验证拖拽、辅助线和连线只写回项目逻辑帧，不保存实际投影坐标；
- 补齐 `interrupt_weakness` 的完整关键帧，并扩大生成器到更多真实技能样本；
- 验收覆盖连携技、终结技、嵌套或重叠实例、排除目标和不同时钟计时器。

### 迁移脚手架清理门槛

Next 迁移期间允许存在用于贯通新旧入口、生成审计和功能占位的临时代码，但这些内容不是长期架构。进入完整时间线模拟阶段前必须完成一次专项清理：

- 删除仅用于迁移旧技能快照、旧命中身份和旧编辑字段的适配器与回退分支；
- 删除只为样本贯通存在、已被正式仓库接口替代的查询与映射代码；
- 将仍有长期价值的临时逻辑提升为有明确职责、类型和测试的正式模块；
- 清理生成器中的一次性补丁；无法从数据源稳定推导的例外应进入显式配置或审计报告；
- 不得为了兼容尚未发布的 Next 中间存档而保留双模型、双解释器或静默回退；
- 以仓库搜索、依赖图、完整测试和文档核对确认脚手架已移除，再开始扩展完整模拟与投影。

### 第四阶段：投影和显示

从统一 receipt 生成资源曲线、状态条、合法性、战斗日志、伤害详情、长图和移动只读视图。

## 3. 架构整改关注点

技能编辑工作区直接编辑统一的 `SkillDefinition` 草稿，项目只保存完整 `customDefinition`，右侧属性面板只显示来源状态与入口。当前已支持顶层帧字段、费用、初始动作黑板、释放条件、主体调度序列和事件监听器；监听器行为与主体共用 `ScheduledSequenceDefinition` 和 `CombatStepDefinition`，没有第二套执行格式。首段连携注册属于干员定义，不进入技能块编辑器；后续段窗口仍由技能序列中的 `openComboWindow` 步骤编辑。`ScheduledSequenceEditor` 统一维护单条序列的帧范围、步骤选择和步骤增删移动，主体技能与事件监听器只负责各自的集合级操作。当前全部可执行步骤均可创建、删除、复制和调整顺序，并为伤害、元素、资源、状态、Buff、定时标记、上下文、特殊回能和时间膨胀提供专用参数控件。时间膨胀表单直接维护普通/终结技步骤的判别联合，内联曲线完整保留 Unity 关键帧参数，不经过第二套 UI 数据格式。伤害计算分支、按状态层数追加倍率、资源变化元数据和六类状态修正也已接入结构化编辑。`conditional` 和 `once` 可递归维护嵌套步骤，22 种条件节点均可编辑完整参数，其中敌人 rank 条件使用独立的三值原生身份而不是展示 tier。编辑器会在主体与监听器范围内统一维护伤害步骤稳定键，逐等级字段只修改当前等级，并实时展示严格校验问题。下一阶段主要补齐少数动态数值模式切换，并人工验证复杂表单。

当前“所有步骤可创建”不等于“所有可选参数都已覆盖”。仍需补齐伤害计算路径与动态倍率、资源获取元数据、状态修正器，以及技能定义中的 `blackboard`、`availability` 和事件处理器。新增能力必须继续按判别联合提供专用组件，不能退化为 JSON 或任意键值编辑器。

近期已经完成：

- 编译后唯一执行阶段；
- 标准伤害环境能力预检；
- 干员 Buff runtime 单一所有权；
- 面板、敌人和静态伤害快照进入正式模拟入口；
- 随机流与非随机运行时快照分离；
- 敌人 `CombatVitals` 的场景共享所有权：连续失衡账本由场景装配创建并注入标准伤害环境、条件求值和结果收集，最终生命结果不再回退到静态敌人数值。

下一项核心边界是失衡节点事件：在敌人账本已由场景共享、真实阈值已进入编译结果的基础上，导出节点 Buff，闭合跨阈值事件、短暂硬直和处决回能。

## 4. 入口切换条件

只有同时满足以下条件，才考虑将 `/timeline` 指向 Next：

- 主流构筑和时间轴编辑流程完整；
- 旧项目迁移行为明确且有真实 fixture；
- 关键干员和配装模拟可与游戏样本核对；
- 资源、状态和伤害投影满足用户排轴需求；
- 快捷键、撤销、导入导出和主要视觉完成回归；
- 不支持能力在 UI 中明确可见，不产生静默错误；
- 性能至少不劣于旧版主要操作路径。

## 5. 更新方式

- 每完成一项跨层闭环，更新本页和功能矩阵。
- “模块已有单测”只能写为部分接入；必须经过生产入口才可写为已接入。
- 短期开发任务放在整改路线图，长期职责保留在本文件库。
