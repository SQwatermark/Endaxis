# Endaxis Next 当前状态与路线图

本文只给出架构级状态。逐功能的定义、编译、执行和 UI 门槛以[功能迁移矩阵](../architecture/endaxis-next-feature-matrix.md)为准。

## 1. 当前状态

### 已接入

- V2 项目 schema、结构校验、序列化和迁移端口；
- 只读游戏目录接口与默认目录装配；
- 干员/武器/装备/敌人的选择和部分编辑流程；
- 场景 build 解析、装备贡献、敌人编译和干员面板解析；
- 技能 DSL、等级值编译、时间轴输入编译；
- 编辑会话、撤销/重做、复制粘贴和基本时间轴命令；
- 战斗时钟、资源、技能、冷却、黑板和回执基础；
- Buff、Status、Marker、属性、伤害和附着的若干独立运行时模块；
- 技力、终结技能量、失衡、附着、状态和技能诊断的投影基础；
- 标准生命伤害场景的编译、能力预检、模拟和最终生命结果；
- Next 页面、按需游戏文本、主题基础和部分旧版兼容 UI。

### 部分接入

- 干员目录：正式 Next 定义覆盖有限，生成器仍在扩充完整行为、天赋和潜能。
- 武器与装备：选择、静态面板和部分贡献可用，战斗期特殊效果未完整安装。
- 敌人：通过旧数据适配器过渡，完整来源生成和多节点失衡仍待验证。
- 元素系统：基础附着和复合工厂模块存在，完整反应目录和场景装配未闭环。
- 伤害：标准生命伤害已贯通，单节点失衡执行/恢复与目录驱动元素附着已接入标准环境；处决、生命汲取和状态依赖分支仍需扩展正式环境。
- 时间轴 UI：主要布局和编辑基础存在，尚未达到旧版全部交互和投影能力。
- Pipeline：通用 revision/cache 基础存在，正式应用入口尚未全面采用分阶段缓存。

### 尚未闭环

- 全干员、全武器、全装备和套装的严格可执行目录；
- 完整玩家主动战斗环境；
- 终结技、连携窗口、活动机制和所有特殊资源的端到端模拟；
- 完整战斗日志、伤害归因和分析界面；
- 旧存档迁移的真实样本覆盖；
- 与旧版 UI 的完整视觉和交互回归；
- `/timeline` 正式入口切换。

## 2. 当前优先级

### 第一阶段：实例选择和编辑

优先贯通干员、武器、装备和敌人的选择、配置、筛选、面板查看与持久化。技能实例高级编辑暂缓。

### 第二阶段：时间轴编辑

补齐轨道选择/排序、技能库、拖拽、框选、多选、复制粘贴、上下文菜单和快捷键作用域，并保持旧版主要视觉。

### 第三阶段：完整模拟

以当前标准伤害闭环为基础，按状态所有权逐步接入：

1. 敌人 `CombatVitals` 的场景共享所有权；
2. 失衡执行和恢复；
3. 实际 Buff 和装备事件安装；
4. 元素附着与反应；
5. 连携窗口、终结技和特殊干员机制；
6. 完整 receipt 与运行时结果。

### 第四阶段：投影和显示

从统一 receipt 生成资源曲线、状态条、合法性、战斗日志、伤害详情、长图和移动只读视图。

## 3. 架构整改关注点

近期已经完成：

- 编译后唯一执行阶段；
- 标准伤害环境能力预检；
- 干员 Buff runtime 单一所有权；
- 面板、敌人和静态伤害快照进入正式模拟入口；
- 随机流与非随机运行时快照分离。

下一项核心边界是敌人 `CombatVitals`：生命条件、伤害写入、未来失衡推进和最终结果必须共享同一场景实例，而不是由专用伤害环境私有保存。

## 4. 入口切换条件

只有同时满足以下条件，才考虑将 `/timeline` 指向 Next：

- 主流构筑和时间轴编辑流程完整；
- 旧项目迁移行为明确且有真实 fixture；
- 关键干员和配装模拟可与游戏样本核对；
- 资源、状态和伤害投影满足用户排轴需求；
- 快捷键、撤销、导入导出和主要视觉完成回归；
- 不支持能力在 UI 中明确可见，不产生静默错误；
- 性能至少不劣于旧版主要操作路径。

## 5. 更新方式

- 每完成一项跨层闭环，更新本页和功能矩阵。
- “模块已有单测”只能写为部分接入；必须经过生产入口才可写为已接入。
- 短期开发任务放在整改路线图，长期职责保留在本文件库。
