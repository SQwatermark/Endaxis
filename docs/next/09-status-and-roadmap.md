### 部分接入

- 干员目录：正式 Next 定义覆盖有限，生成器仍在扩充完整行为、天赋和潜能。
- 武器与装备：选择、静态面板、定义严格校验和动态事件装配已接入；真实特殊效果数据覆盖、内部冷却样本及装备触发伤害的来源分类仍待闭环。
- 敌人：通过旧数据适配器过渡；当前 82 个定义已从 1.4.4 模板资产捕获原生 `rank`，并贯通项目实例、编译与 `CheckEnemyRank` 条件求值。失衡节点阈值语义已验证，节点 Buff 与节点事件仍待闭环。
- 敌人模型边界：敌人永久是单一木桩，不实现敌方技能、攻击、AI 或动画时钟，也不由运行时自动生成玩家受击。只有无法通过正常模拟渠道产生、又确实影响干员机制的事实才允许由时间轴外部事件补入；能由技能、Buff、治疗、资源或其他正常操作链产生的事件不得转走外部系统。默认没有标记时相关监听器保持休眠。外部事件的伤害标签、特征和数值只按真实消费者证据逐项增加，无法投影且不影响主动输出链的行为可以明确放弃。
- 元素系统：基础附着和复合工厂模块存在，完整反应目录和场景装配未闭环。
- Buff 行为：内联定义、等级编译、严格校验、实例级生命周期执行器和正式战斗操作链已贯通；技能编辑器可为八个生命周期阶段搭建与技能相同的有序步骤。原生图标身份、可见性、显示位和排序元数据现已贯穿生成、审计、外部定义适配与运行时，Buff Inspector 会实际渲染图标并在缺图时保留 ID；活动 Buff 状态栏投影仍待接入。图标是必要展示身份，不能因不参与数值模拟而丢弃；粒子、音效、镜头等纯表现仍可延后。外部元素 Buff 的旧低层动作协议仍待迁移。
- 伤害：标准生命伤害、处决伤害与连续失衡账本的执行/恢复已贯通；处决会按敌人配置和技能倍率回复技力，目录驱动元素附着已接入标准环境。失衡节点效果、生命汲取和状态依赖分支仍需扩展正式环境。
- 治疗：普通 `HealAction` 已贯通严格源解析、DSL、等级编译、技能编辑器、标准场景执行和回执。场景为每名已解析面板的干员建立初始满血账本；公式既支持“治疗来源四维属性 × 倍率 + 固定值”，也支持原生 `DefiniteValueCalculation` 的直接动作值，后者不会伪造属性依赖。目标支持施法者、Buff 来源、Buff 宿主、当前主控、生命比例最低者及排除主控后的生命比例最低者。Buff 即使在接受者容器中执行也保留原始治疗来源。即使目标满血也执行并分别记录原始治疗量、实际治疗量和溢出治疗。`ModifyHealCalcResult` 已按反汇编证据接入 `AfterCalculation` 的 healer/receiver 两侧 Buff 修正，当前严格子集支持目标生命比例和 Buff 黑板条件，公式为 `value *= 1 + baseMultiplier * multiplierCount`。雪绒连携的能力实体 Aura、队友 Buff 宿主治疗和低血量治疗增益已形成生产闭环。治疗标签只保留原生整数身份。后续仍需补结果投影，并只在确有必要时由最小外部受击事实改变实际/溢出分配。
- 时间轴 UI：主要布局和编辑基础存在；模拟结果以完整已发布快照原子替换，等待或失败时保留上一份技能起点、效果和命中投影。实时性能审计已展示最近模拟的分阶段墙钟耗时、预算和最慢阶段，尚未达到旧版全部交互和投影能力。
- Pipeline：通用 revision/cache 基础存在，正式应用入口尚未全面采用分阶段缓存。
- 连携窗口：干员级首段注册、伤害/附着语义事件、内部续段步骤、按干员候选账本、暂停计时、同帧轨道排序、候选黑板传递、当前激活项消费和窗口失败诊断已接入；复杂条件覆盖、立即施法和 UI 激活间隔尚未闭环。
- 时间膨胀：技能定义、编译器、生成器、普通/终结技动作执行器、公共配置以及技能、冷却、Buff、失衡各自的时钟已接入标准模拟。项目横轴、放置输入、外部标记、控制切换与模拟范围统一使用实际战斗帧；每个对象只消费自己的 `default/global/self/cooldown` 等局部增量，不建立统一模拟速度或全局逻辑时间。原先用于推迟输入和双标尺的全局积分映射已删除。常态只在时间膨胀来源技能块内显示按持续量裁剪的流光；悬停或选中来源块时才沿全部轨道纵向展开带持续秒数的黑色区间。拖动直接写回鼠标实际帧，主块及其时间膨胀投影即时跟手，依赖模拟的其他投影以约 30Hz 更新且首个有效位移立即触发，松手等待最终新快照发布后再撤销预览。技能块宽度现由每个施法实例按施法者 `selfScaledDelta` 累计到 `timelineBlockFrames` 后发布的实际结束边界决定；动作序列提前结束或被下一技能中断不会截断块宽累计，连线块端点也消费同一实际宽度。场景编译器按 `castId + stepKey` 为根技能、控制流和能力实体子技能递归绑定稳定 `hitId`；块内命中标记、提示归因与命中连线优先消费 `DamageApplied` 的首次实际帧，同帧附着和反应按同一 `castId` 归组，定义局部偏移只在尚无运行回执时保底。技能编辑器可以查看和编辑两类时间膨胀步骤，包括公共命名曲线与完整内联关键帧。当前版本还从固定哈希的 `GameplayTagConfig` 生成 652 项完整路径目录；槽位与原生优先级来源均以命名下拉显示，Buff、实体条件、治疗、资源恢复等其余标签入口复用同一可搜索选择器，底层仍保存原生 int32。关键帧不完整的公共曲线继续严格拒绝。

## 3. 架构整改关注点

技能编辑工作区直接编辑统一的 `SkillDefinition` 草稿，项目只保存完整 `customDefinition`，右侧属性面板只显示来源状态与入口。当前已支持顶层帧字段、费用、初始动作黑板、释放条件、主体调度序列和事件监听器；监听器行为与主体共用 `ScheduledSequenceDefinition` 和 `CombatStepDefinition`，没有第二套执行格式。首段连携注册属于干员定义，不进入技能块编辑器；后续段窗口仍由技能序列中的 `openComboWindow` 步骤编辑。`ScheduledSequenceEditor` 统一维护单条序列的帧范围、步骤选择和步骤增删移动，主体技能与事件监听器只负责各自的集合级操作。当前全部可执行步骤均可创建、删除、复制和调整顺序，并为伤害、元素、资源、状态、Buff、定时标记、上下文、特殊回能、时间膨胀和能力实体提供专用参数控件。能力实体蓝图已移入干员构筑弹窗的附属对象工作区：生成蓝图保持版本化只读，项目只保存新增/覆盖定义，公共表只展示 ID 且不可改写；技能步骤通过合并后的 ID 选择器引用蓝图，只维护本次生成参数。子技能递归复用初始黑板、调度序列和战斗步骤编辑器，不引入共享模板选择器，也不提供独立费用、冷却或施法身份。默认 Next 项目提供已选中的 Arclight 终结技生成样本，其能力实体含两段真实局部子时间线；样本因既有零倍率时间停滞默认禁用模拟。时间膨胀表单直接维护普通/终结技步骤的判别联合，内联曲线完整保留 Unity 关键帧参数，不经过第二套 UI 数据格式。伤害计算分支、按状态层数追加倍率、资源变化元数据和六类状态修正也已接入结构化编辑。`conditional` 和 `once` 可递归维护嵌套步骤，22 种条件节点均可编辑完整参数，其中敌人 rank 条件使用独立的三值原生身份而不是展示 tier。编辑器会在主体与监听器范围内统一维护伤害步骤稳定键，逐等级字段只修改当前等级，并实时展示严格校验问题。下一阶段主要补齐能力实体时间膨胀查询的编辑表单和少数动态数值模式切换，并继续用真实复杂样本人工验证递归表单。

`buff_chr_*` 蓝图现属于干员级 `buffDefinitions`，与技能等级解耦；非角色前缀的公共/系统 Buff 由版本化游戏数据仓库提供同一份只读表。技能的 `applyBuff` 只保存稳定 ID、施加目标和实例黑板赋值。编辑器后续必须增加“干员附属对象”工作区，支持创建、复制、删除和编辑自定义角色 Buff，校验干员内 ID 唯一性，并让技能步骤通过选择器引用已有 ID；公共 Buff 只能选择引用、不得编辑，也不得重新把完整定义复制回每个技能步骤。项目存档与自定义干员模型在该工作区落地前仍需保持兼容边界明确。

当前“所有步骤可创建”不等于“所有可选参数都已覆盖”。仍需补齐伤害计算路径与动态倍率、资源获取元数据、状态修正器，以及技能定义中的 `blackboard`、`availability` 和事件处理器。新增能力必须继续按判别联合提供专用组件，不能退化为 JSON 或任意键值编辑器。
