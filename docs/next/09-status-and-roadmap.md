# Endaxis Next 当前状态与路线图

本文只给出架构级状态。逐功能的定义、编译、执行和 UI 门槛以[功能迁移矩阵](../architecture/endaxis-next-feature-matrix.md)为准。

## 1. 当前状态

### 已接入

- V2 项目 schema、结构校验、序列化和迁移端口；
- 只读游戏目录接口与默认目录装配；
- 干员/武器/装备/敌人的选择和部分编辑流程；
- 场景 build 解析、装备贡献、敌人编译和干员面板解析；
- 技能 DSL、等级值编译、时间轴输入编译；
- 编辑会话、撤销/重做、复制粘贴和基本时间轴命令；
- 战斗时钟、资源、技能、冷却、黑板和回执基础；
- Buff、Status、Marker、属性、伤害和附着的若干独立运行时模块；
- 技能与内联 Buff 共用的同步有序步骤执行器，以及按 Buff 实例隔离的生命周期序列适配器；
- 技力、终结技能量、失衡、附着、状态和技能诊断的投影基础；
- 标准生命伤害场景的编译、能力预检、模拟和最终生命结果；
- Next 页面、按需游戏文本、主题基础和部分旧版兼容 UI。

### 部分接入

- 干员目录：正式 Next 定义覆盖有限，生成器仍在扩充完整行为、天赋和潜能。
- 武器与装备：选择、静态面板、定义严格校验和动态事件装配已接入；真实特殊效果数据覆盖、内部冷却样本及装备触发伤害的来源分类仍待闭环。
- 敌人：通过旧数据适配器过渡；当前 82 个定义已从 1.4.4 模板资产捕获原生 `rank`，并贯通项目实例、编译与 `CheckEnemyRank` 条件求值。失衡节点阈值语义已验证，节点 Buff 与节点事件仍待闭环。
- 敌人模型边界：敌人永久是单一木桩，不实现敌方技能、攻击、AI 或动画时钟，也不由运行时自动生成玩家受击。只有无法通过正常模拟渠道产生、又确实影响干员机制的事实才允许由时间轴外部事件补入；能由技能、Buff、治疗、资源或其他正常操作链产生的事件不得转走外部系统。默认没有标记时相关监听器保持休眠。外部事件的伤害标签、特征和数值只按真实消费者证据逐项增加，无法投影且不影响主动输出链的行为可以明确放弃。
- 元素系统：基础附着和复合工厂模块存在，完整反应目录和场景装配未闭环。
- Buff 行为：内联定义、等级编译、严格校验、实例级生命周期执行器和正式战斗操作链已贯通；技能编辑器可为八个生命周期阶段搭建与技能相同的有序步骤。外部元素 Buff 的旧低层动作协议仍待迁移。
- 伤害：标准生命伤害、处决伤害与连续失衡账本的执行/恢复已贯通；处决会按敌人配置和技能倍率回复技力，目录驱动元素附着已接入标准环境。失衡节点效果、生命汲取和状态依赖分支仍需扩展正式环境。
- 治疗：普通 `HealAction` 已贯通严格源解析、DSL、等级编译、技能编辑器、标准场景执行和回执。场景为每名已解析面板的干员建立初始满血账本；公式既支持“施法者四维属性 × 倍率 + 固定值”，也支持原生 `DefiniteValueCalculation` 的直接动作值，后者不会伪造属性依赖。目标支持施法者、当前主控、生命比例最低者及排除主控后的生命比例最低者。即使目标满血也执行并分别记录原始治疗量、实际治疗量和溢出治疗。Ember 连携与 Gilberta 战技/连携已移除治疗豁免并生成正式步骤；Liino 连携的 `final_heal_value` 已通过直接治疗链解析，但技能整体仍停在能力实体时间膨胀闭包。治疗标签只保留原生整数身份。后续仍需补治疗语义事件消费者、结果投影，以及在确有必要时由最小外部受击事实改变实际/溢出分配。
- 时间轴 UI：主要布局和编辑基础存在；模拟结果以完整已发布快照原子替换，等待或失败时保留上一份时间映射、技能起点、效果和命中投影。实时性能审计已展示最近模拟的分阶段墙钟耗时、预算和最慢阶段，尚未达到旧版全部交互和投影能力。
- Pipeline：通用 revision/cache 基础存在，正式应用入口尚未全面采用分阶段缓存。
- 连携窗口：干员级首段注册、伤害/附着语义事件、内部续段步骤、按干员候选账本、暂停计时、同帧轨道排序、候选黑板传递、当前激活项消费和窗口失败诊断已接入；复杂条件覆盖、立即施法和 UI 激活间隔尚未闭环。
- 时间膨胀：技能定义、编译器、生成器、普通/终结技动作执行器、公共配置以及技能、冷却、Buff、失衡各自的时钟已接入标准模拟。项目输入按逻辑时间调度，实例生命周期回执与逻辑/实际时间双向映射已贯通；UI 已接入实际起点、双标尺、光标、连线、曲线宽度及全局/实体时间区间。常态只在时间膨胀来源技能块内显示按持续量裁剪的流光；悬停或选中来源块时才沿全部轨道纵向展开带持续秒数的黑色区间。拖动改为冻结按下时映射并以逻辑/实际锚点加鼠标实际位移，不再用包含拖动源自身冻屏的整局逆映射回算；主块及其时间膨胀投影即时跟手，依赖模拟的其他投影以约 30Hz 更新且首个有效位移立即触发，松手等待最终新快照发布后再撤销预览。技能编辑器可以查看和编辑两类时间膨胀步骤，包括公共命名曲线与完整内联关键帧。实体变速后的技能块实际宽度仍待完成，关键帧不完整的公共曲线继续严格拒绝。
- 能力实体：已从 1.4.4 模板资产建立 54 个严格证据定义，并按零距离、全范围、单敌人约束接入场景级逻辑目录、生成步骤、owner/实体 ID Context 组查询、可选计数输出、稳定句柄迭代、有限时长读取/比较/赋值、生命周期推进和审计回执。原生 born tags 仅留在模板证据；生成器对受支持的标签查询求值后输出明确的 `abilityEntityIds`，生产 DSL 和运行时不再解释裸标签。生成器已闭环庄方宜的 `Context ForEach -> LT -> InputTarget/Assign` 时长形状，并对全语料 10 个时长赋值做严格载荷校验。原生反汇编已证明 `setMultipleTarget=false` 是一次单目标调用；生成器现在只对“此前确定逻辑生成且未被普通目标组复用”的命名 Context 建立 0/1 单例证明并复用统一迭代逻辑。Li Zhiyan 战技的能力实体子技能中无筛选的 `Owner -> Target` 距离条件，在当前实体与唯一输入敌人身份均已证明后复用统一零距离折叠。其连携技的四个封印实体只有表现子动作，`BL/BR/FL/FR` 又都是无筛选固定位置，因此逻辑生成会丢弃空间目标但保留四个实例与八个时长赋值；同技能的单标签时间膨胀查询由模板 born-tag/引用文件证明只命中这些实例，并正式生成实体 ID 目标集合。`trigger` 的两路敌人合并与一条固定点回退现由控制流穷尽证明为恒非空；固定点仍不是敌人，后续数量守卫直接保留成功分支而不生成 `singleEnemyPresent`。诀（`arcane`）由此达到 11/11 严格技能入口可编译。能力实体 `TimeDilationAction` 的 owner-spawned 与命名 Context 查询已进入正式 DSL/执行器；全局和终结技动作会按原生数据把这些实体加入排除集合，Entity 分支也能逐实例安装倍率。DSL、编译器和运行时支持把无费用/冷却/施法身份的子技能时间轴内嵌到生成步骤；每个实体实例复用统一动作序列解释器，并用与自身寿命相同的局部倍率推进，结束实体时会对称结束活动序列。生成器现对完整动作集仅含伤害、已投影固定周期伤害、附着、动作黑板修改、资源获得、已证明的施法者目标 Buff、严格内联的实体 Owner Buff、直接 `FinishOwnerAction(Owner)` 与可编译局部条件，且原生 `assignBlackboard=true` 的严格子集执行原子迁移；跳转另要求唯一根/分支动作、完整条件与分段终止证明。Arclight、Gilberta、Laevatain、Fluorite、Lifeng 的相应子图以及庄方宜审计中的普攻二、四、五已改为实体局部帧，父时间轴对应投影同时删除。Lifeng 的局部 67 帧外层 `IfElse` 跳转被保留为一次性条件分支，失败时仍执行原黑板写入；其 `ultimate` 仍因其他明确行为缺口保持 partial。直接结束宿主已接入运行时，庄方宜三个样本保留局部帧 897，重复同帧结束按终止语义去重；条件结束仍未闭环，其他未获闭包证明的 Entity `effectTargets` 继续显式阻塞。当前严格全量审计为 317 个可解析、281 个可编译，零角色专用声明完整直转 11 名；解析数下降来自新治疗 parser 对 Liino 非乘属性治疗公式的严格拒绝，不是已建模行为回退。空间组件不建模；一般多实例 Context 的单目标选择顺序、复杂实体 Buff、目标变更和其余子图迁移仍待闭环。
- 能力实体 Buff 不另建简化 ID 表：`currentAbilityEntity` 只作为 Buff 施加目标出现在已有子/Context 目标作用域中。场景为首次成为 Buff 目标的实例惰性创建标准 Buff 容器，共享实体黑板与实体四路时钟，并在宿主结束时对称清理；生命周期序列保留同一实体句柄，周期回调可经统一操作链结束宿主。Gilberta 战技的真实监视 Buff 已严格识别为每 0.15 秒执行一次 `CheckHp(Source ratio <= 0) -> FinishOwnerAction(Owner)`，并转换为来源死亡通知驱动的宿主结束。标准玩家伤害环境现有干员满血账本供正常治疗和生命条件读取，但不会凭空制造伤害或死亡；来源死亡仍只能来自已证明的正常事实或最小外部事实。Yvonne 与 Li Zhiyan 的其余两个 Owner-Buff 消费者仍分别受复杂条件/伤害/资源动作及 Buff 结束/owner-tag 实体结束/Aura 阻塞。
- 能力实体直接结束默认只迁移线性末端形状；带跳转子图另需通过严格分段终止证明。桌面原生模块已确认 `FinishOwnerAction` 按目标 Entity 类型分派，能力实体的 `ObjectType=0x200` 进入通用完成路径。Fluorite 原始列表中的 89/90 与 149/150 两组伤害/结束实际受两条 frame-0 `JumpToAction` 控制：目标死亡跳 89，目标持有终结技 Buff 跳 149，属于替代路径而非结束后的继续执行。`JumpToAction` 会在首次执行及后续每个 Tick 重试条件，第一次通过后只跳一次；原生时间轴会跳过起始时间严格早于目的帧的待执行序列、结束在目的帧前已终止的活动序列，并保留跨越目的帧的活动序列与恰在目的帧开始的待执行序列。原生 `OnTick` 还确认跳转发生后本帧内部处理立即停止，目的帧动作留到下一 Tick。Next 的统一 `jumpTimeline` 控制步骤支持条件首次检查与逐 Tick 重试、单次跳转、执行中重入、普通技能和能力实体子技能局部帧改写，并复用 `TimelineActionProcessor.jumpTo` 完成游标迁移。生成器对直接跳转只接受唯一根动作、精确根路径、前向目的地、完整直接条件以及每个目的区段均显式终止的形状；Fluorite 已命中该子集。外层 `IfElse` 跳转另要求根容器与成功分支各自只有该动作、直接条件为空、外层条件可编译且路径精确关联，并生成一次性条件分支而非可重试条件；Lifeng 已命中该形状，失败分支黑板写入保持不变。其他条件类型、多动作 Sequence 和外层控制流同样不得借用这两个子集。

- 技能冷却立即调整已闭环 `Reduce + 基础周期比例`、`Set + 基础周期比例` 和 `Set + 绝对秒数`，并让根时间轴与条件分支共用严格解析、DSL、运行时和编辑器。Rossi 连携技 2 的条件清零自身冷却与连携技 3 对二段连携重置完整周期已严格编译；全量审计最新为 317/320 可解析、283/320 可编译、12 名零专用声明完整直转。绝对值 `Reduce` 没有当前干员样本和语义证据，继续拒绝。
- 能力实体 Context 横向消费现要求支配写入严格证明 `OwnerSpawnedEntityFinder + AbilityEntity + TagValidator`，并允许仅改变集合优先级的 `PriorityFilter`；通过后，Buff 会在 `forEachContextTarget` 中以 `currentAbilityEntity` 为目标逐实例施加。固定 `Target/MainTarget/Context smart_target` 的序列化残留组键不再错误破坏唯一敌人身份，`CharacterTeamFinder + MainCharacterValidator` 也按实际 finder 语义解析主控治疗目标。能力实体 `ActionOwner` 现还能作为独立 Buff 来源，由运行时从当前稳定句柄解析 source ID；Camille 战技的投射物命中子图因此可先生成蝙蝠，再把实体 Buff、伤害和附着整体迁入局部时间轴。Ardelia 下落攻击、Yvonne 终结技收尾及 Camille 三个技能新增通用 DSL 覆盖，Camille 达到 12/12；当前严格审计为 317/320 可解析、288/320 可编译、13 名零专用声明完整直转。Avywenna 与 Tangtang 已越过实体距离守卫，但分别停在复合投射物子图和条件能力实体生成，仍未虚报完整。
- Buff 来源中的 `ContextTarget/smart_target` 与普通目标解析共享唯一敌人归约，不再因来源字段使用了 Context 身份而阻塞；Yvonne 战技因此进入通用 DSL。当前严格审计为 318/320 可解析、289/320 可编译、13 名完整直转。Yvonne 连携、Tangtang 连携与 Liino 连携的无标签 owner-spawned Entity 时间膨胀仍可能命中此前技能留下的任意实体，在全干员实体闭包完成前不能按“当前技能实体”缩窄。

- 能力实体定义内联：`spawnAbilityEntity` 现在使用 `abilityEntityId + definition`，逐使用点携带默认生命周期和可选子技能。born tags 与 `maxStackingCount` 留在 VFS 证据层；生成器把受支持的 owner-spawned 标签查询严格降为明确的 `abilityEntityIds`，生产 DSL、编辑器、编译器和运行时均不再携带无语义标签或共享模板注册表。技能编辑器可递归编辑实体子技能；普通全局、普通实体和终结技时间膨胀表单也能编辑明确实体 ID 或 Context 组查询，不会重新引入 born-tag 字段。
- 诀（`arcane`）生成审计：11 个技能入口已作为 `outputStage: audit` 样本落盘并通过定向生成检查，但不属于正式目录。`seal_total -> seal/listener -> 隐藏结束技能` 已闭环，Interrupt 在无敌方主动行为模型中归约为零效果。形态实体黑板已从基础被动自动派生并在技能创建前写入共享实体黑板。终结技的原生 `ChangeSkillAction` 也已结构化：首段直接 Buff 在启用时把 `UltimateSkill` 换成二段并指定还原首段，二段自身第 0 帧永久换回首段，audit 已严格输出 `ultimate -> arcana -> ultimate`。稳定技能组支持不可直接放置的 `replacementSkills`；场景为同一 `castId` 编译全部形态，能力系统在释放开始时快照当前槽技能，`changeSkillSlot` 只影响未来释放。生成器现已消费闭环关系：诀在 manifest 明确声明 `arcana` 为运行时替换形态后，首段第 47 帧在监听 Buff 后生成换到 `arcana` 的步骤，二段按原生第 0 帧动作生成换回 `ultimate` 的步骤。只有明确声明的不可放置形态才进入 `replacementSkills`；庄方宜等普通/强化技能继续作为独立技能组供用户拖放，不从原生换技动作猜测编辑器语义。下一项干员级阻塞转为形态展示、形态感知连携注册、天赋和潜能对照。

### 尚未闭环

- 全干员、全武器、全装备和套装的严格可执行目录；
- 完整玩家主动战斗环境；
- 终结技、连携窗口、活动机制和所有特殊资源的端到端模拟；
- 完整战斗日志、伤害归因和分析界面；
- 旧存档迁移的真实样本覆盖；
- 与旧版 UI 的完整视觉和交互回归；
- `/timeline` 正式入口切换。

生成版佩丽卡现已作为第一条单干员生产模拟验收样本。该样本从项目文档出发，覆盖完整普攻链、连携、战技、终结技、下落攻击和处决，并保留连携与终结技的原生时间膨胀动作。Arclight 与佩丽卡组成的双轨样本进一步覆盖主控身份、共享技力、跨干员伤害以及连携窗口的开启和消费；场景装配会从轨道和主控切换记录推导主控身份，不要求外部环境重复注入。它们证明生成产物可以进入正式多干员模拟入口，但不代表时间投影、全部特殊机制或全干员目录已经闭环。

Arclight 战技的叠层增益现已从 `OnBuffEnhanceChanged` 生成完整运行时序列：读取静态面板智识、按原生黑板倍率计算、向全队施加限时电伤提升，并在伤害快照中与静态构筑增伤叠加。原生 `isConvertedAttribute` 保留为 converted 来源身份。表现子 Buff 除逐技能 manifest 显式忽略外，只会在定义结构完整证明唯一行为是 `EffectAction` stack effect 时自动剔除，不能按名称推断。相同内联边界也支持 Lifeng/Estella 已证明的物理脆弱生命周期形状。达坂第一天赋已经闭环：冷却百分比以配置基础周期为基数，旧式 Buff 结束按已证明的插入顺序和来源限制执行，9 个技能入口完整生成。证据见 [Buff stack effect 与达坂第一天赋证据](../research/buff-stack-effect-and-dapan-talent-evidence.md)。

除首个佩丽卡样本外，当前生成目录又注册了九名正式定义；其中一些定义仍通过 `conversionSupport` 明确声明局部缺口，不能称作整名干员完整转换。Endministrator 的 Buff 点燃已经通过生产场景：连携创建冻结，终结技执行直接与条件伤害、分发 `EndminUlt` 响应并结束冻结。Last Rite 普通战技也已进入完整生产链：`main_start -> self -> party main Buff` 递归内联，实际 Buff 宿主负责主控条件、资源、标记与事件执行，后代敌方分身 Buff 由当前创建来源干员归因，原始施法快照仍用于定位技能程序；双轨回归已验证队友末段普攻触发分身伤害和元素附着。manifest 不再保留 `main_start/self` 的 `unmodeledBuffIds`。当前 manifest 全量生成通过：10 名输出正式定义，庄方宜和诀继续保持审计阶段。直接输入和延迟接续施放共用施放前事件/连携参数准备路径；隐藏天赋技能、附加技能、复杂 Buff、未闭环能力实体集合操作和混合养成载荷继续作为明确缺口保留。

## 2. 当前优先级

### 第一阶段：实例选择和编辑

优先贯通干员、武器、装备和敌人的选择、配置、筛选、面板查看与持久化。技能实例高级编辑暂缓。

在官方干员实例流程稳定、`OperatorDefinition` 结构收敛后，按[自定义干员设计](../architecture/endaxis-next-custom-operators.md)接入项目级自定义干员。自定义干员与官方干员复用定义、校验、编译和模拟链；支持复制现有模板与从空白模板创建，不建立第二套战斗模型。首个稳定存档版本前不为这一过程中的 schema 变化编写迁移。

### 第二阶段：时间轴编辑

补齐轨道选择/排序、技能库、拖拽、框选、多选、复制粘贴、上下文菜单和快捷键作用域，并保持旧版主要视觉。

### 第三阶段：完整模拟

以当前标准伤害闭环为基础，按状态所有权逐步接入：

1. 敌人 `CombatVitals` 的场景共享所有权；
2. 失衡执行和恢复；
3. 扩大实际 Buff 和装备事件的数据覆盖，闭环内部冷却与叠层样本；
4. 元素附着与反应；
5. 扩大连携条件求值覆盖，接入立即施法、UI 激活间隔、终结技和特殊干员机制；
6. 完整 receipt 与运行时结果。

Buff 生命周期装配应先于扩大全干员生成范围：由场景装配层按来源与所属实体建立 Buff 操作上下文，使伤害、资源、状态、事件归因都使用 Buff 自身身份。不得直接复用某次技能释放的 `SkillRuntime`，也不得在缺少操作链时忽略生命周期步骤。

### 明确重点待办：时间膨胀的 UI 投影

原生动作、时钟、输入推迟、生命周期回执和双向时间映射已接入。下一阶段不再重做冻结算法或在 UI 猜测时长，只消费模拟结果：

- 补充实体变速后的技能块实际宽度事实；
- 手工验收冻屏源跨出自身阴影、阴影同步移动、松手不回弹和后续技能块稳定性；拖拽只写回项目逻辑帧，手势实际帧只属于瞬时预览，不能进入项目存档；
- 补齐 `interrupt_weakness` 的完整关键帧，并扩大生成器到更多真实技能样本；
- 验收覆盖连携技、终结技、嵌套或重叠实例、排除目标和不同时钟计时器。

### 迁移脚手架清理门槛

Next 迁移期间允许存在用于贯通新旧入口、生成审计和功能占位的临时代码，但这些内容不是长期架构。进入完整时间线模拟阶段前必须完成一次专项清理：

- 删除仅用于迁移旧技能快照、旧命中身份和旧编辑字段的适配器与回退分支；
- 删除只为样本贯通存在、已被正式仓库接口替代的查询与映射代码；
- 将仍有长期价值的临时逻辑提升为有明确职责、类型和测试的正式模块；
- 清理生成器中的一次性补丁；无法从数据源稳定推导的例外应进入显式配置或审计报告；
- 不得为了兼容尚未发布的 Next 中间存档而保留双模型、双解释器或静默回退；
- 以仓库搜索、依赖图、完整测试和文档核对确认脚手架已移除，再开始扩展完整模拟与投影。

### 第四阶段：投影和显示

从统一 receipt 生成资源曲线、状态条、合法性、战斗日志、伤害详情、长图和移动只读视图。

## 3. 架构整改关注点

技能编辑工作区直接编辑统一的 `SkillDefinition` 草稿，项目只保存完整 `customDefinition`，右侧属性面板只显示来源状态与入口。当前已支持顶层帧字段、费用、初始动作黑板、释放条件、主体调度序列和事件监听器；监听器行为与主体共用 `ScheduledSequenceDefinition` 和 `CombatStepDefinition`，没有第二套执行格式。首段连携注册属于干员定义，不进入技能块编辑器；后续段窗口仍由技能序列中的 `openComboWindow` 步骤编辑。`ScheduledSequenceEditor` 统一维护单条序列的帧范围、步骤选择和步骤增删移动，主体技能与事件监听器只负责各自的集合级操作。当前全部可执行步骤均可创建、删除、复制和调整顺序，并为伤害、元素、资源、状态、Buff、定时标记、上下文、特殊回能、时间膨胀和能力实体提供专用参数控件。能力实体表单直接维护 `abilityEntityId + definition`、生成参数、实体黑板、生命周期与可选子技能；born tags 仅存在于生成证据，不进入编辑器。子技能递归复用初始黑板、调度序列和战斗步骤编辑器，不引入共享模板选择器，也不提供独立费用、冷却或施法身份。默认 Next 项目提供已选中的 Arclight 终结技生成样本，其能力实体含两段真实局部子时间线；样本因既有零倍率时间停滞默认禁用模拟。时间膨胀表单直接维护普通/终结技步骤的判别联合，内联曲线完整保留 Unity 关键帧参数，不经过第二套 UI 数据格式。伤害计算分支、按状态层数追加倍率、资源变化元数据和六类状态修正也已接入结构化编辑。`conditional` 和 `once` 可递归维护嵌套步骤，22 种条件节点均可编辑完整参数，其中敌人 rank 条件使用独立的三值原生身份而不是展示 tier。编辑器会在主体与监听器范围内统一维护伤害步骤稳定键，逐等级字段只修改当前等级，并实时展示严格校验问题。下一阶段主要补齐能力实体时间膨胀查询的编辑表单和少数动态数值模式切换，并继续用真实复杂样本人工验证递归表单。

当前“所有步骤可创建”不等于“所有可选参数都已覆盖”。仍需补齐伤害计算路径与动态倍率、资源获取元数据、状态修正器，以及技能定义中的 `blackboard`、`availability` 和事件处理器。新增能力必须继续按判别联合提供专用组件，不能退化为 JSON 或任意键值编辑器。

近期已经完成：

- 编译后唯一执行阶段；
- 标准伤害环境能力预检；
- 干员 Buff runtime 单一所有权；
- 面板、敌人和静态伤害快照进入正式模拟入口；
- 随机流与非随机运行时快照分离；
- 敌人 `CombatVitals` 的场景共享所有权：连续失衡账本由场景装配创建并注入标准伤害环境、条件求值和结果收集，最终生命结果不再回退到静态敌人数值。
- 长区间逐 Tick 动作：`repeatEachTick` 在区间开始及每次后续宿主更新执行嵌套序列，普通技能与能力实体子技能均可按原生整数舍入读取自己的局部执行帧。Liino 两项战技由此不再需要把 1646/1801 帧静态展开，全量 SkillData 达到 320/320 可解析；其后续 Aura 与 `OnAddedBuff` 缺口继续单独处理。
- 固定单敌人 Aura 的动作生命周期：严格闭合的根时间轴敌方 Aura 会在开始帧施加内联 Buff，并在结束帧通过实例句柄只结束本动作实际创建的 Buff。距离与范围按项目模型归约为命中唯一敌人，但标签、槽位、对象筛选、进出区域动作和嵌套 Aura 不会因此被省略。Liino 普通战技的 Aura 已穿过生成与运行时，首个阻塞推进到技能监听器 `OnTrulyExitFight`；全量编译数仍为 289/320。

下一项优先继续横向贯通正常模拟与干员转换：以全量审计中首个可形成“严格解析 → DSL → 标准场景执行 → 回执/结果 → 真实干员产物”闭环的动作缺口为单位推进。外部事件系统保持最小，只在普通操作链客观无法产生所需事实时使用；失衡节点事件等独立机制随后按同一闭环门槛接入。

## 4. 入口切换条件

只有同时满足以下条件，才考虑将 `/timeline` 指向 Next：

- 主流构筑和时间轴编辑流程完整；
- 旧项目迁移行为明确且有真实 fixture；
- 关键干员和配装模拟可与游戏样本核对；
- 资源、状态和伤害投影满足用户排轴需求；
- 快捷键、撤销、导入导出和主要视觉完成回归；
- 不支持能力在 UI 中明确可见，不产生静默错误；
- 性能至少不劣于旧版主要操作路径。

## 5. 更新方式

- 每完成一项跨层闭环，更新本页和功能矩阵。
- “模块已有单测”只能写为部分接入；必须经过生产入口才可写为已接入。
- 短期开发任务放在整改路线图，长期职责保留在本文件库。
