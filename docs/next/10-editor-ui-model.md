# Endaxis Next 编辑器交互模型

## 定义工作区统一设计（后续改造的权威规则）

本节规定目标设计；下文的实现记录不表示现状已经符合本节。Inspector 的属性描述、句柄和注册表仍以 `tools/inspector-schema/README.md` 为唯一实现依据，不在这里重复定义技术协议。

### 当前不一致与处理范围

| 入口 | 当前问题 | 统一后的行为 |
| --- | --- | --- |
| 干员附属 Buff | 列表旁直接编辑父草稿 | 从对象列表进入定义详情页 |
| 干员能力实体 | 已移除数量摘要与二级保存，列表/详情页面模式尚待统一 | 直接展示对象列表，进入同样的详情页，修改父草稿 |
| 技能、养成、角色行为、连携 | 存在二级保存、取消与多套返回栏 | 作为工作区页面导航，共享根保存范围 |
| 武器、装备词条及附属 Buff | 各自安排基本字段、贡献图与附属对象入口 | 复用概览、对象列表、定义详情三种页面模式 |

改造范围包含干员、武器、单件装备、套装的自定义定义工作区及其子页面。实例的等级、配装、加点编辑不是定义编辑，不套用定义工作区的信息分组。不得修改技能块文本或据此变更模拟规则。

### 页面骨架与导航

工作区只保留一层外壳：顶部显示对象身份及未保存状态，中间承载当前页面，底部固定根级撤销/重做、问题数量、取消和保存。分类导航用于概览和对象列表；进入定义详情时隐藏父分类和对象列表，将内容区交给节点图及可收起的 Inspector，不在基础属性页硬留 Inspector 空栏。

Skill、Buff、能力实体是根干员定义下的平级对象，采用同规格的全工作区详情页。共享草稿、历史和保存范围不等于视觉嵌套；不得再叠加“父分类 → 对象列表 → 子编辑器 → Inspector”挤压节点图，也不能因组件复用方式不同而形成不同编辑层级。此规则替代先前“详情始终保留分类导航”的要求。

页面只采用三种模式：

1. 概览：身份、基础属性、成长配置分组展示。高频字段先于低频技术信息，ID 和来源信息放在明确的身份/来源区；不把全部字段堆成一列。
2. 对象列表：标题、简短用途说明、搜索和新增；每项展示名称或 ID、对象类型、引用/问题摘要以及进入详情操作。没有对象时提供创建入口，不先显示一个数量框再要求点击“编辑”。
3. 定义详情：固定返回入口与面包屑、当前对象标题、对象级操作；下方是占满剩余工作区的图和可收起的 Inspector。打开 Buff、能力实体、技能都进入这种页面，不混用列表旁长表单、折叠嵌套表单和叠加弹窗。

返回与面包屑始终可见。面包屑表达归属，例如“干员定义 / Buff / 对象”，使用可读对象身份，完整技术 ID 可复制。从技能引用进入 Buff 时是切换平级详情页，不在技能面板内打开 Buff，也不把面包屑写成技能拥有 Buff。返回入口恢复跳转前页面的选择与视图位置；引用关系不是所有权或 UI 嵌套关系。不打开另一份可写副本。浏览、返回和切换分类不创建历史事务。

新建、复制、删除属于当前列表或对象标题，不放在无关表单底部。复制定义必须明确新身份；被引用对象的删除限制继续保留。新增可使用轻量选单，只有确认删除、放弃整个工作区修改等决策使用覆盖弹窗。

### 信息分类

| 工作区 | 左侧分类及内容 |
| --- | --- |
| 干员 | 概览（身份、基础面板、成长）；技能与技能组；养成（天赋、潜能）；角色行为与连携；附属定义（Buff、能力实体） |
| 武器 | 概览（身份、类型、基础属性、成长）；词条与效果；附属定义 |
| 装备 | 概览（身份、部位、基础属性、套装关联）；词条与效果；附属定义 |
| 套装 | 概览（身份、套装信息）；套装效果（按触发件数组织）；附属定义 |

分类复用同一页面组件，但不凭对称性伪造契约不存在的内容。词条的元数据和它的动作图属于同一详情页的不同区域；属性修正、事件行为、初始化行为采用一致的标题与分组层级。公有定义在引用查看器中明确标为只读，不能混进自定义对象列表冒充可编辑项。

### 保存、历史与状态

一个根定义只有一份草稿、一套历史、一个保存入口。附属定义编辑不创建临时副本，不提供“保存子对象后再保存根”的流程。返回只导航；取消只在根工作区执行，并在存在修改时明确确认放弃范围。保存统一校验整份定义，问题可跳到对应对象/节点/字段。

撤销和重做恢复数据并导航到对应对象及字段；不能因当前处于列表页、另一分类或输入框失焦而失效。导航状态与文档历史分开保存。独立打开某个定义时，它可以成为根保存范围，但被根工作区包含时必须借用根上下文，而不是根据组件名字是否叫 Dialog 决定历史归属。

保存范围和撤销范围并非技术上必须一致；这里选择根级统一历史，是因为完整定义存在跨对象引用、删除和联动操作，对象各自倒序可能只恢复事务的一部分。因此按照根文档实际编辑顺序撤销，不能只撤销当前页面，也不能静默修改另一个对象而不给反馈：

- 撤销/重做控件提供下一操作的可读说明，例如“撤销：修改 Buff ×× 的持续时间”，包括对象身份和操作含义，而非只有通用按钮。
- 恢复时自动切换到对应的平级详情页，选中节点并定位字段；新增/删除等结构操作定位到相应对象或列表，不能打开不存在的对象。
- 浏览、返回、选择对象与撤销引起的自动定位不加入编辑历史。跨对象的一次操作是一个原子事务，禁止只恢复一半。
- 验收“修改技能 → 修改 Buff → 返回技能 → 撤销”：撤销目标应是 Buff，操作说明、页面跳转及数据恢复必须一致；重做亦然。

现有节点/字段定位只是基础；下一操作说明与完整跨页面反馈尚未实现，不能将根级历史可用等同于交互完成。

### 实施顺序与验收门槛

1. 先贯通干员 Buff 与能力实体：统一对象列表/详情导航，移除能力实体数量中转页、独立草稿和二级保存，验证跨对象撤销。
2. 同一外壳接入技能、养成和角色行为，移除各自的保存/返回栏；递归结构只进入主图。
3. 武器、装备、套装采用同样的页面模式；保留各自契约差异，删除旧版外壳和重复布局规则。
4. 验收完整路径：新增对象→编辑→跳转引用→返回→撤销→跨分类→保存/取消；验证窄屏、长 ID、空列表、只读对象和校验失败，不以静态结构测试代替浏览器验收。

每一阶段必须同时替换导航、保存行为和布局，不接受只加一层公共边框或统一按钮颜色作为“统一工作区”完成。

当前实施边界（2026-09-07）：能力实体分类直接显示列表和图，保留干员分类导航及根保存栏；嵌入时读取根草稿并借用根历史，新增、复制、删除和图编辑不再经过二次保存。独立入口仍保留自身保存范围。已补共享草稿和跨 Buff/能力实体撤销测试；恢复实体选择需等待根草稿通过 props 下传，避免撤销删除时选不中恢复的对象。本轮尚未完成统一对象列表/详情页、面包屑与浏览器视觉验收，也未统一技能、行为、武器和装备的二级保存边界。

## 1. 编辑内容的共同特征

Endaxis Next 的干员、技能、Buff、能力实体、武器和装备定义具有同一组编辑特征：

- 每个对象都有稳定身份，其他对象通过 ID/key 引用它；改名可能使使用点失配，但不应静默改写引用。
- 定义是深层组件树：技能包含时间序列和步骤，步骤可包含条件、Buff 生命周期或能力实体子技能。
- 同级对象通常有顺序语义，复制、移动和删除必须明确作用于当前层级。
- 模板与使用实例分离；模板编辑影响全部引用者，单次技能块覆盖只影响一次释放。
- 逐等级值、黑板参数和运行时 Context 让同一字段同时具有结构、数值和来源语义。
- 校验问题既可能属于当前字段，也可能属于跨对象引用；用户需要在原位置看到问题，并能从汇总跳回对象。

因此它更接近游戏引擎的 Blueprint/Prefab 编辑器和 IDE，而不是一张无限增长的设置表单。

## 2. 统一工作区

### Inspector 字段元数据与历史边界

条件编辑采用“权威 TS 数据契约 → 编译期自动提取结构 → 显示注解 → 公共字段渲染器”。不再手写每种条件的字段数组和 Vue 分派。契约和转换器不依赖 UI；结构中类型、可选性与枚举全部来自 TS 类型检查器，领域校验仍调用既有校验器。UI 注解只维护结构不能推导的显示语义。属性编辑架构、自动准备流程和迁移验收以 `tools/inspector-schema/README.md` 为准。

`conditionStructure.generated.ts` 覆盖全部 70 类条件，当前 67 类可自动生成完整表单，3 类逻辑组合的递归字段明确归图编辑器，Buff 查询的有限参数对象联合已接入。不能只渲染已支持字段而悄悄漏掉其他字段。此前手写的条件字段数组已经移除；`combatInspectorFields.ts` 暂时只保留施加 Buff 的手写复合字段配置。`InspectorFields.vue` 统一布局、提交和错误显示；手写字段仍经类型约束工厂检查，自动结构与手写字段共用同一个写入实现。

复合字段约束：值类型直接索引数据契约，不另立游戏数据定义。动态 Buff 引用的关联清理由 `replaceApplyBuffReference` 一次完成，引用和被清理的内联定义、时长、效力覆盖共同撤销。赋值字典完整保留单值、逐级数组和动态操作数；展示不能解析并覆写为当前等级，只有用户显式切换形式才替换整个值。移除最后一项恢复省略字段，空键/重名重命名不覆盖其他条目。窄 Inspector 中赋值键和操作数分行，避免数值区域被挤出。

自动结构补齐了生命值比较的完整目标枚举及 `contextKey`、剩余时长比较的 `outputKey` 等旧面板遗漏。生成物一致性测试防止契约变更而界面结构过期；Vite 开发/构建/测试和 npm 类型检查自动准备，开发时监听契约依赖；生成文件是 Git 忽略的本地缓存，无需手动生成。新增普通条件不需要新增字段数组和模板分支。字符串/枚举数组已复用统一列表编辑器，保持原顺序和重复项，可选列表区分省略与空列表。混合联合保持原标量/表达式/列表形式；公共字符串引用控件同时用于 Buff 身份和动态标记身份。递归条件不能在 Inspector 里展开：结构 Schema 的 conditionNode/conditionNodes 归图编辑器，Inspector 仅显示当前节点参数。独立条件入口改用复用既有节点投影和命令的条件图；已有大图的 layerOnly 面板不重复创建子图。Buff 查询已使用契约生成的参数对象联合编辑，不产生独立图节点。切换查询形式只替换 query，参数内修改仍整体提交到宿主历史。这里的 70 类覆盖仅指条件。步骤已复用同一提取器和公共参数注解，88 类中 77 类在图内 Inspector 自动编辑；复杂参数与完整表单继续使用专用组件，不能因为参数自动化而丢失结构入口。当前覆盖不代表重构完成。后续优先收束属性绑定和局部类型定制，贯通一个完整面板后删除旧实现，不再以新增覆盖数代替代码收敛。结构提取不推断业务规则；可选字段初始内容只是编辑草稿，不代表游戏默认值。

所有字段通过完整对象的不可变更新回到所属草稿；渲染器不拥有独立历史。一个保存范围只有一份撤销历史，图形、表单、下拉修改、对象增删共用该历史。独立子草稿保存后在父草稿中记为一次修改。省略、0、false 必须分别保留；输入空字符串不能静默转成 0。复合控件的连续输入事务合并仍待统一，不应把字段元数据样板等同于已经完成全部输入交互迁移。

涉及 Inspector 的历史记录包含修改时的对象身份和节点路径。撤销和重做均恢复同一修改位置，并显示对应 Inspector；不得用用户后来浏览的位置覆盖重做的定位。已删除节点由现有路径查找回落到最近存活父节点。浏览选择本身不产生历史。

目前共享历史已接入干员根定义、能力实体集合、附属 Buff 集合、养成/角色/连携行为以及武器装备保存范围；入口、返回栏的完全统一与窄屏画布布局仍需继续验收。

定义编辑器统一采用四层结构：

1. **对象导航（Outliner）**：左侧显示可搜索的层级或分类，只承担选择与少量上下文操作。
2. **路径导航（Breadcrumbs）**：主区顶部持续显示“模板 / 分类 / 对象 / 子对象”，用于返回上级和切换同级。
3. **结构画布与属性区（Graph/Inspector）**：自由漫游画布完整表达技能、调度序列、步骤和条件分支的父子关系；右侧继续复用严格的结构化表单，只编辑当前节点。
4. **问题栏（Problems）**：底部持续显示错误/警告计数；展开后列出路径和原因，点击跳到对应对象。字段附近仍保留就地提示。

顶层只保留保存、取消、恢复等文档级动作。新增、复制、删除、移动等对象级动作放在对应列表或对象工具栏；超过三个的低频动作进入上下文菜单。

`CombatStepEditor`、`CombatConditionEditor`、生命周期、调度序列、逐级值等组件是 Inspector 或字段编辑器，不再各自视为工作区。它们必须服从宿主分配的滚动和宽度，不能反过来撑大整个弹窗。

### 2.2 布局尺寸契约

- 根定义工作区统一使用最多 `1600px`、距离视口四周 `16px` 的近全屏弹窗。弹窗头、内容和页脚是唯一纵向三段；头和页脚固定，内容区获得全部剩余高度。
- Outliner 默认宽度为 `180–240px`。同一时刻只显示当前编辑层的一列 Outliner；进入技能、行为或能力实体的专注编辑状态后，隐藏祖先分类栏和祖先保存区，由当前子工作区提供返回、保存和取消。
- Graph/Inspector 使用“弹性画布 + 有界属性栏”，Inspector 为 `320–420px`，不得再使用占工作区 `34%–42%` 的比例宽度。新增横向空间优先交给画布；Inspector 内部依靠容器查询改为单列，而不是继续侵占画布。
- 元数据位于画布上方，只占内容所需高度并独立滚动；结构导图获得其余全部高度。图形工作区嵌入根模板时不得保留 `480px`、`520px` 等页面式固定高度。
- 画布、Inspector、Outliner、完整表单和 Problems 各自是明确的滚动所有者。禁止让整个弹窗 body 与内部列表同时滚动，也禁止用内容高度把保存区推离视口。
- 狭窄视口首先隐藏祖先导航、压缩工具栏辅助文字；仍不足时才把 Graph/Inspector 改为纵向两区。不得把画布压缩成只够显示一两个节点的窄条。
- 定义工作区的共享尺寸变量只放在 `definitionWorkspaceLayout.css`；Buff/能力实体的画布规则放在 `definitionGraphViewport.css`，动作序列与装备贡献消费同一 Inspector 宽度变量。具体定义编辑器只描述自身信息结构，不再另定一套弹窗尺寸。

## 3. 一致交互规则

- 结构画布默认展开根节点以下两级，每个节点可独立展开/收起；拖拽空白处漫游，Ctrl/Cmd + 滚轮以指针为中心缩放。
- 单击图节点选择对象，右侧 Inspector 只显示该节点自身字段；选择嵌套 IF/Body 节点时沿真实 `sourcePath` 定位，不在右侧重复展开子步骤列表。
- 新增下一层从导图节点的 `＋` 发起：技能根新增调度序列，动作序列在鼠标位置打开统一步骤类型选择器；右侧 Inspector 不临时插入“添加步骤”等结构操作。节点移动、复制和删除属于当前 Inspector 的本层操作。
- Buff 生命周期和能力实体子技能使用同一边界：导图表达并增删子结构，Inspector 只编辑选中生命周期、调度序列或战斗步骤本身。
- 可移动节点使用独立抓手：拖到容器中央表示移入，拖到同类节点上/下半区表示插到前/后。拖放必须迁移被拖子树的折叠状态，不能因为路径 ID 改变而自动展开。
- 结构复制使用编辑器内剪贴板。复制节点后，只有兼容的目标容器显示“粘贴到此处”；顶栏按钮、右键菜单和 `Ctrl+C` / `Ctrl+V` 执行同一命令，不依赖系统文本剪贴板。
- 结构增删、移动和粘贴进入导图自己的撤销/重做历史；定义编辑弹窗打开时必须截断时间轴快捷键作用域，避免 `Ctrl+C` / `Ctrl+V` / `Ctrl+Z` 穿透到底层轨道。Inspector 文本输入仍使用浏览器原生文本剪贴板。
- Inspector 按自身容器宽度响应式排版，而不是假定固定页面宽度；字段、长 ID、工具栏和递归步骤都必须允许收缩或换行，任何层级都不得撑出属性栏。
- 新增后立即选择并聚焦身份字段；复制后使用确定性临时名称，等待用户修改。
- 删除先检查引用。被引用对象不允许静默删除；应列出引用位置。
- 干员模板内的技能、Buff 生命周期和能力实体子技能共享稳定引用索引；删除 Buff 或能力实体时列出所有使用路径，点击路径返回对应技能、Buff 或实体节点。
- 模板 key 允许自由编辑。已有轨道技能块保持原位，解析时严格报错，不自动迁移。
- 搜索过滤对象，不改变对象顺序；清空搜索后恢复原层级。
- 修改状态、来源模板、只读身份和错误计数在所有定义编辑器中使用相同视觉语言。
- 保存只受 DSL/文档结构错误阻止；跨使用点失配允许保存并在具体轨道显示。
- 从时间轴只打开一次定义文档工作区。工作区内选择技能、Buff、能力实体、养成项、被动或连携节点只切换同一画布与 Inspector；禁止为进入下一层继续叠加 `el-dialog`。取消/应用子结构也在原工作区返回上一级。

## 4. 参考依据

- Unreal Blueprint 使用 My Blueprint/Components 层级列表、上下文 Details 面板和 Compiler Results 分工。
- Unity Inspector 把模板/Prefab 覆盖明确标记，并提供 Revert/Apply，而不是隐藏合并来源。
- VS Code 使用 Outline、Breadcrumbs、行内诊断与 Problems 面板同时解决深层定位和集中审计。
- Blender 使用针对任务的 Workspace，把 Outliner、Properties、主视图和 Timeline 组合为稳定布局。

Endaxis 不复制这些产品的外观，只采用其已验证的信息架构。

## 5. 落地顺序

1. 先恢复旧版主编辑器已经具备的可观察行为：方案管理、工作台布局、时间轴选择/拖放/快捷键、属性面板、战斗日志、伤害分析、Buff 轴、命中详情和项目 I/O。
2. 对底层模型已经变化的旧版功能做语义等价改造，并记录边界。例如局部对象时间膨胀不能复用旧版统一逻辑时钟，伤害分析也不能在 UI 重新计算或猜测未冻结的贡献。
3. 旧版主流程完成后，再继续干员、武器、装备、Buff、能力实体等 Next 专属模板工作区；不得因为深层 DSL 入口容易继续扩展，就越过更高频的旧版缺口。
4. 新版定义工作区继续统一 Outliner、Breadcrumbs、Graph/Inspector 和 Problems，但内部选择只原位切换，不能叠加对话框。
5. 每批行为复刻须有结构测试或纯命令测试；“复刻”指操作路径、反馈和结果一致，不要求组件树、Store 或算法实现一致。

## 6. 当前实现边界

- 结构图是 `SkillDefinition` 的结构投影和子节点操作入口；字段仍由 Inspector 编辑，增删移动通过 `sourcePath` 命令写回同一草稿，不会产生第二份图编辑模型。
- 时间轴技能块覆盖在保存时继续严格校验；项目级干员模板可以保留带诊断的中间定义，真正解析到轨道时原地失败。
- 能力实体蓝图当前属于干员定义附属对象；技能节点只显示稳定引用。干员模板工作区可从引用跳到对应 Buff 或能力实体，时间轴实例编辑不伪造缺失的跨对象编辑上下文。
- 顶部工作区已经通过应用层 `openProject` 打开完整项目 JSON，并通过稳定序列化边界导出完整项目；打开新文档会清空旧文档撤销栈。后续时间轴 ID 每次都与当前持久化文档避碰，不依赖页面生命周期内的临时计数器。
- 工具栏持续标记尚未导出的项目修改；成功导出或打开新项目后回到已保存状态。加载覆盖和关闭页面都会保护未导出修改，不能无提示丢弃整个项目。

## 7. 可编辑性契约与覆盖清单

“全部数据可编辑”指所有会改变项目语义的源定义都有结构化入口，不意味着允许直接修改派生缓存、来源证据或稳定引用身份。编辑器必须把三类字段明确区分：

- **源定义字段**：可以编辑，并以领域名称、单位、值域和作用时机说明语义；
- **稳定身份与来源身份**：只读，并说明修改会导致引用断裂或失去游戏数据追溯；
- **编译/投影派生字段**：不进入定义表单，只在审计或预览中展示其来源。
