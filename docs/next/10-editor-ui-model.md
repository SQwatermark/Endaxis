# Endaxis Next 编辑器交互模型

## 1. 编辑内容的共同特征

Endaxis Next 的干员、技能、Buff、能力实体、武器和装备定义具有同一组编辑特征：

- 每个对象都有稳定身份，其他对象通过 ID/key 引用它；改名可能使使用点失配，但不应静默改写引用。
- 定义是深层组件树：技能包含时间序列和步骤，步骤可包含条件、Buff 生命周期或能力实体子技能。
- 同级对象通常有顺序语义，复制、移动和删除必须明确作用于当前层级。
- 模板与使用实例分离；模板编辑影响全部引用者，单次技能块覆盖只影响一次释放。
- 逐等级值、黑板参数和运行时 Context 让同一字段同时具有结构、数值和来源语义。
- 校验问题既可能属于当前字段，也可能属于跨对象引用；用户需要在原位置看到问题，并能从汇总跳回对象。

因此它更接近游戏引擎的 Blueprint/Prefab 编辑器和 IDE，而不是一张无限增长的设置表单。

## 2. 统一工作区

定义编辑器统一采用四层结构：

1. **对象导航（Outliner）**：左侧显示可搜索的层级或分类，只承担选择与少量上下文操作。
2. **路径导航（Breadcrumbs）**：主区顶部持续显示“模板 / 分类 / 对象 / 子对象”，用于返回上级和切换同级。
3. **结构画布与属性区（Graph/Inspector）**：自由漫游画布完整表达技能、调度序列、步骤和条件分支的父子关系；右侧继续复用严格的结构化表单，只编辑当前节点。
4. **问题栏（Problems）**：底部持续显示错误/警告计数；展开后列出路径和原因，点击跳到对应对象。字段附近仍保留就地提示。

顶层只保留保存、取消、恢复等文档级动作。新增、复制、删除、移动等对象级动作放在对应列表或对象工具栏；超过三个的低频动作进入上下文菜单。

## 3. 一致交互规则

- 结构画布默认展开根节点以下两级，每个节点可独立展开/收起；拖拽空白处漫游，Ctrl/Cmd + 滚轮以指针为中心缩放。
- 单击图节点选择对象，右侧 Inspector 只显示该节点自身字段；选择嵌套 IF/Body 节点时沿真实 `sourcePath` 定位，不在右侧重复展开子步骤列表。
- 新增下一层从导图节点的 `＋` 发起：技能根新增调度序列，动作序列在鼠标位置打开统一步骤类型选择器；右侧 Inspector 不临时插入“添加步骤”等结构操作。节点移动、复制和删除属于当前 Inspector 的本层操作。
- Buff 生命周期和能力实体子技能使用同一边界：导图表达并增删子结构，Inspector 只编辑选中生命周期、调度序列或战斗步骤本身。
- 可移动节点使用独立抓手：拖到容器中央表示移入，拖到同类节点上/下半区表示插到前/后。拖放必须迁移被拖子树的折叠状态，不能因为路径 ID 改变而自动展开。
- 结构复制使用编辑器内剪贴板。复制节点后，只有兼容的目标容器显示“粘贴到此处”；顶栏按钮、右键菜单和 `Ctrl+C` / `Ctrl+V` 执行同一命令，不依赖系统文本剪贴板。
- 结构增删、移动和粘贴进入导图自己的撤销/重做历史；定义编辑弹窗打开时必须截断时间轴快捷键作用域，避免 `Ctrl+C` / `Ctrl+V` / `Ctrl+Z` 穿透到底层轨道。Inspector 文本输入仍使用浏览器原生文本剪贴板。
- Inspector 按自身容器宽度响应式排版，而不是假定固定页面宽度；字段、长 ID、工具栏和递归步骤都必须允许收缩或换行，任何层级都不得撑出属性栏。
- 新增后立即选择并聚焦身份字段；复制后使用确定性临时名称，等待用户修改。
- 删除先检查引用。被引用对象不允许静默删除；应列出引用位置。
- 干员模板内的技能、Buff 生命周期和能力实体子技能共享稳定引用索引；删除 Buff 或能力实体时列出所有使用路径，点击路径返回对应技能、Buff 或实体节点。
- 模板 key 允许自由编辑。已有轨道技能块保持原位，解析时严格报错，不自动迁移。
- 搜索过滤对象，不改变对象顺序；清空搜索后恢复原层级。
- 修改状态、来源模板、只读身份和错误计数在所有定义编辑器中使用相同视觉语言。
- 保存只受 DSL/文档结构错误阻止；跨使用点失配允许保存并在具体轨道显示。
- 从时间轴只打开一次定义文档工作区。工作区内选择技能、Buff、能力实体、养成项、被动或连携节点只切换同一画布与 Inspector；禁止为进入下一层继续叠加 `el-dialog`。取消/应用子结构也在原工作区返回上一级。

## 4. 参考依据

- Unreal Blueprint 使用 My Blueprint/Components 层级列表、上下文 Details 面板和 Compiler Results 分工。
- Unity Inspector 把模板/Prefab 覆盖明确标记，并提供 Revert/Apply，而不是隐藏合并来源。
- VS Code 使用 Outline、Breadcrumbs、行内诊断与 Problems 面板同时解决深层定位和集中审计。
- Blender 使用针对任务的 Workspace，把 Outliner、Properties、主视图和 Timeline 组合为稳定布局。

Endaxis 不复制这些产品的外观，只采用其已验证的信息架构。

## 5. 落地顺序

1. 先恢复旧版主编辑器已经具备的可观察行为：方案管理、工作台布局、时间轴选择/拖放/快捷键、属性面板、战斗日志、伤害分析、Buff 轴、命中详情和项目 I/O。
2. 对底层模型已经变化的旧版功能做语义等价改造，并记录边界。例如局部对象时间膨胀不能复用旧版统一逻辑时钟，伤害分析也不能在 UI 重新计算或猜测未冻结的贡献。
3. 旧版主流程完成后，再继续干员、武器、装备、Buff、能力实体等 Next 专属模板工作区；不得因为深层 DSL 入口容易继续扩展，就越过更高频的旧版缺口。
4. 新版定义工作区继续统一 Outliner、Breadcrumbs、Graph/Inspector 和 Problems，但内部选择只原位切换，不能叠加对话框。
5. 每批行为复刻须有结构测试或纯命令测试；“复刻”指操作路径、反馈和结果一致，不要求组件树、Store 或算法实现一致。

## 6. 当前实现边界

- 结构图是 `SkillDefinition` 的结构投影和子节点操作入口；字段仍由 Inspector 编辑，增删移动通过 `sourcePath` 命令写回同一草稿，不会产生第二份图编辑模型。
- 时间轴技能块覆盖在保存时继续严格校验；项目级干员模板可以保留带诊断的中间定义，真正解析到轨道时原地失败。
- 能力实体蓝图当前属于干员定义附属对象；技能节点只显示稳定引用。干员模板工作区可从引用跳到对应 Buff 或能力实体，时间轴实例编辑不伪造缺失的跨对象编辑上下文。
- 顶部工作区已经通过应用层 `openProject` 打开完整项目 JSON，并通过稳定序列化边界导出完整项目；打开新文档会清空旧文档撤销栈。后续时间轴 ID 每次都与当前持久化文档避碰，不依赖页面生命周期内的临时计数器。
- 工具栏持续标记尚未导出的项目修改；成功导出或打开新项目后回到已保存状态。加载覆盖和关闭页面都会保护未导出修改，不能无提示丢弃整个项目。

## 7. 可编辑性契约与覆盖清单

“全部数据可编辑”指所有会改变项目语义的源定义都有结构化入口，不意味着允许直接修改派生缓存、来源证据或稳定引用身份。编辑器必须把三类字段明确区分：

- **源定义字段**：可以编辑，并以领域名称、单位、值域和作用时机说明语义；
- **稳定身份与来源身份**：只读，并说明修改会导致引用断裂或失去游戏数据追溯；
- **编译/投影派生字段**：不进入定义表单，只在审计或预览中展示其来源。
