# 旧时间轴转换命令行入口

网页和命令行共用 `src/application/legacyTimeline` 中的转换逻辑与旧版映射快照。
本目录只保留命令行入口、离线模拟审计及命令行示例配置；正式网页按需加载转换逻辑，
不会引用本目录或游戏数据编译器。多条真实轴已转换并通过运行检查。
网页“更多 → 项目 → 加载”已接入旧轴导入，但仍不是完整旧格式兼容器。

网页检测到旧轴后，可选择“保留原时间”（默认）或“智能修复时间”。智能修复按新版显示时长、
接续窗口和终结技时间膨胀顺延技能，可能改变增益覆盖；保留原时间只换算技能位置的帧率，不修复
重叠或不可接续。两者共用形态判断与主控切换推断，原文件均不修改。
转换入口第四个参数为 `{ timingMode: 'repair' | 'preserve' }`；省略时仍使用智能修复，CLI 默认不变。
报告的 `timingMode` 记录本次选择；保留时间时 `timingAdjustments` 为空，模拟范围仍会扩展以覆盖技能结束。

## 使用

在仓库根目录执行：

```powershell
npm run convert:legacy-timeline -- "C:\Users\sqwat\Downloads\Endaxis_Timeline_2026-08-31.json" tmp/converted-axis --mappings tools/legacy-timeline/mappings.example.json
```

输出目录必须不存在，父目录须存在。只写新目录，不覆盖旧存档。
成功输出 project.json 和 report.json；有遗漏/目标校验失败只输出报告并以非零状态结束。
示例配置只演示字段。旧版 2026-08-31 数据快照统一使用
`src/application/legacyTimeline/mappings.2026-08-31.json`；
原生样本依据归 [combat-spec](../../../combat-spec-operator-completion/docs/research/README.md)。
成功转换不等于新旧模拟结果一致。
报告的 `issues` 保留所有诊断，同时分为 `simulationIssues` 和 `presentationIssues`。
展示连线未迁移不表示技能或伤害输入缺失，可以发布模拟伤害对比，但仍须注明连线遗漏。
未传配置可用来发现未映射内容。

## 模拟审计

伤害对照可使用正式模拟入口生成离线审计（输出请放入被忽略的 tmp）：

```powershell
node --experimental-strip-types tools/legacy-timeline/auditSimulation.ts tmp/converted-axis/project.json > tmp/simulation-audit.json
```

分别重算存档结束线和完整时长，输出总期望伤害、完整 sourceId 分账及结束线后的命中。
逐条伤害保留技能类型、伤害类型、法术爆发类型、Buff ID、动作来源及回执已有的攻击力、技能
倍率、基础伤害、最终攻击值、计算路径、伤害乘区、抗性乘区、暴击率、暴击伤害、暴击结果、
期望与实际伤害；分账包含零伤害、无 castId 和无来源
（null）的公共伤害，不把不同轨道或能力实体猜成同一来源。复合状态等后续伤害可能没有 castId，应使用
`buffId` 和 `sourceActionId` 继续核对，不能据此断言原施法漏伤害。
`diagnostics.castIssues` 按完整 `castId` 汇总旧坐标直接换算后在当前原生门禁下失败的输入。
公开分享轴能够在旧版完成，原则上应视为可行排布；这些提示通常说明两版动画长度、命中停顿、
时间膨胀或窗口精度不同，不能据此判定旧轴错误。比较伤害前应先对提示附近的输入做小范围时间
校准，再比较相同衔接下的命中和状态。未经校准的后续输入还可能替换同模板能力实体，截断此前
技能的长时产物，因此不能把未列入 `castIssues` 自动视为可直接比较。
这些是当前模拟回执的账目，不是新旧命中已一一对应或游戏行为已经核实的证明。

## 映射配置

### 早期存档加载规则

`legacyFormat.ts` 在标准映射前还原旧版 d248cf30 的加载规则：干员 gameId 和 slug 统一身份；
普通技能的旧 ID、类别和段号转成标准技能身份；旧连线只有端点唯一对应技能块且没有效果字段时，
才补齐节点类型。根级战斗常量作为基础，方案局部字段覆盖它，各方案独立换算时间。
早期普攻段号保存在 `attackSegmentIndex`，多段连携保存在 `comboSegmentIndex`；
按技能类别读取，并校验它与完整技能 ID 一致。依据为旧版 `419be04a` 的多段连携保存逻辑。
同一版本的 `createDodgeSkill` 只保存 `<GAME_ID>_dodge`、`type=dodge` 的 0.5 秒空块，
没有方向和极限闪避成功信息。转换器仅在完整身份匹配所属干员时把它转成同轨普通闪避标签；
方向采用新版导入约定的向前，不补技力、体力返还、时间膨胀或隐藏 Dodge 技能。
智能修复模式会让该标签按它与相邻旧技能的相对顺序一起顺延，并在
`dodgeMarkerAdjustments` 记录原帧、目标帧及两侧技能；保留时间模式不移动标签。

缺少独立构筑实例时，按旧版 hydrateTrackInstances 补建：干员 90 级、晋升、信赖 4、
技能 12、天赋满级，潜能取旧表默认；武器 90 级突破，潜能与技能档位按旧表稀有度；
装备保留非零精锻档位，零档按旧版补建规则取 3，不可精锻装备不加精锻。
已有实例不覆盖，轨道 stats 等派生属性不再次叠加。
`legacyLoadDefaults.2026-09-18.json` 是该版本数据表的静态快照，记录 gameId、默认潜能、
技能/天赋档位、武器潜能和装备等级，不依赖本机旧工作树运行，也不读取新版默认养成。

历史时间戳变体由映射表的 historicalSkills 精确匹配干员、完整 ID、类别与段号，不按显示名称猜测。
已收录两个历史 gamedata.json 快照中的 32 个预设变体，另补莱万汀强化普攻 4 个有效分段。
证据为 `9b92b0d7^`（完整提交 4b63a74771bd88c3fa39cb8ab25c5a19e0034c56）和
`b3d1b26d^`（b4569c9be9ece316f7c0cc3631e18d34d9a1205a）的 public/gamedata.json；
每条映射保留旧名称与来源，运行时不加载 Git 或旧游戏数据。
洛茜更早的 `ROSSI_link` 和 `ROSSI_variant_v_1772384921148` 分别对应连携第一、第二段，
依据 `9a2bbf28:public/gamedata.json` 及 `419be04a` 的多段连携改动补入历史映射。
这两个 ID 不按时间戳模式泛化；未知变体仍报错。
旧版按层数、是否强化拆出的战技/连携，如新版仍是同一技能，则由新版实际状态决定分支，
不因为旧块名称强制添加状态。莱万汀终结技内战技指向独立替换技能，整套强化普攻指向技能序列。
旧版第五个空普攻槽、未知变体与未核实的段号不会自动降级或删除，继续报告未映射。
按用户确定的转换策略，忽略 characterOverrides，使用标准技能定义；报告的 ignoredCustomizations
记录被忽略的配置，不将其作为转换失败。武器和装备覆盖仍沿用原有诊断。

`mappings.2026-08-31.json` 是针对旧版数据快照一次性生成、再人工核对少量例外后的完整目录，
不是随着每条待转换时间轴逐项补充的清单。它目前覆盖 31 名干员、79 把武器、258 件装备、
82 个敌人、317 种标准技能身份及 39 条历史技能身份（其中庄方宜 3 条由用户明确指定）。转换新时间轴时应先直接使用这份文件；只有旧版
数据定义本身发生变化，才需要重新整理整份映射。

批量配对依据如下：干员使用稳定 slug；武器优先使用图标中的原生资源 ID；装备使用英文原生
名称并以资源 ID 复核；敌人使用 gameId；技能从旧版技能定义枚举实际存档身份，再按新版技能组
和技能 key 匹配。资源 ID 重复、技能改名或技能结构改变时才人工指定目标。

伊冯旧版 `enhancedBasicAttack` 是一个包含整套强化普攻的技能块，新版对应可递归分叉的技能
序列。映射将它声明为 `operatorSkillSequence`，转换器先放置当前形态的首段，再复用编辑器的正式
递归输入规划器，按模拟回执逐段选择下一技能直到收尾。展开结果写入 `sequenceExpansions`；如果
当前路由无法到达收尾技能，转换会明确阻塞，不能只保留 `ultimateAttack1` 或固定抄六段兜底。

- operators：旧干员 ID → 当前 operatorSlug。
- weapons：旧武器 slug → 当前原生武器 ID。
- gears：旧单件装备 ID → 当前单件装备 ID；不按套装名或图片相似度猜测。
- enemies：旧敌人 ID → 当前定义 ID，按定义的 gameId 核对；未知敌人禁止静默降级为普通敌人。
  保留存档战斗数值覆盖，但身份、图标与战斗分类取已匹配定义。
- skills：按**旧干员 ID**分组的规则数组，每条包含 source 和 target。
  source 精确匹配 skillId、sourceSkillKey、type、segmentIndex、variantKey；
  缺省字段表示旧动作中也未提供，不是通配符。target 是当前项目的技能引用。
  普通 target 保存单个当前技能来源；`operatorSkillSequence` target 保存当前技能组及可选形态，
  用于旧单块对应当前整组技能的结构转换。段号和变体必须逐项确认，不能将换槽、强化、自定义
  动作默认为基础技能。
- actions：按“方案ID/轨道下标/动作下标”的单动作覆盖，优先于 skills；
  仅供明确核对后的例外映射，不依赖可能重复的旧 action.id。
- guardedActions：当方案ID是default_sc等通用值时，同时精确匹配path、旧operator、
  instanceId和source技能身份，再使用target。实例ID不是单独的匹配依据；不匹配时
  仍走普通技能映射，多条命中或与actions冲突显式报错，避免污染其他分享轴。

不得把缺失身份自动变成默认配装或删除技能后宣称成功。
映射只解决身份，不证明新旧版本行为或数值相同。

## 边界与实现来源

`src/application/legacyTimeline/projectConversion.ts` 的输入字段搬运以历史提交 9ec608cc
的迁移器为起点；不恢复旧游戏代码或运行时。
sourcePreparation.ts 单独规格化时间及映射；convert.ts 调用当前正式项目/游戏数据校验。
CLI 用无监听、无 HTTP 服务的 Vite 模块加载当前仓库。

- 支持 version=1.0.0 的 scenarioList，frame 单位必须有有效 fps；
  未标单位按旧 timeSerialization.ts 的秒存档约定处理。
- 只量化实际搬运字段：直接由源帧换算到当前 PROJECT_FPS，报告保留误差。
  绝对时刻先减去原始 prepDuration，以开战为 0；时长不平移。报告 sourceOrigin 记录这一变换。
  `logicalStartTime` 是旧编辑器保存的手工排布时刻，`startTime` 是经过全局停帧平移后用于
  旧编译和模拟的时刻。两者不同时保留并分别换算，迁移技能落点采用 `startTime`；这项结论
  只说明旧存档格式，不作为当前战斗时间规则的证据。
- 养成、配装、输入坐标和场景配置转换；旧 hits、Buff、面板及伤害快照不搬运。
- 没有干员身份且没有动作的旧轨道是合法空占位，直接保留为当前空轨道。带有动作或干员实例却
  无法解析身份的轨道仍会阻塞，不能借空轨规则静默丢弃内容。
- 初次换算后按旧轴全局时间顺序逐个放置技能。第一个技能使用旧轴真实时间；
  之后取旧轴真实时间、同轴前一技能的新版技能块显示结束、全局前一技能的新版模拟开始加旧轴时间差
  三者最大值。候选时间落在终结技时间膨胀内，或恰好等于 `TimeDilationEnded` 的回执帧时，推到结束回执的下一帧；按此顺序放置时，后续终结技也不会与前一段终结技膨胀重叠。
  如果候选位置的正式模拟明确返回“当前技能不可中断”，转换器向后寻找最早允许接续的位置。
  逐帧检查最多300个候选位置，跳过已确认的终结技膨胀区间。输入许可可能先打开、再关闭，
  不能假定它随时间单调变化，也不能用二分搜索跳过中间的短窗口。
  正式转换已复用运行时截面：主会话只推进确认前缀，候选从最早变化的技能/标记帧之前分叉，
  在完整帧末检查当前技能及各轨道上一技能的显示边界，并等待已开启的终结技膨胀结束；满足即停止，
  不强制推进满 300 帧。观察窗口不足时沿该分支继续。回执只读取修复所需的新事实；恢复错误直接暴露，不吞错整场重算。
  `retimingSimulationStats.simulationRuns` 保留观察次数口径，`checkpoints` 另列构筑会话、试跑分支和
  延长观察次数。方案及验收边界见[现有计划](../../docs/handoff/runtime-checkpoint-plan.md)。
  300个候选位置内没有找到时恢复原候选位置，
  保留不可中断提示，并在报告中写入 `inputWindowSearchExhausted`，不能让转换失败或留下300帧假延迟。
  该步骤只处理具体技能之间的中断许可；
  不用移动技能来掩盖技能槽映射、能量、冷却、连携触发或释放顺序问题。
  某些输入会同步切换成 Buff，不产生 `SkillStarted` 和技能生命周期；转换器以
  `SkillSwitchedToBuff` 所在帧作为实际开始，并占用一个输入帧，随后继续计算全局顺序。
  旧单块映射到递归技能组时，先用当前原生路由展开成普通技能块；每段使用稳定派生 ID，随后与
  其他技能一起参与全局排序和智能重排，不向项目格式写入旧版专用标记。
  基础攻击存在条件分支时，正式模拟由实际执行到的 `AllowNextSkillAction` 发布技能块边界。
  例如洛茜第四段普攻的主控与非主控路线分别使用局部36帧和225帧窗口，但非主控路线会先跳到
  189帧；两条路线在现实时间中都于释放后的第36帧到达下一段窗口。转换器只读取这项模拟事实，
  不用静态较晚窗口把主控路线错误拉长。
  旧轴只保存技能槽的基础操作、而正式模拟把该输入解析到同组替换技能时，转换器按干员定义的
  `skillSlots` 改写成实际形态并重新模拟。只接受基础技能到显式替换技能的关系，不猜普通攻击链、
  跨组路由或已经保存为具体形态的技能。
  修正后的技能块超出旧轴结束线时，同时延长战斗总时长和 `simulationRange.endFrame`，使新轴的
  模拟终止线至少覆盖最后一个技能块的实际显示结束。
  旧切换标记按它在全局技能顺序中的位置一起移动：保留相对前一技能的旧时间差，且不越过后一
  技能的新开始。这样技能因真实宽度顺延时，主控切换不会停在旧绝对帧并跨过原本位于它之前的
  技能。
  旧版没有用主控身份参与模拟，因此旧轴通常没有完整的切换标记。转换时默认第 1 轨道为主控；
  其他干员释放普攻、强化普攻、下落攻击或处决时，转换器在该技能开始帧补一个普通主控切换标记。
  旧轴已有的显式切换仍然保留。不同干员的两个此类动作落在同一帧时，按旧轴全局顺序把后一个
  动作至少后移一帧，避免一帧内无法同时满足两个主控身份。该规则只存在于旧轴转换器中，模拟器
  仍按新版项目中的主控标记正常判断条件。
  不增加项目字段；时间、技能形态和切换标记修正分别记录在 `report.json` 的
  `timingAdjustments`、`skillFormAdjustments`、`controlSwitchAdjustments` 与
  `inferredControlSwitches`。`retimingSimulationStats` 记录本次重排处理的方案数、技能数、
  候选位置数和完整模拟次数，供后续性能优化直接比较。
- 转换完成前使用当前干员定义、养成和构筑编译终结技能量上限。旧版运行时本来也会把超出槽上限
  的存档初值钳到上限；转换器按当前原生上限执行同类钳制，并在 `resourceAdjustments` 逐项记录
  原值和结果，不静默修改。身份、文档结构和资源上限等静态处理先于智能重排；
  静态校验失败时仍会正常写出 `report.json`，不会因重排启动模拟而直接退出。
- 旧连接只迁移两端都能唯一对应技能块的 action-to-action 连接。引用 Hit、效果或缺失技能块的
  连接显式阻塞；不根据旧派生 ID 猜测当前内部节点。
- 非空覆盖定义、继承状态、合约、全局修正暂不支持，显式阻塞。
- 切入标记的 characterId 与轨道 ID 共用旧干员身份解析，允许 gameId 与 slug 混存；
  解析后必须唯一匹配，且不能与显式轨道下标冲突。未知或冲突目标阻塞，不能静默丢弃。
  准备期切入目前不受当前项目支持，负帧会明确阻塞，不夹到开战时刻。
- 使用当前游戏定义重算；这不是旧版本模拟器复刻，不证明最终屏幕时间一致。
- 多条真实轴已完成显式身份映射；伤害、Buff 寿命仍需逐 cast 对照。
- 旧格式的其他变体、字段缺省规则和异常输入仍需扩展审计，不宣称任意旧存档均可保真转换。
